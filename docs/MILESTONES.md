## M1 — 流式协议与 Mock Worker

**目标与范围：** 定义音频和识别结果契约，建立可独立于真实模型运行的 gRPC 双向流后端。

**验收与状态：已完成基础范围。**

- [x] 约定 PCM 格式，定义流式音频请求和 partial/final 结果。
- [x] Mock Worker 在输入过程中返回 partial，请求半关闭后返回 final。
- [x] 各 RPC 独立处理音频，取消可中止模拟等待。

**依据：** [流式协议](../proto/tide/asr/v1/asr.proto)、[Mock Worker](../internal/mockasr/worker.go)。没有对应的已落盘 ADR / Experiment，不补造历史记录；旧文档中的 ADR-001 引用无对应文件，故移除。

## M2 — WebSocket 端到端链路

**目标与范围：** 跑通 Client → Gateway → Mock Worker，以及反向结果通路。

**验收与状态：已完成基础范围。**

- [x] 客户端按音频时间轴发送 Start、二进制音频、End，并同步读取结果。
- [x] 音频未发送结束即可收到 partial；正常 End 能收到尾部结果。
- [x] 多会话使用独立 RPC，不串音频与结果。

**依据：** [客户端](../internal/wsclient/client.go)、[Gateway](../internal/gateway/gateway.go)、[协议](../internal/wsprotocol/protocol.go)。[EXP-003](experiments/EXP-003-streaming-load.md) 后续补充了多会话结果归属、顺序和完整性检查，不作为早期实验记录。

## M3 — 会话生命周期管理

**目标与范围：** 明确会话、连接、RPC 和执行流的所有权，实现并发安全的登记、接入限制、取消与服务关闭。

**验收与状态：已完成基础范围。**

- [x] 注册表逐个保存会话；升级前登记，准备、运行和清理阶段均占用名额，原子检查 `MaxSessions`。
- [x] 正常完成、升级失败、协议错误、已被读取发现的客户端断开和 Worker 错误进入相应收尾路径。
- [x] 先取消和关闭以解除等待，再等待执行流退出，最后注销并归还名额。
- [x] `StopAccepting` 停止接入；`Wait` 等待全部注销；`Abort` 请求强制终止，重复及并发调用受控。
- [x] 服务关闭先自然排空，预算耗尽后强制清理；已接管的 WebSocket 连接由会话路径管理。
- [x] 使用关联 `session_id` 的 slog 日志；测试覆盖并发登记、取消、升级竞争和关闭编排。

**边界：** M3 范围内一个 WebSocket 会话对应一次 RPC；跨连接的 `RecognitionAttempt` 生命周期由 M6 增加。M3 的完成不包含静默断网发现、自动重连、断点续传或实例故障后的会话恢复。Start/建流没有专用期限；同步 Close/Abort 不能被等待预算抢占，因此没有无条件的退出时间保证。

**依据：** [当前架构](architecture.md)、[注册表测试](../internal/gateway/registry_test.go)、[Gateway 测试](../internal/gateway/gateway_test.go)、[Abort 回归测试](../internal/gateway/abort_regression_test.go)、[关闭测试](../cmd/gateway/shutdown_test.go)。M4 的 [EXP-001](experiments/EXP-001-send-stall-disconnect.md) / [EXP-002](experiments/EXP-002-slow-websocket-write.md) 进一步验证并加固了阻塞 I/O 下的退出能力。

## M4 — 背压与实时性控制

**目标与范围：** 短暂抖动下继续转发，持续处理不足时限制资源和等待，并明确失败语义。关注单会话流式链路，Worker 池容量与分配策略留给 M5。

**验收与状态：已完成约定范围。**

- [x] 上行拆分为 Reader → 有界音频 FIFO → Sender，读取不等待 Send 或队列空位。
- [x] 同时限制队列字节数和块数；满队列明确过载失败，取消 RPC，并尝试通知 WebSocket 1013。
- [x] End 后按序排空，再半关闭请求；结合发送完成与 Worker EOF 判断正常结束。
- [x] 下行保留 Recv → Write，单条结果写入有独立期限；验证慢写退出行为。
- [x] 保存 Send 停滞、慢 Write 的基线与改动后对照；完成持续音频、多会话、抖动和慢 Worker 的初步负载实验。
- [x] 确认工程初值：正常转录可见延迟 P95 目标 1 秒，最早未确认处理音频等待 3 秒触发失败，End 后完成预算 5 秒；M4 本身不提供失败尾部自动补全，M6 的 v2 另提供有限补齐。真实出字目标与 Mock 回显指标分开验证。
- [x] EXP-004 对比局部期限与处理进度监测，验证短暂抖动、模拟静音、批量进度、单块停滞和 End 后无 EOF 的行为。
- [x] ADR-003 确认处理进度监测与独立 End 期限；已实现原生 Worker 进度协议、有限记录表、协调者计时和明确的超时关闭原因。
- [x] 正式实现重跑 EXP-004 七场景各两次，验证持续停滞、静音、批量确认和 End 后不返回 EOF；补充协议边界与并发进度测试。
- [x] EXP-005 补充真实 loopback TCP 慢读、恢复读取、RST、Abort，以及不同期限先触发的清理对照，共 18 次正式运行。
- [x] 基于 EXP-005 确认保留当前尽力关闭通知及默认写入期限，暂不增加独立异常收尾预算；接受取消与注销可能有间隔，不承诺统一 5 秒清理上界。

**当前证据：** 历史 EXP-003 最终采用 16 轮、179 个会话：155 个正常完成，24 个按预期过载退出，清理后登记数均为零。但慢 Worker 下，已返回结果最大延迟约 5.64 秒；**队列可容纳 2 秒音频，不等于端到端延迟上限为 2 秒**。原有队列与写入参数保持不变。

EXP-004 的 42 次候选实验说明局部期限未覆盖已离开队列且 Send 已返回的音频停滞。方案确认并实现后，又完成 14 次生产对照：8 次正常完成、6 次期限退出，约 3 秒未确认等待或 5 秒 End 等待触发，全部清理后登记数归零。更早取消仍有未完成尾部，真实出字 P95 目标尚未验证。进度确认是新的必需 Worker 语义，Gateway 与 Worker 需要配套升级。

EXP-005 的默认 2 秒写入配置正常退出并释放；写入期限扩大到 8 秒时，处理/End 期限仍能在约 3/5 秒取消 RPC，但会话接近第 8 秒才注销。已有取消目标没有因此被推翻，且尚无并发负载证据表明额外清理等待造成容量问题，因此暂不增加独立异常收尾预算。后续若需延长写入期限，或清理中的会话占用名额影响接入，再单独评估。M4 按此边界完成，不代表真实 ASR 延迟目标已验证。

**关联：** [ADR-002](adr/ADR-002-streaming-io-backpressure.md)、[ADR-003](adr/ADR-003-processing-progress-deadline.md)、[EXP-001](experiments/EXP-001-send-stall-disconnect.md)、[EXP-002](experiments/EXP-002-slow-websocket-write.md)、[EXP-003](experiments/EXP-003-streaming-load.md)、[EXP-004](experiments/EXP-004-processing-progress-deadline.md)、[EXP-005](experiments/EXP-005-tcp-slow-client-cleanup.md)。

## M5 — 容量评估与 Worker 调度

**目标与范围：** 在共享下游处理能力受限时，确定稳定容量、接入规则和多 Worker 会话分配方式。

**状态：已完成约定实验与基础范围。** 已完成共享 Worker 基线、接入保护、固定 Worker 预留、分配对照和持续容量验证；ADR-006 确认 LRR，ADR-007 确认 EXP-009 条件下的保守实验配额 1/3。 `MaxSessions` 是当前静态接入上限，不是测得的稳定容量；EXP-003 中各流独立模拟处理，32 会话通过不证明共享模型能承载 32 会话，不能替代本阶段多 Worker 的验证。

**验收结果：**

- [x] 构建共享处理能力受限的可控 Worker，逐步增加负载，观察正常、临界和过载区间（EXP-006：五档 20 秒、两档 60 秒）。
- [x] 确认并验证“容量满时立即拒绝新会话，优先保护已接入问诊”：EXP-007 按原有/新增群体比较正常与短暂停顿，核对拒绝、RPC 创建、清理与名额复用。
- [x] EXP-009 按 Worker 和十秒窗口报告完成率、延迟、未回显量、CPU/堆及清理，比较三档一分钟负载，完成候选五分钟验证；结论限定于本机 Mock，最大稳定容量未证明。
- [x] ADR-005 确认并实现升级前 Worker 原子预留，清理后先归还再注销；测试覆盖容量拒绝、并发释放、固定路由和显式停止新预留。
- [x] EXP-008 比较同/异构配额、交错释放的两种选择策略，保存 8 次逻辑重放、8 次流式负载和 24 个微基准样本；全部 32 个流式会话完整清理。显式停止接入不等于自动故障检测。
- [x] 依据 EXP-008 及适用边界，在 ADR-006 确认最小预留比例为推荐策略，保留轮询对照和多 Worker 显式配置。
- [x] ADR-007 确认容量取舍及适用边界：1/3 为本轮保守实验配额，1/4 保留为正常负载下的较高利用率候选；应用启动默认值保持原样。

**当前证据：** [EXP-006](experiments/EXP-006-shared-worker-capacity.md) 固定 4 个共享处理槽位、每块模拟 10 ms。20 秒组 8 并发全部完成，但回显 P95 已为 1.675–1.897 秒；60 秒组 6 并发全部完成、P95 22 ms，8 并发则在约第 40.48 秒出现三个处理超时。12 次实验共 106 个会话，63 个正常、43 个处理超时，最终全部注销。6 是候选实验配额，不是已证明的最大稳定容量或生产参数。

[EXP-008](experiments/EXP-008-worker-selection.md) 在异构配额 2/6、处理槽位 1/3 的六秒四会话负载中，轮询分配 2:2，回显 P95 约 1.49 秒；最小预留比例分配 1:3，P95 15–16 ms。同容量组均约 14–15 ms。全部 32 个流式会话完整结束并归还预留；这支持比较候选的分配行为，不是长期稳定容量结论。

[EXP-009](experiments/EXP-009-multi-worker-capacity.md) 共 17 个正式样本：1/5 的 B 两轮均出现处理超时；1/4 正常一分钟负载两轮达标，但十次周期暂停中三次未确认达到恢复观测阈值；1/3 的十次暂停均确认恢复，并通过四会话五分钟正常输入。持续降速时 B 的会话仍会超时，A 在本实验中保持完成。80 个主会话中 67 个正常、13 个超时，另有 30 次拒绝及 80 个正常复用探针，全部清理，无样本排除。[ADR-007](adr/ADR-007-experimental-capacity-margin.md) 据此确认实验配额取舍；未确认恢复不等于已证明无限积压。

**关联：** [EXP-003](experiments/EXP-003-streaming-load.md) 提供负载工具；[EXP-006](experiments/EXP-006-shared-worker-capacity.md) 提供共享能力基线。[ADR-004](adr/ADR-004-admission-protection.md) 已确认接入保护取舍；[EXP-007](experiments/EXP-007-admission-protection.md) 的四个合格样本支持本轮候选配额保护原有会话（另四次因时间连续性问题排除并保留）。[ADR-005](adr/ADR-005-worker-reservation-lifecycle.md) 已确认本地预留的生命周期；[ADR-006](adr/ADR-006-least-reserved-ratio-selection.md) 已确认最小预留比例为当前推荐策略。

**收尾边界：** 已验证的是本机 Mock 的有限时长负载及所列故障，未证明最大稳定容量或生产就绪。没有多 Gateway 配额协调、自动健康检测、动态配额或跨 Worker 迁移。五分钟正常组和一分钟周期暂停组分别运行；部署模型、环境或负载改变时重新标定容量。故障发现与恢复语义进入 M6 讨论，真实 ASR 和临床时长验证由 M7 承接。

## M6 — 弱网与故障恢复

**目标与范围：** 区分断开、静默失联和实例故障，定义检测、终止及恢复转录的语义。

**状态：检测与有限恢复基础已实现，M6 未完成。** ADR-008 提供双端心跳；ADR-009 确认由客户端持有业务 Session、独立 RecognitionAttempt、安全断点提交、有限音频缓存和共享恢复预算。v1 保留单次链路，显式 v2 使用新的可恢复 Worker RPC。EXP-014 已验证实际链路的重放、缺口和停止语义；EXP-015 已在默认缓存与预算下验证单会话持续输入，处理余量不足会持续出字却无法及时追上。尚未完成静默失联与恢复的联合验证，不是生产恢复保证。

**当前证据：** [EXP-010](experiments/EXP-010-silent-disconnect.md) 完成九场景、基线与心跳候选各两轮，共三十六个正式样本，无排除。两秒周期、三秒响应预算的双端 Ping/Pong 在十二个故障候选样本中约 3.8–4.8 秒观察到失联，六个健康/暂停候选样本没有提前退出；基线无待确认音频时在六秒窗内不能检测静默阻断。默认 Send 停滞组仍先由三秒处理期限取消，候选随后才结束失联收尾。全部最终清理归零，但基线故障组使用了窗口后的兜底，不能计为自行恢复。候选正常停用时取消在途 Ping 导致误关连接的开发失败已记录并由定点回归复现、修正。

[EXP-011](experiments/EXP-011-heartbeat-interval.md) 再比较两秒和五秒周期，三秒单次预算保持不变：二十四个检测样本中，故障组分别约 3.8–4.8 秒和 6.8–7.8 秒发现失联，健康/暂停组无提前退出。十二个开销样本覆盖 64/256 个空闲会话与无心跳对照；256 会话下，测试进程 CPU 从约 0.021–0.023 核降至 0.007–0.010 核，五秒档少 60% 探测，常驻心跳 goroutine 数不变。三十六个正式样本全部通过质量及清理校验，无排除；不把空闲会话数当成 ASR 容量，音频积压和追赶仅作解析估算，未测真实恢复时间。[ADR-008](adr/ADR-008-websocket-heartbeat-lifecycle.md) 已确认两秒周期、三秒预算作为可配置的实现初值，五秒仍可作对照；不承诺所有网络下五秒必达。

**实现回归：** [EXP-012](experiments/EXP-012-heartbeat-lifecycle.md) 验证等待 Start、慢建流、Send 停滞时的失败取消，以及正常 End、在途 Ping 停用、Abort、处理期限先取消等协调边界。失败探测不再追加等待关闭握手，原有业务失败原因仍保留；这些回归不代表容量或恢复性能。

**恢复候选证据：** [EXP-013](experiments/EXP-013-recovery-checkpoint.md) 完成十三种组合各三轮，共三十九个样本，保留十五个预期语义失败。按处理水位释放会丢失尚未应用的结果；尝试隔离与重复事件处理避免所测重复。正常连接长期没有安全断点也会耗尽十五秒缓存。生产 Gateway 接入组确认旧清理仍占名额、重试共享总预算。该实验的协议部分是可控 Worker 与客户端状态模型；实际实现随后由 EXP-014 验证，真实 ASR 的断点能力和追赶时间仍未验证。

**已实现与验证：**

- [x] 每次尝试建立新的连接/RPC，复用客户端业务身份；本地旧尝试先取消并 join，再重新接入，继续服从 M5 配额。
- [x] 结果和安全断点原子应用，按采样点重放；静音覆盖、旧尝试隔离、重复结果和非法范围均有检查。
- [x] 缓存不足时保留显式缺口；未 End 可在剩余预算内从新片段继续，End 后只补尾部；预算耗尽停止自动重试。
- [x] [EXP-014](experiments/EXP-014-production-recovery.md) 十种场景各三轮，十五个完整、十五个按预期不完整；结果与缺口覆盖一致，全部 Gateway 排空及受控 RPC 归零。
- [x] [EXP-015](experiments/EXP-015-continuous-recovery.md) 四组各两轮：持续十六秒输入、默认心跳/缓存/预算下，明确 Worker 故障加两秒接入不可用后，40 ms/100 ms 音频档约四秒追上；80/100 ms 档持续返回结果但十秒预算内未追上，按约定中断。全部覆盖和清理检查通过。

**剩余验收：**

- [ ] 在静默链路阻断下联合验证默认心跳、十五秒缓存和十秒恢复预算，将检测期间积压计入，检查重放与 M4 处理期限/队列的相互影响。
- [ ] 补静默断网恢复、Gateway/Worker 实例退出及重新接入的完整链路验证；已有检测与消息丢失回归不替代进程故障实验。
- [ ] 分别观测检测、重新接入、重放和追赶时间，结合接入拒绝、旧尝试清理及并发恢复负载评估边界。

**关联：** [当前架构](architecture.md)、[ADR-008](adr/ADR-008-websocket-heartbeat-lifecycle.md)、[ADR-009](adr/ADR-009-bounded-recovery.md)、[恢复协议](recovery-protocol.md)、EXP-010 至 EXP-015。真实 ASR 断点契约与质量由 M7 验证。

## M7 — 真实 ASR 与临床时长验证

**目标与范围：** 接入真实流式模型，在目标部署环境验证完整 ASR 链路。AIGC 病历生成不属于本路线的实现范围。

**状态：未开始。** 五分钟 Mock 负载不能替代数十分钟问诊验证。

**计划验收：**

- 验证真实模型的音频格式、partial/final、半关闭、错误和取消契约；有差异时重新评估接口。
- 定义真实音频采集到结果可见的延迟口径，分别观察中间结果与最终结果，避免直接套用 Mock 逐块回显指标。
- 按确认的临床会话时长、并发和故障负载运行，报告端到端延迟、稳定容量、资源趋势及恢复行为。
- 保存硬件、模型、参数、版本和原始数据，形成部署建议及已知限制；真实模型推翻早期假设时回到对应阶段修正。

**关联：** 尚无本阶段 ADR / Experiment。

## 跨阶段要求与下一步

当前已有结构化日志、回归测试和实验用指标采集；尚未形成在线服务的完整指标体系。随 M4–M7 的验证需求补充活跃会话、拒绝与退出原因、排队与处理延迟、资源及恢复指标，并控制采集开销。实验 hook 不等于生产监控。

**下一步验证 M6 静默失联后的追赶：** EXP-015 已将明确 Worker 失败、两秒接入不可用和不同处理速率组合验证；80 ms 档说明“能继续出字”不等于十秒内恢复实时性。接下来用静默链路阻断增加真实心跳检测等待，检查更大重放积压是否先触发 M4 保护，再补实例退出及并发恢复。默认配置在单会话合成 Worker 下的结果不替代真实模型能力；若需要改变预算或流控语义，再按工作流讨论。

涉及重要设计或语义选择时遵循 [文档工作流](README.md)：对话讨论及必要基线实验 → 确认选择 → 最终 ADR → 实现与验证。普通实现、一般 bug 修复和本次进度整理不单独创建 ADR。

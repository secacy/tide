# 文档约定

仓库文档用于解释系统如何运行、为什么这样设计，以及验证了哪些行为。个人复盘和面试表达保存在本地。

| 位置 | 内容 | Git 管理 |
| --- | --- | --- |
| [MILESTONES.md](MILESTONES.md) | 阶段目标、进度、验收结论与证据缺口 | 是 |
| [command.md](command.md) | 当前可用命令、参数和运行方式 | 是 |
| [adr/](adr/README.md) | 正式架构决策：问题、备选方案、选择、后果与约束 | 是 |
| `worklog/` | 工程推进记录：技术设计、协议契约、分步实现、问题修正与验收 | 是 |
| `experiments/` | 实验条件、判据、报告、工具与归档证据 | 是 |
| `personal/` | 个人日常笔记、STAR + T、简历与面试准备 | 否；本地保留，由根 `.gitignore` 忽略 |

## 工程记录与 ADR

现有工程记录统一放在 `worklog/`，保留日期文件名和历史验收内容。它们记录“提出方案 → 分步实现 → 问题修正 → 测试验收”的过程，便于追溯如何实现和验证。

ADR 聚焦一个需要长期记住的决策，例如“为什么按会话绑定 Worker”“为什么采用累计处理确认”。编写时使用 [ADR 模板](adr/TEMPLATE.md)，写清备选方案、最终选择、必要约束和已知代价，并链接工程记录及实验依据。决定被替代时记录替代关系。

第一至第五阶段的七项关键决策已整理，见 [ADR 索引](adr/README.md)。后续从 worklog 中提炼新的重要决策，并维护替代关系。实现进展和逐轮测试继续记录在工程或实验文档中；个人贡献复盘、简历表达与面试准备写在 personal 中。

## 引用与归档

受 Git 管理的文档引用同样受管理的文件，使新的 checkout 能独立阅读。个人总结中的项目事实，应有 Milestones、工程记录或实验依据；仓库中的结论直接引用这些依据，不依赖 personal 中的文件。

移动文档时同步更新相对链接。实验归档中的源码快照、日志、清单及哈希保持原始内容，历史路径按当时版本解释；文档迁移不改写归档证据。

文档目录中，`.gitignore` 只忽略 `/docs/personal/`，worklog 中的工程记录正常跟踪。忽略规则只影响未跟踪文件；已跟踪的个人笔记需要撤销索引登记并保留本地文件，现有 Git 历史仍会保留此前提交的内容。

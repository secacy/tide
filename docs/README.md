仓库文档用于解释系统如何运行、为什么这样设计，以及验证了哪些行为。个人复盘和面试表达保存在本地。

| 位置 | 内容 | Git 管理 |
| --- | --- | --- |
| [MILESTONES.md](MILESTONES.md) | 阶段目标、进度、验收结论与证据缺口 | 是 |
| [command.md](command.md) | 当前可用命令、参数和运行方式 | 是 |
| `adr/` | 正式架构决策：问题、备选方案、选择、后果与约束 | 是 |
| `designs/` | 技术设计、协议契约、分步实现与验收记录 | 是 |
| `experiments/` | 实验条件、判据、报告、工具与归档证据 | 是 |
| `worklog/` | 个人日常笔记、STAR + T、简历与面试准备 | 否；本地保留，由根 `.gitignore` 忽略 |

## 设计记录与 ADR

现有设计记录从 `worklog/designs/` 迁入 `designs/`，保留日期文件名和历史验收内容。它们包含实现指导、修改过程及测试记录，其中部分篇幅较长；这些内容适合作为技术资料保留。

ADR 聚焦一个需要长期记住的决策，例如“为什么按会话绑定 Worker”“为什么采用累计处理确认”。编写时使用 [ADR 模板](adr/TEMPLATE.md)，写清备选方案、最终选择、必要约束和已知代价，并链接设计及实验依据。决定被替代时记录替代关系。

后续可从设计记录中逐项提炼重要决策；移动文件本身不表示已完成 ADR 整理。实现进展和逐轮测试继续记录在设计或实验文档中。

## 引用与归档

受 Git 管理的文档引用同样受管理的文件，使新的 checkout 能独立阅读。个人总结中的项目事实，应有 Milestones、设计或实验依据；仓库中的结论直接引用这些依据。

移动文档时同步更新相对链接。实验归档中的源码快照、日志、清单及哈希保持原始内容，历史路径按当时版本解释；文档迁移不改写归档证据。

`.gitignore` 只影响未跟踪文件。已跟踪的个人笔记需要撤销索引登记并保留本地文件；现有 Git 历史仍会保留此前提交的内容。

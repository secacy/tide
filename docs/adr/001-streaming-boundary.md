# ADR-001：通过双向流接口分离 Gateway 与 ASR Worker

- 状态：Accepted
- 记录日期：2026-10-04
- 覆盖阶段：第一、二阶段；引用后续接入和验证
- 依据性质：回溯记录。现有依据未确认原始选型日期，受版本管理的资料未提供完整的早期方案比较；本文依据现有协议、代码和 Milestones 说明当前选择，备选方案分析为本次补充。
- 关联：[ADR-002](002-session-lifecycle.md)、[ADR-007](007-session-worker-selection.md)

## 问题与约束

客户端需要持续上传音频，同时接收逐步产生的识别文本。Gateway 需要管理外部连接、协议和会话退出；具体模型及计算资源可能独立变化。将这两类责任分开，才能在保留客户端入口的同时替换或增加识别后端。

现有系统以一次客户端连接承载一次会话。输入包含 start、音频和 end；输入结束后还可能有结果返回。链路必须允许双向独立推进，不能等待上传整段音频后才开始接收结果。

## 可选方案与依据

以下为当前架构的回溯比较，不表示早期已逐项评测。

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| Gateway 进程内直接调用模型 | 少一层网络传输，部署简单 | 模型依赖、计算资源和连接服务共同变化，故障与扩缩容边界更紧密 |
| 整段上传后提交识别任务 | 任务边界清晰，适合离线处理 | 难以满足当前上传期间持续返回结果的目标 |
| Gateway 与独立 Worker 通过双向流协作 | 将接入与识别职责分开，支持持续发送与接收、独立后端进程 | 引入网络错误、流取消、协议演进与跨进程观测责任；当前采用 |

没有 WebSocket 与其他客户端传输协议、gRPC 与其他内部协议的性能对照证据。选用当前协议不构成协议性能优越性的结论。

## 决策与契约

1. 客户端通过 WebSocket 接入 Gateway，Gateway 通过 `StreamingRecognize` gRPC 双向流调用 Worker。合法 start 通过后才创建识别流。
2. 当前一个 WebSocket 会话对应一条独立识别流。Worker 计算、进度与识别结果通过约定协议返回，Gateway 负责转发、控制和清理。
3. 请求流关闭与响应流结束分别表达输入结束和后端完成；具体成功判定见 ADR-002。
4. 第五阶段启动层为各后端持有并复用 gRPC ClientConn，会话拥有自己的 RPC 流及取消范围。单场退出不关闭其他会话共享的 ClientConn，连接由启动层回收。
5. 后端适配器须遵守协议语义，包括片段结果以及启用积压保护时的处理确认；统一方法签名本身不足以保证任意模型可直接替换。

## 事实、假设与代价

**已验证事实：**现有 Mock 链路支持音频上传期间返回结果、合法 end 后继续返回尾部，以及会话隔离；第五阶段已有多后端路由和共享连接回收验收。入口见[第一至三阶段记录](../MILESTONES.md)、[正常结束测试](../../internal/gateway/normal_end_test.go)、[会话隔离测试](../../internal/gateway/client_disconnect_test.go)及[多 Worker 接入验收](../worklog/2026-09-27-worker-session-routing.md)。这些是已有证据，本次整理未重新运行测试。

**架构假设：**目标 ASR 可以由适配器提供当前流式结果及取消语义。真实模型是否能提供可信处理进度、如何报告说话人信息，仍需第七阶段验证。

**当前约束与代价：**连接级会话没有跨连接恢复标识；请求与响应需要跨网络协调，当前测量不足以给出真实推理延迟或生产容量。Mock 的固定文本不验证识别质量。

## 重新评估条件

第六阶段需要让逻辑问诊跨连接存活时，应明确区分连接与逻辑会话，修订当前一对一生命周期约定。真实适配器在进度、分段或取消语义上无法满足现有协议时，应先调整接口契约，再接入模型；已有实现能力不自动视为适配器保证。

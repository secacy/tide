# ADR-002：由会话协调者统一判定结束并执行清理

- 状态：Accepted
- 记录日期：2026-10-04
- 覆盖阶段：第三阶段；纳入第四阶段新增退出原因
- 依据性质：依据 Milestones、当前代码与既有测试回溯整理。未确认独立原始决策日期；本文的备选方案表为本次补充分析。
- 关联：[ADR-001](001-streaming-boundary.md)、[ADR-003](003-session-admission.md)、[ADR-004](004-operation-deadlines.md)

## 问题与约束

音频上传和结果返回并行进行。一侧异常退出时，另一侧可能仍在读写；两侧都可能报告同一次取消引发的错误。直接结束整场又可能丢失合法 end 后的尾部结果，因此需要明确业务完成条件和资源清理责任。

发出取消通知只代表要求操作停止。会话收尾还需解除阻塞、等待内部 goroutine 退出，并释放连接和准入名额。服务退出时也需要统一执行这些步骤。

## 可选方案与依据

| 方案 | 收益 | 代价与选择 |
| --- | --- | --- |
| 上传和下载各自关闭资源 | 局部错误路径较短 | 关闭顺序与原因判定分散，需额外协调重复关闭及尾部保留 |
| 主要依赖并发任务返回的 error | 容易复用任务组工具 | end 是中间事件，`is_final` 是片段状态，正常 EOF 还要结合输入状态；仍须增加业务判定 |
| 两侧汇报事件，由协调者判断并收尾 | 关闭责任和结果判定集中，便于验证竞争场景 | 必须维护事件含义、错误归类与清理顺序；当前采用 |

任务组工具也可以与业务事件配合使用。当前代码在会话内采用事件协调，在主程序中使用 errgroup 协调服务运行与退出；未做两种工具的性能对照。

## 决策与契约

1. 上传、下载负责描述退出事件，`session.run` 协调判定并调用 `finish` 收尾。保护辅助函数可以取消实际阻塞的 RPC/I/O；最终关闭策略仍由协调者汇总。
2. 合法 end 表示输入结束，上传半关闭请求流并继续保留接收方向。`is_final` 仅代表片段定稿。正常完成候选要求 Worker 响应 EOF、此前结果已完成网关写回，并且协调者已观察到合法 end；还需正常收尾。
3. Worker 在合法 end 前结束不能被当成整场完成。这里按协调者可观察的通知与事件判定，不承诺还原分布式事件的精确物理先后。
4. 异常收尾取消对应 RPC，并按退出原因关闭 WebSocket/取消其 I/O，随后等待会话内两个 goroutine 退出。正常收尾保留尾部结果后尝试正常关闭握手。
5. 多个原因竞争时，协调者检查服务停止、RPC 发送超时、输入超时、结果写回超时，再处理收到的事件；不以某个 goroutine 偶然先返回的传输错误直接替代业务原因。
6. 停服先关闭准入、取消已有会话，再在共享的 15 秒清理等待预算内关闭 HTTP 服务并等待会话退出。等待失败向主程序返回错误；不会等待所有问诊自然结束。

实现依据：[session.run / waitSessionResult / finish](../../internal/gateway/session.go)、[上传](../../internal/gateway/upload.go)、[下载](../../internal/gateway/download.go)、[服务退出](../../cmd/gateway/main.go)。

## 事实、假设与代价

**已验证事实：**[第三阶段资源清理实验](../experiments/session-lifecycle-cleanup.md)记录五次运行、每次 20 轮、每轮六场，共 600 个正式会话；覆盖正常结束、客户端断开和 Worker 报错，逐轮会话与服务端连接归零，Worker 与 handler 退出。正常尾部、提前 EOF 和停服另有[正常结束测试](../../internal/gateway/normal_end_test.go)、[Worker 异常测试](../../internal/gateway/worker_failure_test.go)和[停服测试](../../internal/gateway/shutdown_stream_test.go)。这是已测条件下的证据，不能推出任意故障下绝无泄漏。

**架构假设：**底层网络操作与 Worker 流能响应取消或连接关闭；具体适配器需要验证这一前提。

**当前约束与代价：**WebSocket 关闭握手、运行时调度和取消传播都有耗时。15 秒是服务清理等待预算，`Wait` 超时不会强制销毁会话；发送取消与清理完成必须分别观察。当前 `ServeHTTP` 丢弃 `session.run` 返回值，不能把内部分类能力描述为已经具备完整线上失败指标。

## 重新评估条件

引入连接重附着、有限重放或后台保留会话后，“客户端断开即清理整场”的规则需要调整。新的 ADR 应明确逻辑会话、连接和 Worker 流各自的所有权、保留窗口及终止条件，并复验尾部和准入释放行为。

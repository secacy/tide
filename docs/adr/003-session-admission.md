# ADR-003：以未完成清理的会话数执行单实例准入控制

- 状态：Accepted
- 记录日期：2026-10-04
- 覆盖阶段：第三阶段计数与停服；第四阶段容量准入
- 依据性质：准入选择依据来自 2026-09-22 工程记录；早期 tracker 职责依据 Milestones 和现有实现回溯，日期不合并为单一原始决策时间。
- 关联：[ADR-002](002-session-lifecycle.md)、[ADR-007](007-session-worker-selection.md)

## 问题与约束

即使每个异常会话最终都会退出，同时接入过多会话仍会占用连接和 goroutine。长时问诊的名额释放较慢，满载后继续等待也需要额外的排队上限、期限和取消规则。

现有 tracker 已管理活动数与停止接入状态。本阶段需要保证单实例接纳上限和停服的一致性，尚不需要按 ID 查询、定向取消或跨连接恢复。

## 可选方案与依据

以下准入取舍来自[同期设计记录](../worklog/2026-09-22-session-admission.md)。

| 方案 | 收益 | 代价与选择 |
| --- | --- | --- |
| 满载后等待空位 | 吸收短暂接入峰值 | 等待者仍占资源，需要额外有界队列、期限及取消；暂不采用 |
| 独立 channel 信号量 | 获取与归还直观 | 与已有 active/stopping 形成两套状态，需要共同协调 |
| 在 tracker 同一临界区判断并登记 | 复用计数、停止与归还机制 | 锁只允许做状态操作，不能覆盖网络等待；当前采用 |
| 外部分布式名额服务 | 可以限制多 Gateway 总量 | 增加跨实例协调和故障语义；当前范围为单实例 |

按 ID 保存对象的注册表可支持查询与恢复，但仅为计数和统一停服引入它会增加对象登记及删除责任。该边界见[第三阶段记录](../MILESTONES.md)。

## 决策与契约

1. `active` 表示已登记但尚未完成清理的会话，包括升级、等待 start、识别和收尾。WebSocket 升级前在同一把锁内检查 stopping、上限并递增；失败不改计数。
2. 满载或停止立即返回 HTTP 503，以错误文本区分原因；不升级、不创建 Worker 流、不等待名额。拒绝请求仍有普通 HTTP 处理开销。
3. 每次成功登记对应一次 `leave`，在会话及连接清理后执行。升级失败也归还；end、RPC 取消或单侧 goroutine 返回均不提前释放名额。
4. `StopAccepting` 永久禁止新登记，调用本身不取消旧会话。`drained` 在已停止且 active 为零时关闭；`Wait` 只等待该事实，不负责取消。
5. `MaxSessions` 负值拒绝、零使用开发默认值 64、正值自定义。该数值是保护配置；它与按负载测得的容量分别管理。
6. 当前只保存数量及状态，没有会话对象注册表，也没有按 Worker 活跃数反馈调度。

实现依据：[tracker](../../internal/gateway/tracker.go)、[HTTP 准入和配置](../../internal/gateway/handler.go)。

## 事实、假设与代价

**已验证事实：**[准入实验](../experiments/session-admission.md)在上限四的条件下进行五轮、每轮 20 次突发，共接纳 20、容量拒绝 80、其他错误零；每轮占用保持为四，清理后归零，另有五次重新接入正常完成。[边界测试](../../internal/gateway/admission_test.go)覆盖并发登记、拒绝不扣名额、停止接入及升级失败归还。

**架构假设：**实例级会话数可作为第一层保护，运维配置应根据具体负载评估。没有证据证明默认 64 适合目标真实模型。

**当前约束与代价：**所有会话等额占位，未按音频成本计费；上限不覆盖所有 HTTP 连接或内核资源，多实例共享下游时也不提供总量保证。提前拒绝会损失本次接入机会。仅计数不能定位某个会话对象。

## 重新评估条件

需要断线保留和重附着时，明确保留会话是否继续占位以及如何登记对象；需要跨实例总容量或不同优先级时，再定义全局名额和公平性。若改为等待准入，必须同时定义队列容量、期限、取消及拒绝指标，不能仅增加等待。

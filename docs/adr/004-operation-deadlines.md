# ADR-004：按操作与阶段设置等待期限

- 状态：Accepted
- 记录日期：2026-10-04
- 覆盖阶段：第三、四阶段
- 依据性质：start/输入等待依据第三阶段记录回溯；发送、尾部和结果写回依据 2026-09-21 至 2026-09-22 工程记录整理。后补分析不作为原始评测事实。
- 关联：[ADR-002](002-session-lifecycle.md)、[ADR-003](003-session-admission.md)、[ADR-005](005-processed-audio-budget.md)

## 问题与约束

长时问诊允许音频持续输入，但某次发送、结果写回或输入结束后的处理可能停止推进。单个输入空闲期限无法覆盖这些不同等待；为整个 RPC 设置较短期限则会截断仍正常运行的问诊。

期限触发必须作用于实际阻塞操作，并最终释放资源。只让外层函数返回超时、让发送或写入 goroutine 留在后台，不能满足清理要求。

## 可选方案与依据

| 方案 | 收益 | 代价与选择 |
| --- | --- | --- |
| 整场固定短 deadline | 统一且容易配置 | 与长时问诊冲突；未来最大会话时长策略可另行定义 |
| 用任意结果输出刷新统一 watchdog | 能检测部分无输出场景 | 静音和结果频率影响含义，零星输出也可能持续续期；需要先定义进展 |
| 队列分离读写 | 队列有余量时可继续读取 | 满载后仍要定义期限与退出，且引入排队责任 |
| 分别约束当前操作及 end 后完成等待 | 对应已定位的阻塞点，便于独立归类和验证 | 配置与竞争判定增加，阈值过紧会结束原本可完成的慢会话；当前采用 |

发送期限的初始比较与后来补充的 watchdog/计时方式讨论，见[发送记录](../worklog/2026-09-21-worker-send-timeout.md)；尾部与写回选择分别见[尾部记录](../worklog/2026-09-22-tail-timeout.md)、[写回记录](../worklog/2026-09-22-result-write-timeout.md)。这些机制可以组合，不表示做过所有方案的性能 A/B。

## 决策与契约

| 控制点 | 计时范围 | 当前开发默认值 |
| --- | --- | --- |
| StartTimeout | 等待完整 start 的读取与校验 | 10 秒 |
| InputIdleTimeout | 音频阶段每次读取下一条完整消息 | 30 秒 |
| WorkerSendTimeout | 单次同步 Worker Send | 2 秒 |
| TailTimeout | 协调者观察合法 end 后，到 download 完成事件的一次性等待 | 15 秒 |
| ResultWriteTimeout | 单条结果的 WebSocket Write；编码在计时前 | 2 秒 |

默认值来自[配置代码](../../internal/gateway/handler.go)，用于开发保护，不作为业务 SLA 或已测最优值。

- 发送保持原上传者同步执行，通过计时回调取消创建 stream 的实际 RPC；回调已经启动时等待其结束，避免迟到取消影响后续操作。同步辅助函数依赖 stream 响应 RPC 取消，不能强制停止不响应取消的自定义实现。
- 合法 end 后关闭输入空闲计时的使用，启动一次尾部完成预算；后续 partial/final 不延长预算。预算起点是协调者收到通知，非客户端发送 end 的精确时刻。
- 结果写回用独立子 context 限时。超时可能导致连接关闭，协调者检查已发布的期限状态，以免先到的上传错误掩盖写回超时。
- 每类超时进入统一收尾。正常 Write 成功不表示客户端应用已消费文本，Send 成功不表示 Worker 已处理音频。
- 不用这些期限相加推导整场转录延迟或清理硬上限。输入空闲期限不覆盖阻塞 Send，尾部期限也不度量输入阶段的处理落后。

实现依据：[发送](../../internal/gateway/send.go)、[输入](../../internal/gateway/upload.go)、[尾部](../../internal/gateway/tail.go)、[写回](../../internal/gateway/result_write.go)、[原因协调](../../internal/gateway/session.go)。

## 事实、假设与代价

**已验证事实：**[停读后的发送期限实验](../experiments/worker-send-timeout.md)中，保持连接和客户端断开两组各三次均自主清理；断开组外部兜底由 3/3 变为 0/3。[尾部期限实验](../experiments/tail-timeout.md)与[结果写回实验](../experiments/result-write-timeout.md)分别使用 200ms 测试预算，三次均自主退出，释放后重新握手成功。重新握手不等于完成第二场 ASR；完整正常尾部另由对应集成测试覆盖。

**架构假设：**可配置期限能够覆盖目标环境中不可接受的阻塞，同时容纳允许的抖动；实际阈值需按网络和模型分布校准。

**当前约束与代价：**过慢会话会失败，可能丢失尾部。关闭握手、调度和清理耗时不都属于操作预算。现有实验证明受测场景下自主退出，不保证所有网络故障的硬性释放时间。每块计时器开销未单独 benchmark。

## 重新评估条件

有真实延迟分布后调整默认值；发现计时器分配成为瓶颈时评估复用；要求严格从 end 接收时刻计算绝对期限时引入时间戳。重连方案需明确断开等待窗口与这些操作期限的关系，避免不同期限互相覆盖。

# ADR-005：以累计处理确认控制未确认音频预算

- 状态：Accepted
- 记录日期：2026-10-04
- 覆盖阶段：第四阶段；引用第五阶段过载观察
- 依据性质：基于 2026-09-22 至 2026-09-25 处理进度、预算设计及实验记录；第五阶段结果作为后续验证。
- 关联：[ADR-002](002-session-lifecycle.md)、[ADR-004](004-operation-deadlines.md)、[ADR-006](006-mock-shared-capacity.md)

## 问题与约束

Send 可以在音频尚未处理时返回。第四阶段暂停和持续降速实验显示，未触发单次发送超时也可能积累大量未处理音频。因此需要独立于传输返回和文本产出的处理进度信号，并限制继续送入慢 Worker 的音频量。

静音仍应推进处理确认，partial/final 的出现频率不能代替音频处理位置。当前没有音频缺口协议或自动恢复能力，超限策略必须明确业务是否完整完成。

## 可选方案与依据

同期取舍见[进度设计](../worklog/2026-09-22-worker-progress.md)、[预算设计](../worklog/2026-09-23-audio-backlog-limit.md)和[队列取舍](../worklog/2026-09-25-stage4-acceptance.md)。

| 方案 | 收益 | 代价与选择 |
| --- | --- | --- |
| 只使用 Send/尾部超时 | 已有机制，控制等待 | 无法完整发现 Send 快速返回后的处理落后 |
| 增加有界音频队列 | 显式限制新增本地排队，读写可独立推进 | 已交给传输/Worker 的音频仍需计量，增加排队与收尾责任 |
| 达到预算后等待确认 | 有机会在短暂抖动后继续原流 | 实时采集可能在上游积压，需定义等待预算、唤醒及取消 |
| 丢弃旧音频后继续 | 有机会追上实时输入 | 产生转录缺口，现有协议不能完整表达或恢复 |
| 累计处理确认，严格超限则终止 | 限制继续放行，失败与清理语义明确 | 本次流无法完整完成；当前采用 |

## 决策与契约

1. Worker 按本次流起点报告连续已处理的原始音频字节数。接收或入队不等于处理完成；进度消息与识别文本字段互斥，在 Gateway 内消费，不作为文本结果发给客户端。
2. Gateway 记录累计完整接收量 `received` 和处理确认 `processed`，计算 `pending = received - processed`。确认允许相等，拒绝倒退和超过接收量；溢出/非法计量明确失败。
3. 保持单上传者逐块执行：完整读取 → 记接收量 → 检查预算 → 允许才 Send。发送失败或预算失败不回滚已经读取的事实。下载确认只减少未确认量，锁不覆盖网络 I/O。
4. `MaxPendingAudioBytes` 为零关闭、正值启用、负值拒绝。等于预算允许，严格超过则不发送触发块，并按 `audio backlog exceeded` 进入统一收尾。
5. 触发检查时已读取最后一块，所以账目可能超过预算一块消息大小；预算不等于整个进程内存或所有网络缓冲上限。单消息大小限制是另一层约束。
6. 默认关闭保留无进度 Worker 的兼容行为。启用后未收到确认不会自动豁免，累计输入仍会耗尽预算。实验候选 32000 字节在固定 PCM 下对应一秒音频量，非一秒实际排队等待。
7. 本次流的处理确认不承诺持久保存、跨流恢复或结果已经送达客户端，不能直接用于第六阶段的断点恢复检查点。

## 事实、假设与代价

**已验证事实：**[EXP-004-11](../experiments/backlog-comparison.md)在同一源码下完成三场景、两配置、各三次，共 18 个主会话。启用预算后正常和一次 500ms 暂停共 6/6 完成；持续降速三次在 35200 字节（1.1 秒音频）处明确失败，触发块未发送。关闭预算的降速组三次完成，但未确认量观测峰值为 4.3 秒音频。全部 18 次完成清理，额外 18 个短会话正常完成。实验主测使用生产 session 的接入壳，名额复用另走真实 Gateway；该差异保留在报告中。

**后续验证：**[第五阶段加权过载实验](../experiments/weighted-overload.md)中，16 并发三批共七次积压保护失败；批次后服务端归零，之后六次低负载新会话完成。它没有恢复原失败会话，也没有测得内存上限。

**架构假设：**Worker 提供可信、连续且足够及时的处理确认。确认传输延迟或慢结果写回会影响 Gateway 观察，pending 表示未确认量而非精确下游队列长度。

**当前约束与代价：**超限时舍弃本次完整完成机会；此前片段仍是部分结果。当前没有直接转发与有界队列的实现性能 A/B，没有全链路总内存上界或真实模型进度适配证据。

## 重新评估条件

如业务要求短断网后保留问诊，需要共同设计上游有限缓存、恢复确认、重放与缺口表达。发现读取/发送耦合成为具体瓶颈后，再评估有界队列并同时保留下游未确认量控制。真实适配器若无法提供可信处理确认，应明确该保护的可用性和替代契约。

# ADR-006：以跨流共享处理名额构建可控 Mock 容量模型

- 状态：Accepted
- 记录日期：2026-10-04
- 覆盖阶段：第五阶段实验基础设施
- 依据性质：共享处理容量依据 2026-09-27 设计；观测约定依据 2026-10-01 至 2026-10-02 记录；容量实验为后续证据。
- 关联：[ADR-005](005-processed-audio-budget.md)、[ADR-007](007-session-worker-selection.md)

## 问题与约束

早期 Mock 在每条流内独立等待配置的处理延迟。增加流时，各条流可以同时等待，无法明确表达一个实例的有限处理能力。用这种负载直接比较 Worker 数量或调度策略，难以解释性能变化来自什么资源争用。

需要可重复设置的实例容量模型，同时保留取消、单流顺序、进度汇报与故障注入。模型用于系统行为实验，真实推理设备仍需另行验证。

## 可选方案与依据

同期比较见[共享处理容量设计](../worklog/2026-09-27-worker-processing-capacity.md)。

| 方案 | 收益 | 代价与选择 |
| --- | --- | --- |
| 保留每流独立延迟 | 适合单流变慢和故障注入 | 不显式模拟跨流处理争用 |
| 整条流占用一个名额 | 会话容量边界直观 | 长会话会独占到结束，模型变成会话串行/有限并发，而非逐块共享处理 |
| 固定执行池与任务队列 | 可以统一排队及执行 | 增加音频所有权、结果路由、取消和流内顺序责任 |
| 每实例共享名额，每块处理期间占用 | 可配置并行度，跨流争用明确，继续使用现有流 goroutine | 等待者仍持有资源，不模拟全部 GPU 行为；当前采用 |
| 直接使用真实 ASR | 更接近目标环境 | 难固定成本及隔离模型因素；留第七阶段 |

## 决策与契约

1. `ProcessingConcurrency` 为正时，每个 Worker 实例创建一个共享名额池；零关闭限制、负值拒绝。不能每条 RPC 各建一个池，也不使用全进程全局池约束不同实例。
2. 每条流串行处理：Recv 一块 → 等待名额 → 模拟处理 → 归还 → 累计处理量并发送进度/结果。只有实际完成模拟处理的块推进确认。
3. 网络接收/发送、结果延迟及暂停/停读故障不占用处理名额；该范围是实验模型约定，不假设所有真实模型都这样使用计算资源。
4. channel 控制物理名额。获取可取消，获取成功后由处理调用者在实际处理退出时归还；context 取消不提前自动释放正在使用的名额。归还函数幂等。
5. 逻辑 in_use/waiting 及快照由短锁保护。waiting 包含已被唤醒但尚未登记成功的请求，不能机械地用“会话数减一”反推其峰值。
6. Gateway 和每个 Worker 独立采样。busy/waiting 占比是有效快照比例，非 CPU 或时间利用率；不同实例的异步峰值不能相加。

实现依据：[名额池](../../internal/mockasr/processing_slots.go)、[Worker 接入](../../internal/mockasr/worker.go)、[观测约定](../worklog/2026-10-01-worker-processing-observation.md)、[采样记录](../worklog/2026-10-02-worker-recording-tool.md)。

## 事实、假设与代价

**已验证事实：**[名额池测试](../../internal/mockasr/processing_slots_test.go)及[接入验收](../worklog/2026-09-27-worker-processing-capacity.md)覆盖竞争、取消、归还、实例隔离和处理边界。[联合观测基线](../experiments/joint-observation-baseline.md)在固定单名额条件下观测处理争用及批次前后空闲。

**后续资源对照：**[EXP-005-07](../experiments/worker-count-comparison.md)在同机把一个同配置 Worker/处理名额增加到两个，10 并发、20 秒、各三批的完成数由 26/30 变为 30/30。它说明该 Mock 模型下增加名额的效果；Mock 通过等待模拟耗时，不能据此推断 CPU 推理能力或两台机器的扩容收益。

**架构假设：**跨流争用有限处理名额足以暴露本轮想研究的调度失配和积压问题。真实 ASR 可能存在批处理、GPU 显存、缓存和可变块成本，当前模型未覆盖。

**当前约束与代价：**名额限制同时处理数，不限制活跃流或等待者总数。每个等待者可能持有一块音频，传输缓冲和识别状态不计入名额。channel 未提供本项目验证过的严格公平性；实验未测完整排队时间、CPU/GPU 或内存上限。

## 重新评估条件

需要研究批处理、动态成本或资源公平性时，先定义新的模型与指标，再决定引入任务队列或执行池。真实模型接入后，应重新测量运行点，并保留 Mock 与真实模型结论的边界。具体负载档位、采样预算、重复次数和质量门槛继续写在实验方案中。

# ADR-007：按新会话选择并绑定 Worker，支持轮询与静态加权

- 状态：Accepted
- 记录日期：2026-10-04
- 覆盖阶段：第五阶段
- 依据性质：2026-09-27 路由设计先采用轮询；2026-10-03 根据异速观察增加平滑加权及选择接口；策略对照、延长和过载为后续验证。
- 关联：[ADR-001](001-streaming-boundary.md)、[ADR-003](003-session-admission.md)、[ADR-006](006-mock-shared-capacity.md)

## 问题与约束

多个 Worker 可同时服务新会话，但有状态识别需要保持同一流的上下文。分配需与转发解耦，并允许以简单策略建立对照基线。普通轮询按选择次数均分，不表达会话时长、后端处理速度或健康差异。

[异速轮询观察 EXP-005-11](../experiments/heterogeneous-workers.md)在两个单名额、逐块耗时 10ms/20ms 的 Worker 上发现：10/12 并发均未达标，慢实例频繁繁忙和等待，快实例仍有空闲快照。由此提出按已知能力差异调整新会话比例的假设；当时尚没有加权改善的实测结果。

## 可选方案与依据

取舍来自[初始轮询设计](../worklog/2026-09-27-worker-session-routing.md)和[加权设计](../worklog/2026-10-03-weighted-round-robin.md)。

| 策略 | 收益 | 代价与选择 |
| --- | --- | --- |
| 普通轮询 | 状态少，固定列表可重复，适合基线 | 不反映处理差异；保留为默认策略 |
| 随机 | 规则简单 | 小样本波动增加实验解释成本 |
| 最少活跃会话 | 能随会话退出调整分配 | 需要获取/释放的一致性；相同活跃数不等于相同计算压力 |
| 静态平滑加权轮询 | 表达已知能力差异，改动可控 | 不感知动态变慢或健康；新增为显式可选策略 |
| 实时负载反馈 | 有机会适应动态负载 | 需要定义指标、新鲜度、失败及分配振荡；暂未实现 |

平滑加权按每次累加权重、选最高分、减去总权重工作，避免按权重展开列表。2:1 来自固定模拟耗时关系，作为首个候选比例验证，不预设最优。

## 决策与契约

1. 通过准入及合法 start 后调用一次 Pick，再创建 RPC；非法 start 或准入失败不消耗选择。选中的 Worker ID 和流保存于会话，后续音频、进度、文本及 end 均使用同一流。
2. 建流失败消耗本次选择，不回退游标、不自动重选、重放或迁移。选择成功不表示后端健康，也不保证流成功。
3. Gateway 依赖小接口 `WorkerSelector.Pick()`；实现支持并发调用、只做本地选择，不执行 RPC 或等待处理名额。共享客户端由启动层创建和关闭。
4. 保留默认 `round_robin`；显式 `weighted_round_robin` 使用按地址位置对应的固定正权重。启动校验策略、权重数量和数值，并记录实际有序配置；2:1 不成为所有部署的默认值。
5. 平滑加权构造时复制配置；整次加分、选取、扣分由一把锁保护，同分优先配置靠前者。单次 O(N)、状态 O(N)，N 为后端数；锁内不做 I/O。
6. 权重表示新选择比例，不代表并发上限、处理名额或任何时刻的活动比例。当前 Pick 没有无可用后端的错误返回，也没有占位归还契约；动态健康或最少活跃调度需要重新设计接口。

实现依据：[选择接口](../../internal/gateway/worker_selector.go)、[会话选择时机](../../internal/gateway/session.go)、[轮询](../../internal/workerpool/round_robin.go)、[平滑加权](../../internal/workerpool/weighted_round_robin.go)、[启动组装](../../cmd/gateway/worker_selector.go)。

## 事实、假设与代价

**正确性证据：**[路由及启动验收](../worklog/2026-10-03-weighted-round-robin.md)覆盖顺序/交叠会话的整场绑定、失败不重选、配置与连接回收。选择次数比例测试属于算法正确性，不代表会话吞吐或锁性能。

**同资源策略证据：**[EXP-005-12](../experiments/strategy-comparison.md)保持两个异速 Worker、两个处理名额、相同二进制和输入，三轮相邻顺序 RR/W、W/R、RR/W。12 并发、每场 20 秒、各三批，轮询 30/36 → 加权 36/36 完成，达标 0/3 → 3/3。达标须全部完成、成功尾部 p95 ≤250ms、每次尝试最大发送落后 ≤100ms；失败保留分母。8/10/12 三档合计加权 90/90 完成、九批达标，轮询 83/90 完成、三批达标。

**延长与过载证据：**[EXP-005-13](../experiments/weighted-extended.md)加权 12 并发、120 秒两批 24/24 完成且达标，合并成功尾部 p95 92.118ms；没有新增轮询长时对照。[EXP-005-14](../experiments/weighted-overload.md)加权 16 并发、20 秒三批 41/48 完成、七次积压保护失败，之后同后端六次低负载新会话完成；探测距原批次退出约 19 秒，未测即时恢复原负载。

**架构假设：**固定处理能力差异可由静态权重近似表达。逐实例快照支持分配改善的解释，但实验未采集逐会话 Worker 绑定，不能把某次失败归因给某实例或证明最优权重。

**当前约束与代价：**实验为同机有限 Mock 批次，三轮顺序不完全平衡，未做主机隔离或统计显著性证明。13–15 并发未测，12 不是已确定上限。成功样本群体不同，尾部变化不写成配对延迟降低比例；尾部也不代表逐块转录延迟。既有会话绑定使新权重无法迁移存量负载。

## 重新评估条件

观察到运行中处理能力变化、长短会话混合失衡或后端失效后，分别定义健康摘除、选择失败、占位归还及重试语义，再评估动态策略。第六阶段如需 Worker 切换，必须先解决识别状态与音频重放；真实模型、持续到达和长时容量需重新验证，不能套用本轮参考点。

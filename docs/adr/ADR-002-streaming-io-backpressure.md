# ADR-002: 上行 I/O 解耦与有界积压

Status: Accepted
Date: 2026-09-10
Related: [EXP-001](../experiments/EXP-001-send-stall-disconnect.md), [EXP-002](../experiments/EXP-002-slow-websocket-write.md)

## Problem

当前上行串行执行 WebSocket Read 和 Worker Send。EXP-001 复现了 Send 停滞期间客户端断开无法及时引起取消与清理的问题。

下行串行执行 Worker Recv 和 WebSocket Write。EXP-002 中，写入阻塞没有阻止客户端关闭或显式 Abort 引起的清理，但阻止了下一次 Recv 读取已就绪的 Worker 错误。

实时会话需要容忍短暂波动，并在持续积压或客户端持续无法接收结果时明确失败、释放资源。

## Requirements

- 音频转发阶段，客户端读取不等待 Worker Send 或队列空位。
- 单会话音频缓冲有界，正常路径保持 FIFO，不静默丢弃音频。
- 允许客户端短暂慢读；单次结果写入超过配置期限时结束会话。
- 正常 End 后发送完已入队音频，再关闭 RPC 请求方向，并转发尾部结果。
- 异常路径取消剩余工作；全部会话执行流和连接清理完成后才注销。

## Options

| 方案 | 收益 | 代价与限制 |
| --- | --- | --- |
| A：保留串行上行，增加 Send 停滞期限 | 改动少，限制发送等待 | 客户端读取仍依赖 Send 返回或超时 |
| B：拆分上行，增加有界音频队列；下行增加写入期限 | 上行独立读取；限制积压和持续写入等待，协调范围较小 | 队列满或写入超时会结束会话；下行仍不能在写入期间继续 Recv |
| C：同时拆分上下行，增加音频和结果队列 | 在结果队列有空间时，可独立接收 Worker 结果 | 增加结果积压、满队列策略和排空协调；队列满后仍需退出策略 |

## Decision

选择 B：WebSocket Reader → 有界音频 FIFO → Worker Sender；下行维持 Recv → 带期限的 Write。Session 协调者负责异常处理和收尾。

- 音频队列同时限制字节数和条目数。Reader 非阻塞入队；超过任一上限时立即将会话判定为过载失败，取消 RPC 并尝试以 WebSocket 1013 通知客户端，不等待空位、不覆盖旧音频。
- Reader 收到合法 End 后关闭队列输入，继续监测客户端断开和非法后续消息。Sender 消费完队列后执行 CloseSend。
- 每次结果写入使用独立的超时范围。写入超时触发会话失败、RPC 取消及剩余 I/O 清理。
- 异常结束可以存在未处理音频或未送达结果，必须按失败处理，不报告正常完成。本次决策不提供持久化或断线续传保证。

目前允许通过写入超时终止持续慢读会话，未要求在此期间持续接收和保留 Worker 结果，因此暂不承担 C 的结果队列与排空协调成本。容量与期限可配置，通过后续实验调优。

## Invariants

- Reader 独占 WebSocket 读取和音频入队；Sender 独占 Send 与 CloseSend；下行独占结果写入。
- 队列字节数、条目数不超过配置上限；单条消息继续受消息大小限制。内存核算另计正在读取、发送的数据及协议缓冲。
- 正常完成必须同时满足：合法 End、音频发送与请求半关闭完成、Worker 正常 EOF、结果转发完成。仅收到 End 不代表已发送完音频。
- 取消能解除队列等待和 I/O 等待；持有队列或会话控制锁时不做网络 I/O，也不等待其他执行流。
- Sender 停止发送不代表 Worker 成功完成；RPC 最终接收状态由 Recv 判断。

## Trade-offs

得到上行独立推进、明确的音频积压上界与持续慢读退出行为；代价是新增 Sender、队列计量和结束协调，且过载或超过写入期限的会话会失败。

队列只吸收有限波动，不增加 Worker 吞吐量。写入期限不能保证立即读取 Worker 错误，也不解决所有 Worker 停滞、建流等待或静默断网问题。

## Validation

EXP-001/002 已记录基线与本方案的对照结果：上行 Send 停滞时断开能够触发取消与注销；满队列明确失败；持续写入停滞由写入期限触发退出。下行仍未在阻塞写入期间读取 Worker 错误。

回归测试覆盖 FIFO、容量计量、End 后排空、空输入、Send/CloseSend 错误、提前 EOF、正常 final、每条结果独立计时，以及取消与收尾；全量 race 和 vet 通过。

[EXP-003](../experiments/EXP-003-streaming-load.md) 补充了持续音频、多会话、短暂抖动与持续慢 Worker 的局部负载验证。结果支持队列上界和过载退出语义，也说明应用队列上界不能约束 gRPC 缓冲及 Worker 处理带来的总延迟。

[EXP-005](../experiments/EXP-005-tcp-slow-client-cleanup.md) 在 ADR-003 实现后补充真实 loopback TCP 慢读：默认 2 秒写入期限能退出，短暂停读后恢复能正常完成；扩大写入期限时，其他失败的关闭握手仍可能延迟资源释放。临床量级会话时长、共享计算资源瓶颈和默认参数选择仍需验证。

实验观察窗不等同于业务 SLO，局部故障实验不作为并发容量结论。

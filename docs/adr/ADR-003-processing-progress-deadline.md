# ADR-003: 处理进度监测与 End 完成期限

Status: Accepted
Date: 2026-09-11
Related: [ADR-002](ADR-002-streaming-io-backpressure.md), [EXP-004](../experiments/EXP-004-processing-progress-deadline.md)

## Problem

EXP-004 中，队列和 Send 的局部等待未达到期限时，已接纳音频仍可能长期未被处理。仅发一块音频后 Worker 停滞，局部期限甚至没有等待对象。另一个独立问题是 Worker 已确认全部音频，却不返回 EOF。

## Requirements

- 最早未确认处理音频从 Gateway 成功接纳起等待达到 3 秒时，按失败取消本次识别。
- Gateway 收到合法 End 后，完成等待预算为 5 秒；不能因持续有进度而无限延长。
- 容忍 500 ms 短暂停顿；静音也能报告处理进度，不能用文字输出间隔判断处理停滞。
- 保留有界音频队列、结果写入期限与原有清理顺序；失败不保证未完成尾部自动补全，不静默丢弃后报告成功。
- 正常转录可见延迟 P95 目标 1 秒；处理进度期限不是该指标的替代，真实出字仍需模型接入验证。

## Options

| 方案 | 收益 | 限制 |
| --- | --- | --- |
| 仅调整队列容量及队列/Send 期限 | 协议不变，限制局部等待 | 覆盖不了音频已出队且 Send 已返回的停滞 |
| 按结果间隔退出 | 容易计时 | 静音和分句可能无文字；持续返回旧结果也不表示追赶成功 |
| 连续处理进度＋独立 End 期限 | 覆盖传输与 Worker 内的未确认音频，以及尾部完成等待 | 需要协议支持、有限进度记录和期限协调 |

## Decision

选择连续处理进度监测与独立 End 期限。沿用 Reader → 有界 FIFO → Sender 和串行下行，期限由已有 Session 协调者管理，不为每个音频块创建计时器或 goroutine。

- 请求增加从 1 开始的连续 `audio_seq`。Worker 通过独立的 `ProcessingProgress` 消息确认 `processed_through_seq`，表示此前所有音频均已处理，包含静音；允许累计确认与相同值重复，不允许倒退或确认尚未开始发送的音频。进度消息不转发为文字结果。
- 保留现有结果字段，进度与结果不得混装。新增字段在 protobuf 线格式上可扩展，但处理确认是新的必需语义；Gateway 和 Worker 配套升级，不把旧 Worker 的缺失确认当成功，不承诺混合版本兼容。
- 每块成功入队时记录到达时间，确认后释放记录。跟踪范围包含应用队列、正在发送和下游尚未确认的音频。固定容量记录表默认最多 4096 块；容量耗尽同样明确过载，避免大量小块导致元数据无界增长。这个上限是资源初值，不是稳定容量结论。
- `ProcessingTimeout` 默认 3 秒，`EndTimeout` 默认 5 秒，均独立于问诊总时长。零值采用默认值，负值拒绝；新增 `MaxUnprocessedChunks` 的零值默认 4096，负值拒绝。
- 协调者等待最近的截止时刻，入队、进度和 End 唤醒其重新计算。已到期的失败不可被迟到确认或重复 End 清除。正常完成同时要求原有发送/半关闭与 Worker EOF 条件，以及所有已接纳音频均获确认。
- 处理等待超时使用 WebSocket 1013 / `processing_timeout`；End 完成超时使用 1011 / `end_timeout`；进度记录满使用 1013 / `progress_capacity`；非法进度、缺失尾部确认按 Worker 失败 1011。先取消 RPC，再尽力发送关闭原因并清理。客户端只有观察到正常完成才可把整个转录标记为完整，已有分段 final 不代表整个会话成功。

## Invariants

- 单会话请求序号连续；确认水位不倒退且不超出开始发送的水位。开始发送标记在调用 Send 前建立，以容忍确认先于 Send 返回。
- 未确认记录数量不超过配置上限；到达时间使用同进程单调时钟，不比较客户端与服务端墙钟。
- 锁内不执行网络 I/O、不取消或等待执行流；队列锁可获取进度锁，反向获取禁止。
- 没有新输入或结果时，已存在的期限仍能触发。已无未确认音频时不启动音频期限；合法 End 仍有独立期限。
- 取消与正常完成竞争时由协调者作最终判断，期限在确认推进及成功判定前复核；清理完成后才能注销。

## Trade-offs

处理确认的批量间隔和返回延迟计入等待预算，确认延迟可能引起保守退出；真实 Worker 必须保证处理进度语义。固定记录表每槽保存一个单调时间偏移，默认时间数组约 32 KiB/会话，另计结构与原有音频队列。较早终止限制积压，但仍可能留下转录缺口。

期限是超时判定预算，不是所有网络条件下的资源释放硬上界。保持原有下行结构，写入期间不会继续 Recv；原结果写入期限仍负责慢写保护。本次不提供持久化、重连、重放或独立 RecognitionAttempt 生命周期。

## Validation

EXP-004 已提供候选方案及正式实现的对照。回归测试覆盖序号与确认边界、重复/倒退/越界/混装/缺失确认、确认先于 Send 返回、有限记录容量及复用、迟到确认不可掩盖过期、无新输入触发期限、End 不延长、正常尾部和并发进度。

生产实现重跑七种工作负载各两次：8 次正常完成、6 次期限退出，无观察窗截断；处理等待约 3 秒、End 等待约 5 秒触发失败，全部清理后注册表归零。慢 Worker 的未确认尾部仍有 150–151 块。全量 race、实验构建 vet 与生产实验 race 检查通过。

[EXP-005](../experiments/EXP-005-tcp-slow-client-cleanup.md) 补充真实 TCP 慢读、RST、Abort 和恢复读取：默认写入期限可以退出；写入期限扩大到 8 秒时，处理/End 期限按时取消 RPC，但关闭通知过程使注销延迟到约第 8 秒。该结果验证了本决策所述的清理时间限制，没有提供独立异常收尾预算。

长时及共享模型负载继续作为后续验证工作。实验不证明真实出字 P95 目标或所有网络条件下的资源释放时间上界。

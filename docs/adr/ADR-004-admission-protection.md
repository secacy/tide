# ADR-004: 容量不足时立即拒绝新会话

Status: Accepted
Date: 2026-09-12
Related: [EXP-006](../experiments/EXP-006-shared-worker-capacity.md), [ADR-003](ADR-003-processing-progress-deadline.md)

## Problem

EXP-006 中，共享 Worker 处理能力不足时，已接纳会话持续落后并触发处理超时；短时全部完成也不代表能长期保持实时。问诊中途失败会留下未完成转录，事后超时不能替代接入保护。

## Requirements

- 容量不足时优先保护已接入问诊，立即拒绝新会话，暂不提供接入等待。
- 不为新请求抢占已有会话；原有处理、写入和 End 期限继续生效，保护不等于保证任意故障下成功。
- 拒绝发生在音频接纳与 Worker RPC 创建之前；资源释放后允许重新接入。

## Options

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| 接纳后依赖处理期限退出 | 容忍暂时超额，接入规则简单 | 新负载可能影响已有问诊，接纳后失败产生未完成转录 |
| 按配额立即接纳或拒绝 | 边界明确，减少新增负载对已有问诊的影响 | 配额保守时闲置能力，新问诊需要稍后重试 |
| 容量满时有限等待 | 吸收短暂接入高峰 | 长会话释放慢，需要等待期限、取消及客户端录音语义 |

## Decision

选择按容量配额立即接纳或拒绝，优先保留已接纳问诊，不增加接入等待队列。

当前单 Gateway、单 Worker 拓扑复用 `MaxSessions`：升级前原子登记，达到上限返回 HTTP 503，不升级、不创建 Worker RPC、不接纳音频。准备、运行与清理中的会话均占名额，清理完成后才归还。

先以 6 作为 EXP-006 条件下的候选实验配额，与上限 16 做后续突发接入对照；不修改生产默认容量，不将该数值推广到真实模型。多 Worker 配额、选择算法及跨 Gateway 的容量协调需另行决策，本记录不提前确定其结构。

## Invariants

- 容量检查与登记不可分割；同一名额不能被并发接入重复占用。
- 被拒绝请求不影响已有会话，不启动 Worker RPC；不建立等待名额的后台任务。
- 取消请求不等于名额已归还，必须在资源清理完成后注销。
- 停止接入状态不因名额释放而解除；服务运行时名额释放后可再接入。

## Trade-offs

通过拒绝新问诊减少接纳后失败的风险，但会增加显式拒绝；不能只用已接纳会话的 P95 评价效果。固定配额不能自动应对 Worker 降速、异构计算或其他 Gateway 争用同一 Worker；配额必须结合负载重新验证。

## Validation

EXP-007 计划在相同共享 Worker 下先启动 6 条持续会话，第 5 秒再加入 10 条，比较上限 16 与 6；覆盖正常处理及一次 500 ms 处理暂停。分别记录原有与新增会话的完成率、延迟、拒绝和超时，并核对拒绝没有创建 RPC、全部清理及名额复用。验证结果在实验完成后补充。

# ADR-008: 双端 WebSocket 心跳与会话收尾

Status: Accepted
Date: 2026-09-13
Related: [EXP-010](../experiments/EXP-010-silent-disconnect.md), [EXP-011](../experiments/EXP-011-heartbeat-interval.md)

## Problem / Requirements

没有未确认音频、尚未 End 时，处理期限无法发现静默失联。Gateway 需要取消旧 RPC、释放连接占用，客户端也需要独立发现失联，为后续有限恢复提供触发条件。正常空闲不能当作故障；处理超时、心跳失败和服务停止须保留不同原因。

## Options

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| 仅依赖业务期限或 TCP 断开 | 无周期探测开销 | EXP-010 的空闲阻断不能在五秒窗内检测 |
| 双端 Ping/Pong，2 秒周期、3 秒预算 | 所测故障约 3.8–4.8 秒检测，较早触发恢复 | 每端每连接一个执行流及周期控制帧 |
| 双端 Ping/Pong，5 秒周期、3 秒预算 | EXP-011 探测次数减少 60% | 同相位晚约三秒发现，增加待补音频 |

## Decision

采用双端独立的 WebSocket Ping/Pong，默认间隔两秒，单次写 Ping 加等待匹配 Pong 共用三秒预算，配置可覆盖；显式禁用仅用于对照或由调用方接管探测。五秒是初始检测目标，不是全网络条件下的硬保证，也不是完整清理或恢复期限。当前绝对开销较小，优先为恢复验证保留较快检测；五秒档仍可通过配置复验。

升级成功后启动，覆盖等待 Start、Worker 建流、音频传输及 End 后等待结果。每端始终由唯一业务 Reader 消费消息及控制帧，心跳不另建 Reader；Gateway 建流不能阻止 Reader 或期限协调者推进。收到 End 不停止心跳，选定最终收尾结果后才停止。

停止后续探测与取消在途 I/O 分开：正常收尾先停止调度，等待当前 Ping 在自身预算内结束，再关闭连接；不直接取消健康连接的在途 Ping。失败收尾先取消 RPC，再等待心跳退出；若在途探测也失败，直接中断连接，否则走既有关闭路径。显式 Abort 可以立即中断底层连接。额外等待最多是当前探测的剩余预算，不新建异常收尾预算。已经选定的业务失败不被后到的心跳错误替换。

活动会话心跳失败记录独立原因，取消会话并强制关闭底层连接；不依赖失联对端接收关闭原因。客户端取消发送/接收并返回失败；正常收到 1000 关闭仍由接收结果识别。它不自动重连、重放或认定整个 Worker 不健康。

## Invariants / Trade-offs

- 每端每连接最多一个在途 Ping，预算包含等待写锁；不按业务流量无限推迟探测。
- 停止入口幂等；所有创建的执行流在会话返回前 join，登记与 Worker 预留仍在清理后归还。
- 探测独立于 Worker Send；建流期间接收音频仍受既有队列、处理及 End 期限约束。
- 正常停止不取消在途 Ping；外部取消/强制关闭可以中断连接。关闭与探测并发时，不把正常 1000 关闭重新判为失联。
- 心跳失败表示此连接不能在预算内完成往返，也可能源于拥塞、读写争用或本地调度，不能确诊网络断开。

正常收尾可能增加最多一个探测剩余预算。健康且持续处理 Ping 的客户端仍可一直不发 Start；心跳不能替代 Start 专用期限。客户端当前输入接口是 `io.Reader`，调用方须保证 Read 可返回；普通 Context 无法中断任意阻塞 Reader。

## Validation

频率及静默失联依据见 EXP-010/011，原始数据保留原版本语义。[EXP-012](../experiments/EXP-012-heartbeat-lifecycle.md) 完成十五个顶层测试各十轮 race，覆盖等待 Start、慢建流、Send 停滞、健康空闲、End/final/1000、正常停用时在途 Ping、处理失败优先取消以及 Abort/停接协调；保留了业务失败后追加关闭等待的复现与修正证据。全量带实验标签的 race 与 vet 通过。生产实现的定点验证与候选性能样本区分记录，不把测试耗时当作业务延迟或恢复时间。

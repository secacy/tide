# ADR-009: 客户端安全断点与有限恢复

Status: Accepted
Date: 2026-09-13
Related: [EXP-013](../experiments/EXP-013-recovery-checkpoint.md), [ADR-005](ADR-005-worker-reservation-lifecycle.md), [ADR-008](ADR-008-websocket-heartbeat-lifecycle.md)

## Problem / Requirements

处理水位不证明结果已到客户端；按它删除音频会漏掉转录。新尝试直接追加结果会重复；安全断点不推进时正常连接也会耗尽缓存。需要在客户端进程存活的前提下尝试有限补齐，覆盖旧连接及实例失效，无法完成时明确缺口，不承诺无损或恰好一次识别。

## Options

| 方案 | 收益 | 限制 |
| --- | --- | --- |
| 只从最新音频继续 | 简单、无需重放 | 无法尝试补齐中断 |
| 保留旧 RPC 并重新绑定 | 可保留上下文 | 不能覆盖旧 Worker 状态丢失，保留资源及结果协调更复杂 |
| 新尝试重放客户端安全断点之后的音频 | 旧实例失效后仍能补齐 | 依赖 Worker 安全重启契约，受缓存、接入和追赶预算限制 |

## Decision

采用第三种方案。业务 Session 身份由客户端持有，各 RecognitionAttempt 使用不同身份和独立 RPC；Gateway 登记与名额仍按连接/实际尝试清理，不持久保留问诊状态。v1 保留单次识别；新增显式 v2 协议和可恢复 Worker RPC，不把旧 Worker 的普通 final 当作恢复能力。

可恢复 Worker 必须提供不可变结果、连续音频覆盖范围和安全重启边界，包括无文字的静音覆盖。一次 checkpoint 携带结果与覆盖区间，客户端校验后在同一所有者中保存结果、推进水位并释放音频；processed progress 继续只用于原有处理期限。首版只支持不需要额外前文音频的重启边界，需要上下文重放的模型另行适配验证。

音频位置使用全问诊的采样点偏移和半开区间，避免分块大小或墙钟变化影响定位。每个 RPC 的 audio_seq 仍独立从 1 开始。旧尝试结果忽略；同一次尝试已应用区间的重复事件不重复追加；前缀有洞、越界或混装的确认失败。

客户端采集与网络发送独立，默认保留最多十五秒 PCM，并另限条目数。首次失联、连接失败或缓存不足开启一次默认十秒恢复预算，覆盖退避、接入、重放和追赶；连续失败或切换到最新音频不重置预算。仅当新尝试的安全断点追上客户端当时已采集末尾，才结束本轮追赶；End 后还须确认尝试正常完成。这个严格的首版判定及初值需由后续负载验证，不是生产性能保证。

缓存不足时终止历史补齐并显式保留未覆盖范围。尚未 End 且预算有剩余时，允许从新尝试实际选定的音频起点 R 继续，旧安全断点 C 到 R 记录为缺口；它表示缺少可靠转录，不宣称这些音频全部丢失。R 在新尝试建立时确定，后续失败也不能使此前缺口消失。

十秒预算耗尽后停止自动重试，返回转录中断和已保留的结果，重新开始由调用方显式触发。End 后只补已有尾部，不跳到最新位置：补齐则正常结束，否则带缺口结束。一次 WebSocket 1000 仅表示尝试正常结束；整个问诊完整还要求所有音频被结果覆盖且没有缺口。

## Invariants / Trade-offs

- 客户端只管理一个活动尝试；先取消并 join 本地旧尝试，再启动新尝试。服务端旧资源可能仍在清理，新尝试继续接受 HTTP 503，不能绕过 M5 配额。
- 终止时停止采集、取消网络并 join；音频 Source 必须响应 Context。普通阻塞 io.Reader 无法被任意取消，文件适配仅适用于可及时返回的 Read。
- 有界缓存耗尽显式触发状态转换，不作为成功路径静默淘汰待补音频；结果及缺口由业务报告保留，不把 PCM 上限当成总会话内存上限。
- 不支持的 Worker、非法协议和音频输入错误不会无限重试；重试总预算不包含客户端进程重启后的恢复。
- 正常已确认前缀保留，临时结果不得冒充提交结果。首版 v2 只发布 checkpoint 中的稳定文字。

代价是额外客户端状态、协议升级、重放计算与可能的识别缺口。真实 ASR 是否能提供安全断点及在预算内追赶仍需验证；Mock 的定期断点不是模型能力证明。不提供磁盘持久化、跨 Gateway 去重账本或完整 UI。

## Validation

EXP-013 提供交付丢失、迟到/重复、缓存停滞及接入拒绝的候选证据。实现回归需覆盖真实 v2 Client/Gateway/Mock 链路、结果丢失后重放、持续故障预算、缓存不足时带缺口继续、End 后尾部成功/失败、非法检查点与旧 v1 兼容，并分别检查尝试退出、名额归还和逻辑问诊完整性。

## 记录规则

- `Accepted` 表示当前采用；验证程度在正文单独说明。未测长时稳定容量不影响“已经采用某方案”这一事实，但必须保留为证据缺口。
- 记录日期为本次正式整理日期。原始决策日期可确认时引用同期记录，不可确认时明确注明回溯；不倒填日期，不把本次方案分析写成当年的评测。
- 正文按“问题与约束、可选方案与依据、决策与契约、事实/假设/代价、重新评估条件”组织。实现细节只保留会影响协议、所有权或后续变更的部分。
- 已验证事实链接测试、验收记录或实验。源码证明当前行为，测试文件说明覆盖入口，已执行结果以对应记录为准；本次文档整理没有重新运行 Go 测试或负载实验。
- 当前约束描述已经存在的限制；架构假设描述尚需在目标环境验证的前提。演进方向需给出触发条件，不能写成已经实现的能力。
- 使用 [模板](TEMPLATE.md)新增 ADR。讨论中的方案用 Proposed；采用后改为 Accepted；被新决策替代时改为 Superseded，并双向链接，保留历史依据。对已采用方案的正式回溯可直接标 Accepted，同时注明依据性质。

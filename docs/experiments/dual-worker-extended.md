# EXP-005-10：双 Worker 两分钟观察

状态：测量前方案、配置与判据已固定，正式数据待执行。

## 目标与选点依据

短时筛查中，16/18 并发各三批达标，19 并发三批未达标。根据 EXP-005-09 的规则，本轮优先延长 18 的观察，并加入 16 作为较低负载对照，检查完整完成率、成功尾部与发送节奏能否在更长窗口持续满足判据。

两分钟是筛查窗口：比 20 秒更容易观察持续积压，也能控制实验成本。它不替代数十分钟问诊或真实 ASR 稳定容量验证。

## 方案与权衡

- 仅延长 18：约五分钟，成本低，但较难分辨本轮环境变化与高负载问题。
- 16/18 各两批：约十分钟；提供较低负载对照并保留重复性，本轮采用。
- 直接延长 19：短时已连续未达标，不能代替验证可重复达标候选；过载行为已有独立证据。
- 一次测试数十分钟：更贴近问诊时长，但在候选尚未经过延长筛查时成本较高；留待后续定义代表性长期负载。

两档按 16 → 18 → 16 → 18 固定执行，不按结果追加直到通过的复测。实例数、处理名额、缓冲、轮询和速率保持一致，仅增加总音频量、会话期限和采样窗口。

## 固定计划与判据

| 项目 | 条件 |
| --- | --- |
| 实例 / 策略 | 两个独立 Mock Worker，每实例处理名额=1、逐块 10ms、响应延迟 5ms；Gateway round robin |
| Gateway | max sessions=64、pending audio=32000 字节，其他参数沿用短时筛查 |
| 正式输入 | 每场 120 秒静音 PCM，32000 字节/秒、3200 字节/块、实时排期；3840000 字节、1200 块 |
| 正式批次 | 16/18 各两批，共 68 次正式尝试；固定次序 16、18、16、18 |
| 预热 | 两场各两秒，不进入正式分母 |
| 会话期限 | 从 35 秒调整到 140 秒，以容纳完整 120 秒输入及收尾；负载进程额外收尾 10 秒 |
| 采样 | Gateway 100ms、各 Worker 20ms，完成查询后等待间隔；查询期限 1 秒；正式窗口 150 秒、预热 10 秒 |
| 业务判据 | 全部完成且无批次错误；成功会话 nearest-rank 尾部 p95 ≤ 250ms；所有尝试有排期观测，最大落后 ≤ 100ms |
| 证据判据 | 三个来源负载前后空闲、负载窗口内无失败查询、最大覆盖间隔 ≤ 500ms；配置、身份、计数、哈希与正常收尾一致 |

期限变化只为容纳更长输入，250ms 尾部和 100ms 发送落后判据保持原值。期限、采样窗口与输入时长分别验证，不能把旧 35 秒期限或 40 秒采样窗口误用于本轮。工程筛查阈值不是临床 SLA；根清单通过表示采集有效，业务达标另看逐批判据。

失败会话保留在完成率分母和实际输入量中；没有成功尾部就保留 null。现有 Mock 仍只发四条 partial 和一条 final，不因音频延长而持续输出更多文本；本轮主要增加音频处理负载的持续时间。

## 来源、观测与实现

[run_dual_worker_extended.py](scripts/run_dual_worker_extended.py) 读取带哈希的[短时参考点](results/dual-worker-short-operating-points-2026-10-02.json)，逐一复核扫档和 19 细测的清单/分组哈希，并从临时副本重新分析原始证据。确认 16/18 三次达标、19 未连续三次达标；源文件一致且每点数字与来源吻合后，固定选择 16/18。

新清单保留参考点文档、来源分组和哈希。构建与网络请求前核对同一 Go/Proto/模块实现；分析时再次复核选点。复用共享编排、每实例采样、异常保留和进程回收，Go 业务代码未修改。

五秒分段覆盖全部 120 秒，包括后半程，不用失败后的空闲替代持续承载。逐 Worker 计数异步，分别报告峰值；等待计数不等于排队时延，忙碌样本比例不等于时间利用率。没有逐音频块处理确认、CPU 或总内存观测，解释保留这些限制。

新增 [七个测试方法](scripts/test_dual_worker_extended.py)：固定 120 秒配置、拒绝短期限/窗口、缺批和缺 Worker、参考点数字和文件篡改、完整后半程分段、历史复算兼容；共 65 个分析测试通过。

使用 `caffeinate -i` 仅在本次命令期间阻止自动空闲休眠；覆盖判据决定采集是否有效。失效/中断尝试单独保留，完整复测采用新目录，不拼接好批次。

## 完成后的解读规则

- 四批均达标：16/18 通过两次两分钟筛查，保留它们作为后续 Mock 对照运行点。
- 16 达标、18 未全部达标：报告高负载点在延长窗口中出现的问题，18 不作为已通过延长筛查的参考点。
- 两档都有未达标：记录逐项原因和环境，不能简单归因于某个 Worker 瓶颈。
- 有采集不合格：独立保存，不能用于容量结论；完整复测而非拼接好批次。

成功尾部必须与失败数一起展示。短时达标、两分钟达标和生产稳定容量是不同证据层级；本轮结论只适用于固定 Mock、同主机和当前输入。

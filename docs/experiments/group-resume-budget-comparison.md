# EXP-006-03：共享 Gateway 的恢复尝试次数对照

Date: 2026-10-11
Status: 正式四条件各三批与独立/归档复核完成；96 场保留 68 完成、28 明确失败，无未知。
Related: [设计与方案权衡](../worklog/2026-10-11-group-resume-budget-design.md)、[EXP-006-02](group-resume-baseline.md)、[Milestones](../MILESTONES.md)。

## Goal / Questions

在八场共享原 Gateway、原 Worker RPC 的条件下，只改变客户端 MaxAttempts（5 → 8），比较真实握手占位后的恢复完整性与成本。重新运行同版本五次对照，历史基线只提供问题背景。

1. 入口占位 2s 时，多三次机会是否能等到开放，并完整完成原场？
2. 占位 500ms、开放后仍竞争时，增加次数是否改变完整完成率？
3. 获得多少完成场，同时增加多少实际请求、拒绝和等待？
4. 失败返回是否变晚，原 RPC 和整批资源是否更早自然释放？

本轮不寻找最优次数，不改变退避算法或生产默认值，不用于推断真实 ASR、生产容量或长时多次故障的恢复 SLO。

## Hypothesis / 预算语义

五次预算在快速拒绝时理论尝试约为 0、0.1、0.3、0.7、1.5s，可能早于 2s 开放耗尽。八次额外机会约在 2.5、3.5、4.5s，可能接回并承受开放后的竞争，但仍可能全部失败或先触及 5s 窗口。

以上相对第一次恢复尝试、忽略 I/O 与清理耗时，不是相对代理 T0 的精确排期。窗口包含清理、退避和握手；次数是整场 Run 累计 resume Dial，首次 start 不计，成功不清零。本轮每场全新 Run、一次统一断线；成功 ready 清除该轮时间截止点，不重置次数。

## Setup / 固定条件

### 共享链路、输入与故障

- 每批一个公开 v2 Gateway、一个 TCP gRPC 位置 Worker、一个故障代理，八个独立 V2Client Run；共享 gate、tracker、registry 和 Worker 连接。独立流每块处理 10ms，不另设跨流计算名额。
- 每场 PCM 16kHz/单声道/16bit，60 块 × 3200 字节 = 192000 字节，固定 100ms 采集节奏；位置/实验编号确定输入，八场不同，逐字验证。处理每块产生一条位置结果，EOF 后一条尾部结果，完整场应用 61 个连续序号。
- 顺序启动：每场 ready 转发且首次 Read 被观察到后再启动下一场，不人为阻塞首次 Read。八场首读跨度上限 50ms。
- 在每场初始连接第 20 块 `[60800,64000)` 建立屏障，前 19 块正常转发；最多暂扣一块。全员到达且八条原 RPC 活跃后，两条真实升级、未发首消息的连接占满握手名额。
- 在共同故障时刻 T0 并发切断八条原连接的前后端，丢弃暂扣块，源继续采集。切断完成跨度上限 50ms；初始建立不完整时不伪造完整群体故障。
- 每次恢复立即经过同一个 Gateway；真实 HTTP 503 / handshake_limit 及转发事实分别记录。占位连接在 T0+500ms 或 T0+2s 关闭，handler 返回且名额归还后记录实际释放时刻。
- 各批重新创建夹具；整批自然空闲后才进入下一批。故障是断线加入口占位，不是 TCP 丢包、网络黑洞或实例崩溃。

### 除次数之外保持一致

| 范围 | 固定值 |

## Metrics / 比较口径

| 指标 | 口径与输出 |
| --- | --- |
| 主指标：完整完成率 | 核实 completed、逐字完整音频、连续完整结果及完成确认写出；每条件完整场 / 24，逐批完整场 / 8。失败、未知分别列出；分母始终包含全部计划场 |
| 完成差 | 每个场景八次减五次的完成数及完成率差（百分点）；同时列三轮相邻批次差，不用历史基线当作本轮对照 |
| 实际请求成本 | 每场/每批 resume Dial、代理到达、解析 resume、后端请求四层数量和拒绝码；按计划场均值及相邻对差展示，不假设四层总相等 |
| 请求聚集 | 从 T0 至整批 Run 返回，以固定 50ms 桶记录首波（connection=2）、后续重试、实际拒绝及空桶；不把同桶等同精确同时，也不把入口到达当接纳 |
| 恢复与新音频 | T0→ready、实际全部占位释放→ready；T0 后/释放后首次开始 Read 的块被结果覆盖并成功应用的等待，分别列样本数与 null |
| 转录与失败等待 | 完整场最大相邻 partial 间隔、实际采集/计划采集到应用的等待；全部场 T0→Run 返回、错误类别、尝试数和外层到期事实。失败场的断线前 partial 不代表已恢复 |
| 音频代价/缺口 | 代理重复音频负载；计划、采集、Worker 接收与处理范围；已采集未接收、已采集未处理、尚未采集分别列出，不能当作 TCP 丢包量 |
| 原流保留 | 每条原 RPC 的 T0→worker.exited_at，以及该 RPC 退出减其客户端返回的非负等待；每批八条故障后保留时长之和（RPC·秒），不是 CPU 时间或逻辑会话退出时刻 |
| 整批清理 | T0→整批自然空闲、最后一个 Run 返回→整批自然空闲；另列强制清理/未观察到。旧逐场 remote_idle_after_return 使用整批空闲，不能当作该场释放时间 |
| 资源与证据质量 | 会话、注册、原流、握手/代理任务、整进程 goroutine/heap 采样及最大间隔；首读/切断跨度、采集落后、采样调用耗时。采样峰值不是严格上界或单会话内存 |

保存逐场与逐批结果，按条件汇总 min/median/max，附有效样本数和失败/未知数；中位数从原始场样本合并重算，不平均批次中位数。三批小样本不报告可靠 p99 或统计显著性；两种预算成功者可能不同，不称为逐会话配对延迟收益。

失败终止依据结合实际次数、错误链和时刻说明；仅凭 recovery_exhausted 不能断言是次数还是窗口，代理 T0 也不是客户端内部窗口起点。无法明确区分时标记未知，不凭理论排期补造事实。未恢复、未退出等未测事件用 null，不能填零。

## Acceptance / 证据与结论

1. **配置与分母可复核。**新实验身份、12 批顺序、96 个计划场、实际两种次数和其余固定条件都独立核对；缺批、重复、条件漂移及源码变动不能静默通过。
2. **正确性不折抵。**全体原 RPC 归属不变，不回退 start、不串场；完整场音频与结果逐项核实，源关闭一次。业务失败保留，错误分类与事实一致。
3. **故障与自然清理有证据。**两条真实占位连接、八场故障覆盖及实际释放均核对；50ms 同步判据沿用。不能把最终取消后的零计数作为自然归零。
4. **工具合格不要求八次更好。**不预设必须 24/24 或必须提升多少；若更多尝试无改善、拒绝增多或等待变长，按实测报告，不增加次数重测来改结论。
5. **数据质量与业务结果分开。**原始报告/错误全部保留；配置、同步或证据校验失败的场仍占计划分母，不能冒充明确业务失败或从分母删除。存在未知时不给出无条件的确定完成率差，只列已核实完成/计划、未知数与可能范围。采样缺口限制资源时序结论，不以事件正确自动证明连续资源状态。

结论模板仅在测量后填数：

> 在固定八场共享入口、___ 占位条件下，五次完成 ___/24，八次完成 ___/24，相差 ___ 个百分点；实际恢复请求 ___→___，失败 ___→___，未知 ___/___。成功场新音频等待及原 RPC 保留成本分别为 ___。该结论只覆盖本轮条件。

若增加次数支持等待开放，再独立设计 jitter 来比较请求分散；若仍失败，先从实际到达、拒绝、窗口和保留事实解释，不同时修改窗口/间隔/入口名额。

## 正式结果（2026-10-11）

实测提交 `a7358df`，2026-10-11 15:21:31–15:23:15（UTC+8）。Go 1.26.5、macOS 26.6.2、M2 Pro / 12 CPU / 32GiB、GOMAXPROCS=12；一次非 race 构建、同进程 loopback、八场共享入口、每块 10ms 位置 Worker、六秒输入、一次统一故障，条件和三轮交替顺序保持预登记不变。

**2s 组支持增加机会的效果。** 五次全部在 T0 后 1516.81–1540.02ms 用完，早于约 2s 的实际开放。八次组 15 场用六次、8 场用七次、1 场用八次，全部接回原场并完整完成；三对均为 0/8→8/8。固定条件下完成率增加 100 个百分点，实际恢复请求增加 34 次 / 28.3%，平均每计划场多 1.42 次：24 次成功接回、十次额外拒绝。请求上限增加不等于实际流量同幅增加。

**500ms 组只记录差异，不归因于额外次数。** 观察完成率 83.3%→100%、差 16.7 个百分点，但八次组的全部 24 场仅用第 4/5 次就成功，没有使用任何额外机会。入口竞争的实际事件不同，不能据本轮样本断言增加上限挽救四场或减少流量；109→105 的请求差也不作优化收益。五次四个失败场在释放后的约 710–712ms / 1515ms 仍收到拒绝，全部保留。历史 EXP-006-02 的 22/24 不替代本轮 20/24 对照。

全轮 488 次实际 resume Dial / 代理到达 / 解析 resume / 后端请求本次相同，四层仍分别记录。96 场各一次 start/Pick/原 RPC，没有回退新建或串场。68 个完整场各 192000 字节逐字完整、61 条连续结果、完成确认写出；28 场 recovery_exhausted、最近入口码 handshake_limit，没有外层到期。

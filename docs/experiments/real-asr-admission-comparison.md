# 真实 Worker 本地占用准入与有限并发对照

日期：2026-10-26。状态：实验计划执行完成，见[真实对照结果](../worklog/2026-10-27-real-asr-admission-results.md)。下文保留运行前条件与判据；本地占用池与 Gateway 已先通过[集成验收](../worklog/2026-10-27-gateway-worker-lease-validation.md)。依据[设计评审](../worklog/2026-10-26-real-asr-admission-design.md)。执行前仍需冻结最终源码、程序、输入摘要及环境，不沿用上轮证据冒充本轮结果。

## Goal

在两个独立单名额 Worker、一个活动 Gateway 和固定短输入下，验证本地占用准入是否能利用错峰结束后空闲的 Worker，以及超额请求是否在正确层次失败。分别核对本地名额归还与远端模型实际释放，不推断最大吞吐或长期稳定容量。

## Questions

1. 一场长输入仍在 A 运行、B 已结束短输入时，新短会话是否被分配给 B？
2. 相同到达条件下，旧轮询与本地占用轮询的新会话完成情况有何差异？失败是否确由选中忙实例造成？
3. 两场已接纳时，第三场是否得到 session_limit，且没有额外 Worker RPC 或模型创建？
4. 各场/各批结束后，本地占用、Gateway 活跃会话和各 Worker 的实际创建/释放是否对应？

## 方案与固定边界

- 一个驱动进程，两个独立原生 Worker 进程，独立地址与稳定实例标签；当前旧 bilingual/int8 模型、固定 SDK、greedy、每 Worker 两线程、每 Worker 一个实际模型名额。每场重新加载。
- 对照组：当前 RoundRobin；实验组：CapacityRoundRobin，各条目本地上限 1。两个策略均使用同一套 Gateway 逻辑与显式配置；旧策略经无容量适配器保留原选择顺序。
- `MaxSessions=2`；`MaxPendingAudioBytes=0`；`MaxMessageBytes=3208`，与 3200B PCM 加 8 字节头一致。其余明确冻结为现有值：音频 1MiB/256 块、未确认结果 1MiB/256 条；发送/结果写/Worker status 各 2s，tail 15s，输入进展 30s，恢复窗口 10s，结果保留 30s，入口与 start 各 10s，握手名额 64。
- Worker 输入上限 960000B、单块 3200B、单快照 4096B。这里只收紧实验入口的消息大小，不更改全项目默认值；应用缓冲总预算不等于进程 RSS 上限。
- 客户端实时发送、无自动恢复；长输入 L 使用原模型公开 `test_wavs/0.wav`（321700B，约十秒），短输入 S/N 使用 `test_wavs/1.wav`（163200B，约五秒）。冻结两份 PCM SHA；不引用转录准确率作完成判据。
- 暖机：两个 Worker 各一场固定正常输入，单独记账。Worker 进程随后跨臂复用；每臂重建干净 Gateway 与策略实例，RPC/连接按明确所有权管理。臂间等到 Gateway、本地名额及远端释放均完成后固定空闲两秒；不得为了清空 RSS 重启 Worker。

## 工作负载与分母

### A. 错峰分配对照

三个配对批次，预登记顺序为“旧→新、新→旧、旧→新”，保持输入和触发条件一致。每臂三次新建：L、S、N；每种策略共九次尝试，其中真正观察“空闲 Worker 被利用”的 N 各三次。L/S 的六次结果单列，不能只展示 N 成功而隐去原场失败。

每臂执行顺序：

1. 启动 L，观察其一次 Worker 选择，再启动 S；记下实际归属，不能根据客户端 goroutine 启动顺序猜 Worker 身份。
2. 等待 S 正常 completed/ACK、本地清理和对应原生释放；同时确认 L 仍在运行。
3. 在这个条件下发起 N，记录选中的 Worker、RPC/模型是否实际创建、首次文字、完成或失败及其时间。
4. 等到原 L/S 与 N 都结束并完成清理，才结束本臂。

旧策略预计可能将 N 选回 L 所在实例；新策略应跳过被本地占用的条目。这是待验证预期，当前不填写改善百分比。若 S 清理时 L 已结束、目标重叠条件不成立，则记录为触发窗口未满足，保留全部槽位和原因，不补场或悄悄排除后宣称达标。

真实“Worker 忙”需结合有效输入、所选实例、gRPC 终态及模型创建记录判定；不能把所有 ResourceExhausted 都算为忙，也不能把 WebSocket ready 当作 Worker 已准入。正常 N 必须满足输入字节/SHA、结果序列与快照替换、一次 final、completed/ACK 及清理判据。

### B. 总准入过载验证

使用新分配器，三个批次。每批启动两场原示例 0 输入，观察两实例均已创建模型且两场尚在运行，再启动第三场。

每批两个已接纳场应正常完成；第三场应在 Gateway 总准入处返回 `session_limit`，没有新的 Worker RPC、模型创建或自动重试。分母分别为六场正常输入和三次入口拒绝。拒绝时长从第三场客户端 Run 起点记录；使用现有客户端握手总预算作为失败上限，不预先声称毫秒级 SLA。

本地池无空额而 Gateway 仍有总名额的错误层次，由可控集成测试另行覆盖（Gateway 上限大于池总名额）；不把两种拒绝混成同一指标。

### C. 确定性失败路径

正式真实模型测量前，使用可控 Engine/流和事件屏障验证：发送阻塞时音频预算仍包括在途块、无 AudioProgress 时仍有本地存储保护；池满不建 RPC；入口失败不泄漏名额；恢复保留同一名额；取消期间原生 Close 被阻塞时，网关可能先归还本地名额，后续请求被远端拒绝，且不能误报 completed。

这些是正确性测试，不算真实模型延迟、忙碌率或容量数据。不对真实模型凭空宣称触发了发送超时、音频预算或原生卡住。

## 工具复用与观测

复用已有 Worker 进程启动、输入检查、快照观察、源码冻结与证据复核方法。上一轮 `runGatewayCase` 以“单场后 Gateway 总活跃数为零”为前提，不能直接并发调用；需要按场关联选择/Lease、RPC trace、模型实例事件和客户端回调，仅在批次边界要求全局归零。

每场保存客户端标签、Worker 标签、RPC 尝试序号及必要的模型 ID 对应关系。忙拒绝可能没有模型创建，不能强行按 RPC 数等同模型数。日志不保存 ready 恢复凭据；不会增加业务协议字段来服务实验。

Gateway 快照、每 Worker 本地占用和各独立 PID 的资源可按 500ms 采样，检查超过三秒缺口和不可用项；生命周期因果顺序以原始事件为主，不靠轮询恰好采到瞬时峰值。原始 trace 逐场归档、任务退出后释放，不因保留全文制造资源增长。最终工具的指标接口和边界需随集成落实，再冻结执行。

## Result 写作规则

- 主结果：两策略 N 的完成数/三次机会，L/S 的完成数/六次原场；展示全部九次尝试及失败类别。
- 拒绝结果：第三场正确拒绝数/三次尝试、额外 RPC/模型数，以及六个原场是否受影响。
- 资源结果：各条目占用不越配置上限，模型创建/关闭对应；取消的本地释放与远端释放分开。
- 时间结果：逐场加载、首字、尾部、拒绝等待；当前负载有两场/三场错峰，不能直接与上轮单场数据相减声称纯调度开销。
- 保留重叠条件未满足、失败、未执行和采样质量问题，不以复跑补齐成功分母。小样本只报告逐场值和范围，不推 p99。

只有完成上述实际测量后，才填写路由改善或有限并发的成果数字。本轮仍不改变“一个名额是配置值”“模型处理前缀未知”“最长输入三十秒”的边界。


## 2026-10-27：执行前工具细节冻结

驱动与独立复核器位于 [asradmission](../../experiments/asradmission/README.md)。29 次尝试和十个实验臂在运行前登记；每臂 45 秒总预算，批末自然清理五秒，臂间固定空闲两秒。暖机每 Worker 一次示例 0 正常输入。第三场超额探测使用短示例 1，不改变两个已接纳长输入的条件。

按场保存选择/RPC 事件、客户端返回和应用回调；每臂明确保存触发时 Gateway 快照、各进程累计模型计数及清理结果。独立进程观察不是原子事务，触发重叠还需核对原场运行与模型事件证据。每批清理后一次性检查两本地名额均可取得，不在运行中调用 TryAcquire 探测，也不因此宣称采集了精确的在途占用曲线。两个真实 PID 的 RSS、Gateway 活跃数、驱动 Go 堆/goroutine 仍连续采样；不可用和超过三秒缺口保留。

已有后台日志读取器只为此次显式实验把每 Worker 生命周期事件上限设置为 64，旧十一场基线仍为 22；不改变模型、协议和产品容量。正常/忙拒绝/入口拒绝分开复核。源码及资源身份在正式识别前冻结，首次失败与修订不覆盖旧目录。

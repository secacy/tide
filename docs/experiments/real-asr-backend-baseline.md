# 真实 Worker 连续会话运行基线

日期：2026-10-26。范围：[设计记录](../worklog/2026-10-26-real-asr-backend-baseline-design.md)。目标为真实计算后端下的逐场等待、自然清理和重复运行资源变化；不验证识别准确率、长问诊或稳定并发容量。

## 冻结条件与判据

- macOS arm64；当前 bilingual/int8 Worker，固定 SDK v1.13.8、greedy、CPU 两线程，每场重新加载。Worker 独立进程，Gateway 与 V2Client 位于驱动进程；单名额，不启用未知处理进度预算。
- 原模型公开示例 `test_wavs/0.wav`，PCM 321700B、10.053125 秒，SHA256 `237ee4752b8a1fb41c6284ae94f2d7baf9a1fc8f28c26d3409c69e86cecbade1`；实时 3200B/100ms，不重采样或拼接素材。
- 一场正常预热，清理后空闲五秒；五轮“首条非空 partial 后取消 → 正常完成”，每场自然清理后空闲两秒；末场之后另空闲五秒。取消保留默认十秒恢复窗口，正常/取消清理观察预算分别为五/十五秒。固定全部十一槽位，不补场。
- 正常场要求音频字节/SHA、快照顺序、一次 final、completed 与 ACK 一致；取消场按预期取消、没有伪造完成、保留后自然退出；每场要求一个原生创建/释放对及 Gateway 活跃数归零。清理失败即停止，后续槽位未执行。
- 500ms 连续采样 Worker RSS、驱动 Go 堆/goroutine 与 Gateway 活跃数；间隔超过三秒、RSS 不可用等另列为数据质量问题。模型事件使用驱动观察时刻，避免跨进程时钟相减。正常与取消分母各五，预热单列，不合并多次运行。
- 正式采集不强制 GC，不重启进程清空内存。报告逐场值、范围与空闲曲线，不用五场推 p99 或长期无泄漏；RSS 最大采样值不是精确峰值。

执行前由 `prepare.py` 冻结源码/依赖、输入、模型及 Worker 二进制摘要；执行后用冻结脚本独立复核。命令与工具说明见 [asrbackend](../../experiments/asrbackend/README.md)。

## 首次工具验证与复测理由

首轮原始目录为 `/private/tmp/tide-backend-baseline-2026-10-26-1`，五轮及预热完整退出，冻结复核通过。期间发现准备阶段计算资产摘要使用 `os.ReadFile`，整份模型临时进入驱动 Go 堆，影响其初始资源参考；预热后空闲堆约 209MiB，后续自然 GC 后回落。该值不能归因于 Gateway，首轮保留，不删改原采样。

工具修订仅将文件摘要改为流式读取，避免整份权重进入驱动堆；不更改模型、音频、会话数量、恢复窗口或判据。复测使用新目录、全新完整运行，不把首轮与复测合并成十轮，也不以驱动堆变小宣传网关优化。首轮 Worker RSS 的增长仍保留并在结果中讨论，不能被工具修订掩盖。

本计划在复测启动前固定；最终数据与能力边界另记 worklog。

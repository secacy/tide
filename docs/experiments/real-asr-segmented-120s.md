# 真实 ASR 固定分段：120 秒链路验证

日期：2026-10-27。前置实现 `4e9acdc`。状态：已按本计划完成一次正式运行，见[结果与限制](../worklog/2026-10-27-segmented-120s-results.md)。冻结源码中的本文件保留运行前的预登记版本；以下条件与判据未改。目标是在固定本机条件下验证一次 120 秒输入的四段连续处理、完成与清理；不测稳定并发容量或识别准确率。

## 条件及顺序

- 原始中英 Zipformer int8，sherpa-onnx-go-macos v1.13.8，CPU 两线程、greedy；一个非 race 独立 Worker，一个与非 race 驱动同进程的生产 Gateway，一个 v2 客户端。运行前冻结源码、计划、模型/输入/二进制和动态库摘要。
- Worker 整场上限 3840000B、每段 960000B、每块 3200B、快照 4096B；显式开启片段观察日志。观察器只对该模式记录成功流创建/同步释放返回、调用耗时及成功提交的 float32 样本摘要；不提供模型处理确认，不保证捕获 C 内部未暴露的分配失败。
- Gateway MaxSessions=1，本地容量池限制 1；MaxMessageBytes=3208，MaxPendingAudioBytes=0。V2 音频/结果存储各 1MiB、256 条，输入空闲 30s、恢复窗口 10s、结果保留 30s、Worker 终态等待 2s；发送/结果写入 2s、尾部 15s，其余现有默认配置固定。
- 客户端 3200B、按现有采集时间轴实时输入；不启用重连，10s PCM 重放预算、128 块，完成期限 30s。唯一结果回调只保留当前片段，完整消息按序落盘，final 后清空当前文本；驱动的 RPC 观察 trace 仍持有该场有限结果，采样堆含这些工具开销。
- 素材为模型包 test_wavs/0.wav 的原始 321700B PCM，SHA256 `237ee4752b8a1fb41c6284ae94f2d7baf9a1fc8f28c26d3409c69e86cecbade1`。正式输入循环拼接后截取前 3840000B（120s）；拼接点保持样本对齐，语句自然性和质量不作判据。
- 同进程顺序执行：原素材预热一场 → 空闲 5s → 正式 120s 一场 → 空闲 10s → 素材前 96000B 三秒新场 → 空闲 5s。预热/正式/新场分母分开；不重启 Worker、不强制 GC、不自动补场。预计总时长约 155s。
- 各场 Run 固定 150s 总预算；正常清理观察 5s。失败仍写回该场证据并停止，不挑选通过场替换。批后检查本地容量可复用，运行中不调用 TryAcquire 探测，避免观测改变调度状态。
- 500ms 采样 Worker RSS、驱动 heap/goroutine、Gateway 活动数、模型创建/关闭；同时记录单调时间与墙钟，任一采样间隔超过 3s 或 RSS 缺失，将时间/资源证据标为不合格，仍保留完整性结果。完整采样至少覆盖正式场及两侧空闲。

## 指标及判据

1. **传输/模型提交守恒**：正式场 gRPC Send 累计 3840000B，摘要与冻结源一致；四段各提交 480000 个 float32 原始样本，分段 little-endian float32 摘要与独立源转换一致，不包含 padding。成功 Accept 计数仍不表示解码处理确认。
2. **结果及终态**：正式场只有片段 1/2/3/4，各一次 final；同段完整快照替换，final 后无修订；RPC 观察和回调消息逐项相等，Seq 连续；正常 EOF、completed、completed_ack、最终 offset 和应用序号一致。不设置 CER 门槛。
3. **生命周期**：正式场一次分配、一次 RPC、一次模型成功创建/实际 Close；四次成功流创建与四次同步释放返回，无重叠活动流。三场合计三个模型、六个流，正式结果独立统计。自然清理观察内 Gateway 回到零、本地名额可复用；后续三秒新场完整完成。
4. **时间**：记录每段 final 的客户端收取时刻减该段最后一块源 Read 完成时刻、以及减相应 gRPC Send 返回时刻；两者包含不同环节，不叫逐词延迟。记录每次 StartSegment/ReleaseSegment 调用耗时、整场源 EOF 到 Run 返回。Source 首次 Read 为固定节奏起点；以每块原始 offset/32000s 推导后续计划，记录采集落后及 Gateway gRPC Send 落后，后者含采集、WS、网关等待，不能冒充客户端 Write 精确时刻。
5. **资源**：报告 RSS、驱动 heap/goroutine 的阶段范围及空闲值，采样间隔/采样耗时/缺失数。公共 Gateway Snapshot 不提供逐时刻缓冲占用，本轮只能列配置预算，不能宣称测得所有队列峰值或模型积压有界。

没有预设首字、final、RSS 的性能达标阈值：本轮建立运行事实及后续基线，不能运行后挑阈值包装为优化收益。资源采样质量达标也不等于无泄漏。若失败，先归档事实并定位，再另行登记修正或复测。

## 观察方式的取舍

本轮给现有分段日志包装增加显式开关，围绕真实工厂成功返回、StartSegment、ReleaseSegment、Close 记录事件；不修改 protobuf 或原生模型算法。相比从文本/普通 model 日志猜段边界，它能够区分模型和流；相比重做 SDK C 层遥测，范围更小。代价是 SHA 和 JSON 日志开销，因此结果应称为“启用片段观察的基线”，不能等同于无观察开销的延迟。

首段创建耗时含整个模型工厂，不将其报告为纯流创建时间；后续三次 StartSegment 才是换流创建调用时间。工厂部分创建失败的资源由工厂清理，但没有已成功移交的流事件；出现失败时不能仅凭这份日志宣称记录了 C 内每次分配。

独立 Python 复核将验证冻结摘要、三个输入/结果分母、逐段样本摘要、Seq、终态、日志顺序和采样质量，并用损坏副本确认缺失释放、错误样本摘要、重复 final、伪造 completed 和采样缺口不能通过。原始失败和工具修订应保留。

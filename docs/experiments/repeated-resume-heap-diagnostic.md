# EXP-006-06：多轮恢复的堆分配诊断

日期：2026-10-13。状态：**十分钟正式四场已核实，分配路径与阶段差异已分类；原自然 GC 增长未完全归因。** 依据[设计与取舍](../worklog/2026-10-13-repeated-resume-heap-design.md)及 [EXP-006-05 正式结果](../worklog/2026-10-13-repeated-resume-extended-results.md)。本次定位分配来源和生命周期，不作为性能对照或原质量降级场的替代运行。

## 固定问题与分母

1. 同一进程的晚期−早期存活分配增加，主要落在哪些调用栈，字节与对象数分别多少？
2. 自然空闲和整个测试环境拆除后，这些分配是否回落？
3. 正常组是否也出现相同栈，是否有明显记录器/诊断器分配，哪些仍无法归因？

正式仅 A_normal、B_budget_8，各两场、四个独立进程；顺序 A→B、B→A，一次非 race 构建，不并行压测。每场 6000 块/600 秒、3200 字节/100ms，固定 Mock 10ms/块、原八次预算与缓存/期限配置；B 故障仍为 30/120/210/300/390/480 秒各阻断 500ms。原配置来自 EXP-006-05，新增 profile 干预单独记录。预计业务约四十分钟，外加采集/收尾，不提前承诺诊断结果。

不纳入 C 提前结束组，不增加正式场替换失败。四场固定分母，业务结果、快照有效性、拆除状态分别统计；原 EXP-006-05 六场及其降级事实保留。

## 快照与采样条件

- 专用测试子进程从启动设置 `GODEBUG=memprofilerate=1`，全程核对 MemProfileRate=1；不得中途改采样率，不对默认测试进程设置全局采样率。
- P0：profile 编码向丢弃写入器预热一次、返回后，环境建立前；P1/P2：首块开始后 90/570 秒；P3：原场自然空闲、环境拆除前；P4：子测试全部清理完成并返回后。每场计划五份 profile，共二十份。
- 每点固定 MemStats 前值→两次 GC→MemStats 后值→二进制 heap profile→关闭与最终统计。元数据含计划/实际单调时点、开始结束、NumGC、采样率、字节数、写入/关闭状态、文件摘要及资源阶段。P0/P4 没有伪造音频相对时点。
- P1/P2 独立串行任务调度，不阻塞业务回调，不暂停源、不重置源时间轴。记录触发迟到量；捕获开始迟于目标 1s、跨越 Run 返回、资源状态不再是原活动会话，标记该活动快照未满足计划。缺失快照不补造，后续快照仍按原时点取。
- P3 必须在无兜底参与时资源自然归零，P4 须核对测试连接 Close 返回、服务 Serve 退出和夹具拥有任务的 join；无法确认时不做对应清理差分结论。这些确认不等于第三方库内部所有后台任务均已退出，保留该归因边界。外层只持数值、路径及关闭结果，不持业务实例或捕获它们的闭包。
- 原业务期限 630s、自然观察 15s；诊断测试进程总期限 720s，外部执行期限 725s，由编排器仅终止并等待自己创建的进程。不会因 profile 慢而临时放宽 Worker/写入期限。
- 保留真实音频/结果/原 RPC/自然清理事件和 100ms 资源样本。profile 干预时段全部记录，不从时间序列删除；本次等待值仅为干预下的诊断事实，不参与 EXP-006-05 性能比较。
- 继续固定版本、记录运行环境、保持唤醒并审计睡眠。出现睡眠、进程提前终止、日志/快照残缺、阶段错位或业务失败时，保留全部文件并限制结论，不把文件存在当作快照有效。

## 对比产物与判断

每份保留原始 `.pb.gz`、完整元数据、受测二进制和源码。用同版本 `go tool pprof` 导出 `inuse_space`、`inuse_objects`、`alloc_space`、`alloc_objects`，对比 P2−P1、P3−P2、P4−P0，另外保留每点绝对量。命令、标准输出/错误及退出码都入档，不只保存截图或 top 十行。

差分示例（实施后替换为本场真实路径）：

```sh
go tool pprof -top -nodecount=0 -nodefraction=0 -edgefraction=0 \
  -drop_negative=false -normalize=false -sample_index=inuse_space \
  -base=early_active.pb.gz ./diagnostic.test late_active.pb.gz
```

不要将不同进程的绝对地址作为对象身份；跨场只比较符号化调用路径和量级，不直接合并 profile。符号解析不完整时保留原地址并标未知。累计量和存活量分开解释，负差分保留，累计调用栈数值不重复求和。速率为一提升小分配可见性，仍不把 profile 合计等同 MemStats/RSS。

预定输出是：逐场业务/快照/拆除状态、五个时点的堆与对象数、三类差分的主要分配栈及正负量、两次重复的一致与不一致、工具/运行时路径与尚不能归因的路径。若出现相同栈在两次运行均活动期增长且拆除后仍保留，再据代码决定是否需要修复或进一步对照；不预设百分比泄漏阈值，不把一次回落或“没找到”写成无泄漏。

强制 GC 及全量分配剖析会影响缓存和运行，诊断结果不能证明原自然 GC 条件下的状态完全相同。如果增长未复现，应明确留下这一限制，后续是否补无强制 GC 对照由证据决定。

## 工具验收顺序

先在自有子进程验证：已知大小对象保持存活、解除引用并 GC 后相应分配栈回落；快照速率/阶段/时间/摘要核对；文件独占、写入/关闭失败、截断与缺失不能误报成功；P4 在全部清理后，且诊断调度任务实际 join。已知对象验证需避免编译器消除，并使用同一分配栈比较，不硬比整个进程总堆。

再做 A/B 各一场 12 秒 probe（输入/六轮故障沿用已验收 probe 条件），P1/P2 改为首块后 2/10 秒，其余阶段相同；进程期限 90s、外部 95s。验证音频/结果、原 RPC、全部快照及自然清理；由于采集可能干扰很密集的 probe 故障，失败需先解释并保留，不据此调大正式业务预算。probe 仅验收工具，不作为增长或性能样本。

工具实现完成后冻结提交、源码/计划摘要和实际采样率，再运行正式四场。任何采样策略/时点/期限修订先记录理由和新版本；正式数据不补改。最后归档解压读回并使用冻结分析流程复算。

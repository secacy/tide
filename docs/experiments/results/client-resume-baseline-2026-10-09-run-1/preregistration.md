# EXP-006-01：同实例有限恢复的单会话断网对照

Date: 2026-10-08
Status: 2026-10-09 工具与短时行为验收完成；正式五组各三次测量尚未执行，暂无恢复性能结果。
Baseline: `712a4cf` 已接通同实例有限原场恢复；正式实验使用后续包含采集工具的同一版本，记录提交和源码哈希。
Related: [客户端恢复设计与功能验收](../worklog/2026-10-08-client-v2-resume.md)、[Milestones](../MILESTONES.md)

## Goal / Questions

已有真实网络功能验收说明：已覆盖的四种丢失场景可以接回原 Worker，音频逐字一致、结果不重复。它们没有固定实时输入和断网持续时间，不能给出恢复耗时或断网期间的转录体验。

本实验固定输入、故障边界和预算，比较同一版本关闭/开启客户端恢复时的表现，回答：

1. 中途断网后，整场能否完成？Worker 实际收到哪些音频，有没有缺失、重复或乱序？
2. 恢复路径重新开放后，多久转发恢复 ready？多久返回断网后新采集音频的结果？
3. 恢复后结果落后多少，能否重新跟上固定输入时间轴？
4. 超过恢复预算时，是否明确失败、停止尝试，并在不取消服务兜底的条件下释放原场资源？

只建立单会话、本机真实网络、同一存活 Gateway/Worker 的基线。实例丢失、群体同时断线、真实 ASR、临床长时问诊另行实验。

## 方案选择与权衡

| 选择 | 优点 | 代价及本轮决定 |
| --- | --- | --- |
| 同版本 `Resume=nil` / 非 nil 对照 | 保持 Gateway、Worker、输入和构建一致，观察启用恢复带来的变化 | 不证明相对所有历史版本的收益；本轮采用 |
| 使用 OS 网络故障工具 | 更接近真实链路上的延迟、丢包和网络切换 | 注入权限、外部状态与复现成本更高；留到后续弱网实验 |
| 真实 WebSocket 故障代理 | 可以精确选择丢失消息，记录输入位置，公开入口和真实 TCP gRPC 仍参与运行 | 多一跳且是确定性故障，不能模拟所有弱网行为；本轮采用 |
| 按墙上时间断线 | 直观地表达问诊第几秒断网 | 调度不同会使每轮丢失不同音频；本轮按音频位置触发，并记录真实时刻 |
| 扩展生产结果协议，增加音频位置 | 可为真实模型建立通用结果延迟口径 | 模型位置语义尚未定义，本轮无需改变生产契约；实验 Mock 文本携带位置标记 |
| 在 v2 客户端增加通用观测回调 | 可精确观测内部断线判定、ready 接纳及写入 | 会扩展公共 API 和并发路径；本轮先用源、代理、Worker、已有 OnResult 和 RunResult，不将代理时间冒充内部时间 |

不直接沿用 v1 的 `AudioBytesWritten == PlannedAudioBytes` 完成判据：v2 恢复会再次传输部分位置，网络传输量与逻辑音频量不同。结果 seq 去重也不能代替 Worker 音频完整性检查。

## Hypothesis

以下是实验前假设，不是已测结果：

- 无故障组正常完成；关闭恢复的断线组不能完成原场。
- 500ms / 2s 中断在客户端 5s 固定恢复窗口和缓存预算内，有机会保持原 Worker 并最终完成；是否及时追上输入需测量。
- 6s 中断超过客户端恢复窗口，应返回恢复预算耗尽，而不是再次 start。服务端仍可能保留原场至自己的期限，客户端返回不表示远端已经归零。

## Setup

每次只有一场会话，顺序执行；各场使用独立输入、记录器、Gateway、Worker 和代理，不共享恢复身份。

### Client / Input

- PCM：16kHz、单声道、16bit；6 秒，共 192000 字节，60 块，每块 3200 字节（100ms）。
- `Realtime=true`，采用现有采集器的固定时间轴，不在恢复后重新开始计时。
- 输入采用确定性的位置相关字节内容，逐字核对 Worker 接收内容；不能只用全零静音判断顺序和重复。
- 包装源，记录每块实际 Read 的起止、字节范围和 Close 次数；第一块 Read 的开始作为输入时间轴的可观察原点。它与采集器内部 planned 原点存在少量偏差，结果等待明确按此代理原点计算。
- `MaxReplayBytes=320000`、`MaxReplayChunks=128`；`ReadLimit=65536`。
- `HandshakeTimeout=10s`、`WriteTimeout=5s`、`ApplyTimeout=5s`、`CompletionTimeout=30s`。
- 开启恢复时：`MaxAttempts=5`、`Window=5s`、`InitialBackoff=100ms`、`MaxBackoff=1s`；关闭时 `Resume=nil`。
- 每场业务运行外层期限 15s；业务返回后独立观察自然清理最多 15s。所有观测完成后才执行服务停止兜底；兜底不能使自然清理判据达标。

### Gateway / Worker

- Gateway：`MaxSessions=1`、`MaxMessageBytes=1048576`、`WorkerSendTimeout=2s`、`ResultWriteTimeout=2s`、`MaxPendingAudioBytes=0`。
- v2：`MaxHandshakes=4`、`EntryTimeout=10s`、`InputProgressTimeout=30s`、`ResumeWindow=10s`、`ResultRetentionTimeout=10s`、`WorkerStatusTimeout=2s`。
- v2 存储：`MaxAudioBytes=1048576`、`MaxAudioChunks=256`、`MaxResultBytes=1048576`、`MaxResults=256`。本轮不制造容量竞争，也不关闭有界存储保护。
- 一个可控实验 Worker，真实 TCP gRPC 接入；每块固定处理等待 10ms，可被取消打断，顺序处理。
- 每块处理后先按现有协议报告累计 `processed_audio_bytes`，再返回带有累计字节位置标记的 partial；合法 EOF 后返回一次 tail final。位置标记只供本实验分析，不代表真实模型具有这种输出频率或推理速度。
- Worker 保存实际音频字节、块范围、处理位置、RPC 开始/退出和退出原因；统计 Worker 选择与建流次数。

### Fault

代理在首次连接读取到第 20 块音频 `[60800,64000)` 时，记录故障时刻和该帧，**不转发这一块**，关闭当前两侧 WebSocket；第 1–19 块照常转发。正常组不注入。

故障期间，新连接可以到达代理，但代理收到 resume 后等待通路开放再连接 Gateway；等待可取消，不向 Gateway 提前发送恢复请求。实际开放时刻由计时器返回后记录，不能用“故障时刻 + 配置值”代替。该方式主要测一次握手受阻和后续恢复，不证明快速拒绝/退避策略的性能，也不模拟隐蔽半开连接的故障检测时间。

第 20 块客户端 Write 可能已经返回成功，故意制造“本地写出不等于远端接纳”。恢复 ready 的 nextOffset 才决定补发位置；不能从预设故障直接填报实际重放量。

## Cases / Procedure

| 组 | 恢复 | 故障阻断时长 | 预期用途 |
| --- | --- | --- | --- |
| A：正常参照 | 关闭 | 无故障 | 固定输入、Mock 和工具本身的正常表现 |
| B：断线参照 | 关闭 | 500ms | 未启用恢复时的原场结局；不人为新建替代会话 |
| C：短暂中断 | 开启 | 500ms | 与 B 同故障对照，观察完整性和恢复等待 |
| D：较长中断 | 开启 | 2s | 观察较多缓存音频的追赶，不调大预算 |
| E：超出窗口 | 开启 | 6s | 验证客户端停止尝试和服务端自然到期清理 |

1. 先实现工具并验证位置关联、重复量计算、缺失事件 null、故障只触发一次及自然清理/兜底区别。短时行为测试可启用 race，但不作为性能样本。
2. 正式测量不启用 race、虚拟时间或 t.Parallel。记录 Go/OS/CPU/内存/GOMAXPROCS、提交、源码哈希、完整命令和配置；保持电脑唤醒。
3. 三轮，每轮 A→B→C→D→E，共 15 次；固定顺序便于复现，同时承认未随机化的时间趋势局限。不得把失败运行删去或换成成功重测。
4. 每次先记录 Run 结果，再观察服务端自然归零，等待实际 Worker、Gateway handler 和代理任务退出。自然清理观察失败单独分类，最后执行兜底。
5. 原始 JSON 保留所有源读取、代理帧范围/转发结果、ready 转发时刻、Worker 处理位置、客户端应用结果和资源采样；不保存 sessionID、resumeToken 或患者文本。
6. 汇总前交叉核对每场配置、故障事实、位置范围、时间顺序及退出事实。首次工具错误、未触发故障和采样缺口原样归档，说明不能用于哪些结论；不得悄悄补值。

## Metrics

| 指标 | 口径 |
| --- | --- |
| 完整完成数 | planned 分母固定为每组 3；Run 无错误、Completed、CompletionAckWritten、FinalOffset=192000，并通过 Worker 音频/结果完整性核对才记完整完成 |
| 音频缺失、重复和顺序 | 完成样本 Worker 全部接收字节须逐字等于输入，长度与 60 块一致；失败样本报告收到的连续前缀、缺失范围和差异，不把正常终止后的未采集部分混成网络丢失 |
| 代理观察的重复传输字节 | 将代理实际读取的音频范围长度之和减去范围并集长度；包括故障处读到但未转发的帧，不含协议头。这是可观察的重传量，不是客户端所有 Write 尝试或 Worker 重复处理量 |
| 恢复尝试/接纳次数 | 使用 RunResult 的 ResumeAttempts / ResumedConnections，并用代理入口事实交叉核对；不把服务器 generation 数当成本地接纳次数 |
| ready 转发等待 | 首次恢复 ready 的代理成功 Write 返回时刻分别减故障时刻、通路开放时刻；它不证明客户端已读到并接纳 ready，Write 返回可能晚于客户端处理 |
| 新采集音频恢复等待 | 找到实际 Read 开始晚于故障时刻的第一块，取覆盖该块结束位置的首条已成功应用 partial 的 receivedAt，分别减故障时刻和通路开放时刻；旧结果补发不能充当该样本 |
| 各位置的结果等待 | 对 partial 的音频结束位置定位其最后一块，receivedAt 减该块相对输入原点的计划读取时刻；包含源/调度、缓存、网络、处理及回传，不是纯推理耗时 |
| 更新最大间隔 | 连续已应用 partial 的 receivedAt 间隔；同时保留整条时间序列，不用最大值代替全部体验 |
| 追赶确认 | 开放后按客户端实际接收顺序，首次连续三条 partial 的结果等待均 <=200ms，取第三条到达时刻；记录距开放的等待。200ms 为本实验分析阈值，不是业务 SLA |
| 清理等待 | Run 返回后，服务端活动/握手计数、注册表及 Worker 活动数首次共同空闲的采样时刻减 Run 返回时刻；保留实际观察延迟，不假定返回前已归零而填 0，精度受 10ms 采样间隔限制；另核对任务实际退出 |
| 源与失败事实 | 实际采集量、每块读取落后、Close 次数、业务错误类别、是否耗尽恢复预算、是否到达外层期限、是否使用停止服务兜底 |

不存在的事件和延迟保留 null；没有后续新采集音频时，新音频恢复指标无样本。负的 ready 相对应用时间不强行改成 0，两者不是严格的先后边界。仅完整完成样本贡献成功延迟统计，失败数必须并列展示；各组三次展示逐次值和 min–max，不把小样本 p95 宣称为可靠尾部估计。

## 判据与 Results

先区分业务结果与实验数据是否有效：E 正确停止恢复可以通过行为判据，但其业务完整完成数仍为 0。

- A：3/3 完整完成，Worker 每场一条流，音频逐字一致，partial 位置连续且 tail final 一次；无 resume 尝试。
- B：每场确实触发故障，业务不完整，resume 次数为 0，不创建第二场；已接纳音频是输入连续前缀，资源自然归零。
- C / D：每场确实触发故障，3/3 完整完成，每场仍只选一次 Worker / 建一次 RPC，结果 seq 1–61 每个成功应用一次，音频逐字一致；恢复与追赶时间完整记录。
- E：每场确实触发故障，业务不完整，包含 ErrV2RecoveryExhausted，不回退 start，Run 在外层 15s 到期前返回，尝试数不超过 5；资源在独立观察窗口内自然归零。
- 全组：源恰好 Close 一次，无 race 行为验证错误；每次都输出原始报告。配置错误、工具错误、自然清理失败或需要停止服务兜底均明确标记，不能与正常达标合并。

恢复耗时没有预写“优化 X%”目标。本轮先建立测量事实；追赶未达到 200ms 分析阈值时记录未达到，而不是修改阈值或删除样本。若 C / D 未全部完成或出现数据差异，保留结果并先定位原因，再以新版本复测，不能覆盖首轮。

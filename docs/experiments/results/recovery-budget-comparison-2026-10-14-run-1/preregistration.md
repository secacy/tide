# EXP-006-07：长会话累计与滑动恢复预算对照

日期：2026-10-14。状态：**预登记与工具适配已完成，四场 probe 已验收；正式十分钟四场待执行，Results 暂无正式数据。**

依据：[预算设计](../worklog/2026-10-13-recovery-budget-review.md)、[客户端实现](../worklog/2026-10-14-recovery-attempt-window.md)、[短场网络验收](../worklog/2026-10-14-recovery-attempt-window-network.md)、[工具适配方案](../worklog/2026-10-14-recovery-budget-comparison-design.md)。复用 [EXP-006-05](repeated-resume-extended.md) 的输入、故障和观测口径，旧六场只作问题依据，不进入本次统计分母。正式受测版本在工具验收后冻结，计划与源码一同保存摘要；变更条件须另记版本和理由。

## 目标与问题

在相同十分钟音频、六次低频断线、Mock 速度与缓存预算下，观察五次整场限额改为“最近六十秒最多五次尝试”后的业务完成、失败范围与资源表现。

1. 累计组是否在第六次故障前成功接回五次，然后因额度耗尽终止？
2. 滑动组是否接回六次并处理完整音频、结果及尾部？有没有额外失败尝试或提前终止？
3. 两组前五轮的恢复等待、追赶与转录中断如何；第六轮各发生了什么？
4. 失败留下多少已采集未处理音频，尚未采集部分有多少？完成/失败后原场是否自然释放？
5. 在两组共同在线的固定窗口内，是否有未确认位置持续扩大、活动任务未回落或堆增长线索？

本轮回答指定故障间隔下预算策略的效果。60s 是本次预先选择的回看窗口，便于检验 90s 间隔的旧尝试会过期；不声称它是临床网络的最优参数。密集抖动和精确时间边界已有短场/单元测试，本轮不重新混合为群体重连实验。

## 方案、分组与顺序

只比较两种预算，其他条件相同。使用同一提交、单次非 race 构建的同一二进制，每场独立进程/环境，串行运行，不与其他负载或堆诊断并行。

| 组 / 固定 case 标识 | MaxAttempts | AttemptWindow | Window | 输入 / 故障 | 预期行为 |
| --- | ---: | ---: | ---: | --- | --- |
| L / L_lifetime_5 | 5 | 0 | 5s | 600s / 六轮 500ms 阻断 | 五次恢复后第六轮次数耗尽 |
| S / S_sliding_5 | 5 | 60s | 5s | 同 L | 六次恢复并完整结束 |

固定两轮，第一轮 L→S，第二轮 S→L，共四场，每组分母为二。相反顺序减轻单向时间顺序影响，但小样本不足以给出统计显著性。正常无故障组不加入本轮：当前问题是相同故障下计数范围的差异；这也意味着不能把本轮资源变化单独归因于断线或预算代码的分配开销。

按预期 L 在约第八分钟返回，随后原场保留约十秒；S 完成十分钟。四场串行预计约 37 分钟，另有构建/归档时间，实际超时或其他失败可能改变用时。四个槽位固定保留，不因失败、输入节奏不合格或缺证据而补场替换；环境修复后完整复测须另目录，不拼接分母。

## 固定输入、故障及配置

以下均与 EXP-006-05 相同，只有恢复计数范围按本页分组区分。

- PCM 16kHz/单声道/16bit，3200B/100ms，6000 块，总量 19,200,000B；Realtime=true，采集原点跨恢复固定。块 i 为 `SHA256(ASCII("tide-exp-006-05:") || uint64BE(i))` 摘要重复 100 次，保留旧前缀以保证相同音频。按块生成和增量校验，不保存整场录音。
- Worker 按序核对每块内容，等待 10ms 后发送处理进度与 offset partial；合法 EOF 后唯一 tail final。完整场必须处理全部字节，应用 seq 1–6001 一次，最后完成确认实际写出。
- 零基故障块号 [300,1200,2100,3000,3900,4800]，offset [960000,3840000,6720000,9600000,12480000,15360000]，对应相对首块读取 30/120/210/300/390/480s。
- 代理首次看到指定 offset 时记录 T0、丢弃该块并关闭前后端 socket，只触发一次；500ms 到期开放通路。新 resume 在代理可取消地等待开放，重放该 offset 不再触发故障。源按原时间轴继续采集，不暂停等待网络。
- Client：ChunkBytes=3200，MaxReplayBytes=320000，MaxReplayChunks=128，ReadLimit=65536，HandshakeTimeout=10s，WriteTimeout=5s，ApplyTimeout=5s，CompletionTimeout=30s。
- Resume：MaxAttempts=5，Window=5s，InitialBackoff=100ms，MaxBackoff=1s，Jitter=false；AttemptWindow 仅按 L/S 区分。成功接纳不重置整场 ResumeAttempts。
- Gateway：MaxMessageBytes=1048576，StartTimeout=10s，InputIdleTimeout=30s，WorkerSendTimeout=2s，MaxSessions=1，TailTimeout=15s，ResultWriteTimeout=2s，MaxPendingAudioBytes=0。
- v2：MaxHandshakes=4，EntryTimeout=10s，InputProgressTimeout=30s，ResumeWindow=10s，ResultRetentionTimeout=10s，WorkerStatusTimeout=2s，MaxAudioBytes=1048576，MaxAudioChunks=256，MaxResultBytes=1048576，MaxResults=256。
- 单场 Run 外层期限 630s；返回后自然收尾观察 15s；测试进程保护 660s、采集器外层 665s。自然观察结束前不取消服务或关闭共享 ClientConn。兜底参与、工具写入错误、外层超时分别记录。
- 事件队列 1024、单事件上限 8192B、记录缓冲 65536B；资源每 100ms 串行采样。保持自然 GC，不主动调用 GC 或采集 heap profile。记录 GOMAXPROCS/GOGC/GOMEMLIMIT/GODEBUG 实际环境，两组一致，拒绝误带上一轮全量剖析设置进入正式性能观察。

每个故障的计时/开放任务独立退出，包括 L 第六轮没有 resume 的情况。源提前退出使后续故障未发生时明确记录未发生，不重建会话补计划，也不延后故障等待追赶。

## 证据与判据

沿用 EXP-006-05 的单调 elapsed_ns、组件事件编号、块摘要与范围核对、位置/结果顺序、原 RPC、自然清理检查。配置事件及终态必须包含本实验 ID、case、实际生效的恢复配置。L 的 AttemptWindow 零值允许按旧 JSON omitempty 缺省，但分析时明确解释为 0；S 必须显式记录 60000000000ns。不能只相信场景名字。

| 类别 | 固定口径 |
| --- | --- |
| 完整完成 | Run 无错误、Completed 与 CompletionAckWritten 为真、FinalOffset=19200000；原 RPC/Worker pick 各一，完整输入摘要一致，seq 1–6001 一次 |
| 实际业务结局 | 每组列完整 / 明确失败 / 未知，分母固定 2；缺场或无完整证据列未知，不从分母扣除 |
| 次数 | 整场 ResumeAttempts、ResumedConnections、代理逐次 start/resume/ready 对照；首次 start 不计，成功和失败尝试都计入，禁止回退 start |
| L 预期 | 六轮故障触发，前五轮恢复，ResumeAttempts=ResumedConnections=5；第六轮无 resume、recovery_exhausted，非外层超时，自然释放 |
| S 预期 | 六轮故障触发，每轮接回且下一轮前追赶，ResumeAttempts=ResumedConnections=6，最终完整结束并自然释放 |
| 恢复与中断 | 各轮 T0→代理 ready 转发、T0→首个故障后开始采集块的结果、开放→该结果、开放→连续三条结果等待 <=200ms 的第三条；覆盖故障的相邻 partial 间隔 |
| 缺口 | 实际采集/收到/处理/应用位置分列；已采集未处理与尚未采集区间分开，未恢复时间为 null，失败后的无更新时长带右删失标识 |
| 清理 | Run 返回、原 RPC 退出、活动会话/注册/握手/代理与 Gateway handler/故障任务自然归零各自时刻；源关闭一次，清理任务实际 join |
| 资源 | 全样本及固定窗口的 goroutine、HeapAlloc/HeapInuse、GC、TotalAlloc、记录器队列/累计写出量，配置上限不冒充已测缓存峰值 |

实际行为偏离预期与日志证据损坏分开。例如多一次失败尝试但完整结束，应如实报告完整完成、次数与行为偏离，不能为了符合 6 次预期删除尝试。L 正确耗尽是保护行为达标，业务完成仍为零。

S 的整场尝试数可以大于 5，分析器不得沿用旧 `ResumeAttempts <= MaxAttempts` 的整场判断。始终核对 ResumedConnections <= ResumeAttempts 及代理观测请求数 <= 启动次数。代理看到请求的时间晚于本地启动，不能作为精确的客户端滑动窗口时刻；本轮不新增业务回调或凭代理时间宣称严格证明任意 60s 内的启动上限。该边界由前序协调者可控时间与短场网络测试支撑，本轮记录实际总次数、故障间隔和结果。

每组只有两场，展示逐场/逐轮与 min/median/max；若两组完成数不同，可写“本轮固定条件下 L x/2、S y/2”，完成率差可作样本描述，不能写成生产成功率或显著改善。前五轮只比较双方具备合格证据的实际轮次；第六轮将 L 失败与 S 观察结果并列，不把 L 的 null 当作 0ms，也不计算失败→成功的延迟降幅。

## 时间质量与资源窗口

沿用固定判据，不按结果调宽：故障实际阻断 500–650ms；源非空 Read 最大计划落后 <=100ms；资源窗口样本覆盖 >=90%、最大采样间隔 <=1s。超限保留业务/故障原值，相应等待或趋势解释降级。记录睡眠事件、采样缺口、进程终态和实际配置；工具异常不伪装成普通业务失败。

两组共同观察窗为相对首块 [60,90)、[150,180)、[240,270)、[330,360)、[420,450)s；后续 [510,540)、[550,590)s 按两组原样列出，L 未到达写缺失，S 作为自身继续运行的描述。窗口仍有恢复/已失败则标记，不能作为稳定在线；不把 S 多运行两分钟的总分配量与 L 短场直接比较成本。

稳态活动会话/注册/RPC 预期各一，临时握手/故障任务归零；退出连接不保留活跃转发任务。连续三个后窗最小堆或 goroutine 高于首个合格窗，仅标为需定位线索。堆覆盖同进程全部组件和工具，无正常组及原子引用图，不能从这四场宣称泄漏/无泄漏、单会话严格内存上限或预算算法开销优化。

## 工具验收与正式启动门槛

独立默认 probe 为 12s、120 块，故障块号 [10,25,40,55,70,85]，阻断仍 500ms，MaxAttempts=5；L 的 AttemptWindow=0，S 专用缩短窗口=1s，其他配置相同。业务保护 42s、自然观察 15s、测试进程保护 90s、采集器 95s。probe 的 1s 只能用于缩短行为验证，必须在配置与 manifest 标明；不能带入 formal 或伪装为正式 60s 样本。

probe 顺序同为 L→S→S→L，预期 L 第六轮耗尽、S 六轮完整；资源分组窗沿用旧 probe：[2,2.4)、[3.5,3.9)、[5,5.4)、[6.5,6.9)、[8,8.4)、[9.5,9.9)s，仅检查分组与缺失，不推断趋势。不同模式不混合统计。

正式开始前必须完成：

1. Go 夹具显式接入新实验 ID、case 与 AttemptWindow，实际配置和终态一致；旧入口/旧 JSON 默认仍能复算旧实验。
2. 采集器一次构建、四个独立进程、正式模式显式启用；每槽位退出码/超时/错误保存，受测源码前后摘要一致，源快照包含新计划及所有依赖。
3. 独立分析器按明确策略验证配置、结局和原事件，不把 S 六次尝试误报为超额；覆盖错误 mode/窗口/次数、缺场/截断/重复或跳跃位置、伪完成与强制清理反例。
4. 四场 probe 的完整性及 L/S 预期核实；失败与数据质量原样保留，不因为 probe 性能不佳静默调整正式阈值。
5. 正式运行期间由采集器持有唤醒保护并审计睡眠；日志、配置、事件、二进制/源码、退出状态与环境全部归档。搬移后用冻结分析器复算输出一致，读回文件摘要一致。

采集器或分析器尚未完成时不能通过改旧场景标签直接运行。复用通用记录、采集流程与逐场完整性校验，为 EXP-006-07 提供独立固定条件；旧归档与受测计划原样保留。

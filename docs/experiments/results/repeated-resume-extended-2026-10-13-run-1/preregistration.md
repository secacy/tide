# EXP-006-05：十分钟会话与多轮断线观察

日期：2026-10-12。状态：**实验已预登记；Go 专用夹具/有界记录器及十二秒 probe 已验收，独立采集/分析与六场缩短 probe 也已验收，正式测量未运行。**

依据：[多次断线短场景验收](../worklog/2026-10-12-repeated-recovery-validation.md)、[第六阶段检查点](../worklog/2026-10-12-stage-six-review.md)。正式版本在工具验收后冻结，本文件与实现一同记录摘要；任何条件修改须先记录理由和新版本，原运行保留。

## 目标与问题

固定单会话、输入节奏、Mock 处理能力与六次故障，观察时间拉长后原场是否继续完整处理，以及累计尝试预算和资源保留如何表现。

1. 十分钟输入中六轮短暂断线，是否仍只有一次 Worker 选择及原 RPC，输入与结果完整、有序？
2. 每轮故障到新音频结果的等待是否随轮次变差？恢复后是否重新跟上采集时间轴？
3. 五次预算在多轮故障中何时耗尽？客户端返回与远端名额释放相差多少？
4. 各轮恢复后的活动连接、任务和未确认位置是否回落？整进程堆及 goroutine 是否出现需进一步定位的增长？

这是从六秒恢复实验延长到十分钟的观察，不足以证明数十分钟门诊、生产容量、真实 ASR 或任意弱网可靠性。

## 条件与执行顺序

每场一个 Client.Run、公开 v2 Gateway、单 TCP gRPC Mock Worker 和真实 WebSocket 代理。每场独立环境，串行执行，不与其他负载并行；每场独立测试进程，使用同一非 race 二进制。实验期间保持电脑唤醒，记录系统睡眠事件和采样缺口。

| 组 | 计划输入 | 故障 | MaxAttempts | 预期用途 |
| --- | --- | --- | ---: | --- |
| A 正常参照 | 600s | 无 | 8 | 正常十分钟链路及工具开销参照 |
| B 多轮恢复 | 600s | 六轮，每轮阻断 500ms | 8 | 观察跨轮恢复、完整性、等待及资源变化 |
| C 累计耗尽 | 600s | 与 B 相同 | 5 | 在第六轮观察累计预算边界及自然到期清理 |

固定两轮，第一轮 A→B→C，第二轮 C→B→A；共六场，各组分母为二。对照组与故障组仍独立运行，不作患者配对推断。正常与恢复完整场各十分钟，C 预计在约第八分钟结束；业务及自然清理合计预计约 57 分钟，另有构建和归档时间。未运行前不承诺结果或精确用时。

不把不同完成时长的 C 与 A/B 直接比较整场资源总量，也不把旧六秒样本混入本轮分母。失败、未达标、未知、数据不合格均保留；不追加成功场替换原场。

### 输入及 Worker

- PCM 16kHz、单声道、16bit，3200 字节/块，100ms/块，6000 块，总量 19,200,000 字节；`Realtime=true`。采集时间轴只建立一次，恢复后不重置。
- 输入按块号生成确定内容，不预先持有整场音频。块号从零开始；第 i 块为 `SHA256(ASCII("tide-exp-006-05:") || uint64BE(i))` 的 32 字节摘要重复 100 次。固定各组同一输入，独立分析器按同一格式核对摘要；不使用全零或各块相同内容。
- Worker 顺序校验实际音频与预期下一块逐字一致，每块可取消等待 10ms，再发送累计处理进度及携带结束 offset 的 partial；合法 EOF 后发送唯一 tail final。
- 完整场预期 6000 个 partial、1 个 tail final，客户端应用 seq 1–6001。Worker 对不完整、重复、跳跃或错误内容记录实际错误，不把输入修正成预期数据。
- 源及 Worker 只保留当前块、位置、计数和增量 SHA256；原始位置/摘要事件流式写盘，避免全量音频和事件切片制造随时长增长的堆。

### 预算与配置

- Client：ChunkBytes=3200，MaxReplayBytes=320000，MaxReplayChunks=128，ReadLimit=65536，HandshakeTimeout=10s，WriteTimeout=5s，ApplyTimeout=5s，CompletionTimeout=30s。
- Resume：各组均开启；MaxAttempts 如表，Window=5s，InitialBackoff=100ms，MaxBackoff=1s，Jitter=false。整场尝试数不重置，每轮恢复窗口从客户端观察断线开始；服务器窗口有自己的起点。
- Gateway：MaxSessions=1，MaxMessageBytes=1048576，WorkerSendTimeout=2s，ResultWriteTimeout=2s，MaxPendingAudioBytes=0。
- v2：MaxHandshakes=4，EntryTimeout=10s，InputProgressTimeout=30s，ResumeWindow=10s，ResultRetentionTimeout=10s，WorkerStatusTimeout=2s，MaxAudioBytes=1048576，MaxAudioChunks=256，MaxResultBytes=1048576，MaxResults=256。
- 单场业务外层期限 630s，自然收尾在 Run 返回后另观察最多 15s；测试进程外层保护 660s。服务生命期独立于 Run；自然观察结束前不主动取消服务或关闭共享 gRPC ClientConn。任何兜底参与都明确记录。
- 不通过增加缓存、改变 Worker 速度、打开 jitter 或提高握手容量补救某组失败。

### 故障位置与语义

按音频起始 offset 触发，计划采集时点为相对第一块读取的 30、120、210、300、390、480 秒；零基块号为 300、1200、2100、3000、3900、4800，offset 为 960000、3840000、6720000、9600000、12480000、15360000。

代理第一次看到对应 offset 时记录 round 和 T0，丢弃该块并关闭当前前后端 socket。该轮只触发一次，重放相同 offset 不再次切断。计时到期后开放通路，新 resume 在代理处可取消地等待开放再进入 Gateway；不伪造入口拒绝、ready 或故障结果。不通过重启源或暂停实时输入等待恢复。

第六轮 C 即使没有恢复请求，故障开放任务也独立完成并计入自然清理。后续计划故障若因前面失败无法触发，标记未发生，不补造事件，不重建会话继续计划。

每轮应在下一轮触发前有新采集音频结果，且完成三条连续结果等待不超过 200ms 的追赶确认。未满足时记录未追赶/重叠，不人为延后下一次计划故障。代理暂扣握手使本轮主要观察跨轮恢复而非快速拒绝下的重试排期；理想情况下 B 六次成功恢复、C 五次成功恢复。额外尝试或提前耗尽均保留为待解释事实，不强行填入这个预期。

## 记录、计时与数据质量

- 所有同进程事件携带从单一 `time.Now()` 原点计算的单调经过纳秒 `elapsed_ns`；独立分析以此计算间隔。墙钟只用于 UTC 时间对齐、环境审计，不将去掉单调部分的时间戳相减替代原间隔。不同进程的 elapsed_ns 不相减。
- 故障实际释放须至少经过配置 500ms 的单调时间；记录实际开放时刻。本轮 500–650ms 作为注入时长质量范围，超范围时保留业务结局、将对应恢复时间比较标为不合格，不能伪造恰好 500ms。
- 记录源 Read 起止、字节范围/块摘要/计划时点、代理音频接收及转发、握手种类、ready 位置、ACK 位置、Worker 收到/处理/结果发送、客户端成功应用、所有任务和原 RPC 退出。ID/token 仅在内存验证，不写凭据或原始握手。
- 事件按组件标识和递增编号关联，不假设多个 goroutine 写日志的顺序就是发生顺序。缺失、重复编号、范围矛盾、工具写入错误和截断均拒绝完整证据结论。
- 每 100ms 串行采样活动会话/握手/注册/Worker RPC/代理及 Gateway handler/故障计时任务、goroutine、HeapAlloc、HeapInuse、NumGC、TotalAlloc、记录器队列长度及累计写出量。采样失败不是零活动观测。
- 正常活动窗口不含启动、自然清理：有效采样数至少为计划数量的 90%，最大采样间隔不超过 1s；源非空 Read 最大计划落后不超过 100ms，才满足本轮节奏/资源趋势分析质量。越界保留完整性和故障事实，但相关时间/趋势结论降级，不能删除慢样本改善指标。
- 观察到睡眠，或缺少连续计时/配置/进程终态证据，明确限制本次结论；环境修复后的复测另建目录、冻结版本，不拼接原场。

## 指标与验收

| 类别 | 固定口径 |
| --- | --- |
| 完整完成 | Run 无错误、Completed、CompletionAckWritten、FinalOffset=19200000；原 Worker 一次选择/建流，完整输入逐字校验/增量摘要一致，seq 1–6001 只应用一次 |
| 每轮恢复等待 | 分别记录 T0→ready 成功转发、T0→新采集音频结果、实际开放→新采集音频结果；ready 转发不冒充客户端接纳时刻 |
| 新音频与追赶 | 该轮 T0 之后开始读取的第一块，其位置首次被成功应用的 partial 覆盖；结果等待以该块计划采集时点起算；首次连续三条 <=200ms 的第三条为追赶确认，200ms 为实验分析阈值 |
| 转录中断 | 每轮覆盖故障的相邻 partial 间隔及整场最大间隔；失败后没有下一个结果时，记录截至返回的无更新时长和右删失标识，不当成有限恢复间隔 |
| 次数与恢复成本 | RunResult 总尝试/成功接纳数，逐连接代理请求与 ready 事件；按轮统计实际请求与代理音频范围的重复覆盖字节，不把代理字节当 TCP 总流量 |
| 失败输入范围 | 实际采集、Worker 收到、处理及客户端应用位置分别记录；已采集未处理和尚未采集分开，失败场保留 null 恢复等待 |
| 外部积压线索 | 采集位置、代理观察的 Gateway 接纳 ACK、Worker 处理位置随时间变化；这是各观测点的位置差，不是客户端内部缓存占用或瞬时原子快照 |
| 清理 | 客户端返回与原 RPC 实际退出、服务资源共同归零和代理/记录任务退出分别记时；自然空闲须在取消服务兜底前发生，写盘关闭错误单独记录 |
| 资源趋势 | 所有样本及固定窗口摘要；过程堆包含整个夹具和客户端，不换算单会话内存上限、RSS 或模型显存 |

A 预期两场均完成且零 resume；B 预期两场均完成且六轮都接回原 RPC；C 预期五次恢复后第六轮不再 Dial、明确 recovery_exhausted，无外层超时或回退 start，并自然释放原场。预期未满足要报告，不等于工具证据一定无效。C 正确失败算行为达标，业务完成仍是零。

每场源 Close 一次。所有实际音频、结果、位置与计数须交叉核对；记录器错误、缺场及不完整终态不能包装成业务失败之外的成功样本。两次重复仅展示逐场、逐轮和 min/median/max，不以 P99、统计显著或生产成功率表达结果。

### 资源趋势的预定观察窗口

相对首块读取，固定 [60,90)、[150,180)、[240,270)、[330,360)、[420,450)、[510,540) 秒，每窗列样本数、goroutine 最小/中位/最大、堆最小/中位/最大及 GC 次数，并列出累计记录量和队列峰值。A 使用相同窗口；C 未运行到的窗口记缺失。恢复未结束或业务已失败的窗口标注，不能冒充稳定在线窗口。

额外检查 [550,590) 秒的正常尾段（仅 A/B）。活动会话/注册/RPC 稳态应各一，临时握手和故障任务归零；已退出连接不能继续保留活跃转发任务。首窗与后窗整进程堆/goroutine 变化先作为描述性结果，**不预设无依据的内存百分比阈值，也不凭六个窗口认定泄漏**。若连续三个后窗的最小值都高于首窗，标为需定位的增长线索，结合 A、GC 和记录器队列解释；不能仅凭进程末次 GC 回落宣称全程有界。

需要精确缓存占用时须另外设计由所属协调者发布的快照；本轮不从其他 goroutine 无锁读取私有字段，也不把配置上限当作已测峰值。

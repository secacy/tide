# EXP-004-05：单实例会话准入验收

Date: 2026-09-22
Status: 已完成本步验收；不代表第四阶段完成或稳定容量已确定。
Related: [设计与取舍](../worklog/designs/2026-09-22-session-admission.md)、[Milestones](../MILESTONES.md)

## Situation / Task

发送期限能够终止一次长时间阻塞的发送，但不限制同时进入多少个会话。原 tracker 只计数和管理停止接入；本次增加 MaxSessions，在 WebSocket 升级前限制已登记且尚未清理完的会话数，满载返回 503，清理后允许复用名额。

验收重点是并发接入是否突破配置、拒绝请求是否错误扣减已有名额、清理后是否能恢复接入。配置默认值 64 是开发保护值，本实验使用 4，不推断生产容量。

## Action / Trade-off

1. 复用 tracker 的 mutex，在同一临界区检查停止状态、容量和增加计数；避免检查后再登记的竞争窗口。未增加独立信号量或会话注册表。
2. 满载直接拒绝，不增加接入等待队列。代价是客户端当前尝试失败；收益是无需长期持有等待名额的会话。拒绝请求仍有 HTTP/TCP 处理开销，本机制不限制全部连接数。
3. 沿用清理完成后的 leave，升级失败也归还名额；end 和取消通知本身不归还名额。测试专门验证拒绝不扣减计数、等待尾部结果仍占位。
4. 先固定验收口径，再执行五轮真实连接实验。保留所有尝试的状态、原因与计时，不只统计成功会话。

## 环境与步骤

Go 1.26.5，macOS 26.6.2，Apple M2 Pro，32GiB 内存，12 个逻辑 CPU；未设置 GOMAXPROCS 环境覆盖。客户端、Gateway、Mock 在同一进程，通过本机 TCP 使用 WebSocket 和 gRPC。正式五轮未启用 race；同时运行了独立的全量 race 回归，因此此处耗时只是附带观察，不用作延迟基准。

在同一个 Gateway 上重复五轮：

1. 配置 MaxSessions=4，用启动屏障同时释放 20 个 Dial 调用。
2. 所有成功接入的客户端先不发送 start，也不主动退出，直到 20 个尝试都已返回；记录每次握手的状态、拒绝原因及耗时。
3. 检查持有名额数为 4，并确认尚未创建任何新增 Worker RPC。成功接入的会话此时处于等待 start 阶段。
4. 让 4 个会话各发送 start、一块 3200 字节 PCM、end；检查 Worker 收到的音频内容、正常退出、唯一 final 与 WebSocket 正常关闭。
5. 等待本轮所有 handler 返回后，检查 active=0。重新接入 1 个会话并完成同样流程，再次检查 active=0。

每轮的 max_observed_active 是收集 Dial 结果时在锁内读取的最大值，不是连续追踪全部状态变化。另有 tracker 并发单元测试，以及所有已接纳连接持续占位后的计数校验，共同验证上限行为。

总计 **100 次突发尝试：20 次接纳、80 次容量拒绝、0 次其他错误**。20 个已接纳会话都正常完成；单独计数的 5 次重新接入也全部正常完成，共完成 25 条真实 gRPC 识别流。每轮等待 start 时新增 Worker RPC 为 0；两次清理检查的 active 均为 0。成功完成不依赖服务取消兜底。

80 次容量拒绝从 Dial 调用到返回约为 0.899–2.977ms，包含本机建连和调度。该范围来自这一次五轮验收，不是 SLA、吞吐量或生产延迟承诺。

验证结果：

- `go test -race ./internal/gateway -run '^TestAdmission' -count=3` 通过，包含配置、并发登记、停止、拒绝不误释放、升级失败归还、真实接入与尾部占位测试。
- 全量 `go test -race ./...` 通过；Gateway 实际执行，Mock 使用已有 Go 测试缓存。
- 正式五轮实验通过，失败次数为 0；日志保留了 80 次预期拒绝及其错误内容。

## Think

这次能量化的成果是：把接入行为约束为明确的配置边界，在受测突发负载下保持 4 个名额、拒绝超额请求，并在清理后恢复可用名额。没有测量改造前后的内存或 CPU 差异，因此不声称资源消耗降低了某个百分比。

“收到 503”本身不足以证明保护正确。此前实现检查发现拒绝分支缺少 return，会继续执行 leave；只有同时验证拒绝后计数不变，才能防止悄悄放大接入量。

本实验的音频很短，目的在于验收接入和生命周期规则。它不能证明 64 个长时问诊能稳定运行，也不能保证多个网关共享 Worker 时不过载。单会话积压、发送成功后的识别落后及其他等待边界仍需继续处理；稳定容量由第五阶段实验确定。

# EXP-005-12：异速 Worker 的普通轮询与静态加权对照

## 问题与选择依据（正式运行前固定）

EXP-005-11 的两个单名额 Worker 分别每块处理 10ms / 20ms，普通轮询在 10/12 并发均未达标；慢实例有大量占用与等待，快实例仍有空闲快照。已经实现的静态平滑加权轮询能按 2:1 选择新会话，但正确分配不等于性能改善。本轮要验证：只改变策略及其权重，是否改善完整完成率、达标批数和逐实例等待情况？

直接与旧结果比较省时间，但旧实验早于加权接入，无法保证程序相同；全部轮询后再全部加权容易受机器状态随时间变化影响。本轮重新运行两种策略，采用三轮相邻对照，轮询→加权、加权→轮询、轮询→加权。每组重新启动 Gateway 和两个 Worker。这减少组间历史积压和顺序影响，但三轮顺序并不完全平衡，也没有主机隔离，不能作为统计显著性证明。

2:1 来自已知的模拟逐块耗时差异，是一个待验证的静态比例，不是已经测出的最佳权重。最少活跃会话策略无法直接表达单场在快慢实例上的成本差异；实时指标调度需要额外处理采样滞后和变化。因此先检验较小改动是否有效，动态调度暂不加入本实验。

## 固定条件与运行顺序

- 每组两个独立 Worker，各一个处理名额；有序 Worker 1 为 10ms/块，Worker 2 为 20ms/块，结果延迟均 5ms。Mock 每场四条 partial，最后返回固定 final。
- 普通轮询显式设置 `-worker-strategy=round_robin`，不传权重；加权显式设置 `-worker-strategy=weighted_round_robin -worker-weights=2,1`，权重与有序实例对应。
- 三轮各两组，顺序 RR/W、W/R、RR/W。每组 8→10→12 并发各一批，每场 20 秒、640000 字节、每 100ms 发 3200 字节。共 18 个正式批次、180 次会话尝试；每种策略每档三批。
- 每组另有两场各两秒预热，不计入业务结果。预热和正式批次沿用同一个选择器，不重置选择位置；有限前缀的实际分配受位置影响。没有逐会话实例分配观测，不以名义比例推断实际活动比例或失败归属。
- Gateway 待处理音频上限 32000 字节，最大会话数 64；开始/空闲/Worker 发送/尾部/结果写回预算分别 10/30/2/15/2 秒，消息上限 1048576 字节。
- 会话期限 35 秒；正式批次采样 40 秒、预热采样 10 秒；Gateway 串行查询间隔 100ms，Worker 各 20ms，单次查询预算 1 秒。三个来源都观测空闲后才开始负载。
- 六组源码、二进制 SHA、Go/OS/硬件及运行参数必须一致。每组独立构建同一代码，分析拒绝任一二进制或条件漂移。预计约 13 分钟，使用本次命令范围内的 caffeinate 防止休眠。

## 判据、指标与证据

业务每批须同时满足：全部会话完整完成、成功会话尾部 p95 ≤250ms、逐会话最大发送排期落后 ≤100ms。尾部是 end 后等待最终结果的时间，不是逐块转录延迟。业务失败不停止后续批次，全部保留在分母；各策略同档合并成功原始样本重算 nearest-rank p95，不能平均三个批次的 p95。完成率差用百分点表达，成功者不同的尾部分位数不宣称为配对延迟收益。

数据质量与业务达标分开：负载窗口内零失败查询，覆盖窗口的有效观测间隔 ≤500ms，每批前后 Gateway 和两个 Worker 均有空闲观测，采样器自然结束、后端退出 0。采集错误保留整次尝试并退出，不替换差批次。窗口外查询失败也保留并说明。

保存六组逐会话报告、三个来源 JSONL、实际启动命令与日志、逐实例配置、源码/二进制/工具哈希和退出记录。根分析在临时副本重新分析六组，要求与保存的分组结果一致，再分别按策略和相邻轮次对照。Worker busy/waiting 是快照样本占比，不能当作时间或 CPU 利用率；异步峰值不能相加，也没有等待时长、队列字节或 CPU/内存测量。

本轮只回答固定 Mock、有限批次下策略是否改善，不能给出真实 ASR/生产容量，也不能据此确定精确容量边界或长时稳定性。若短时候选档位达标，下一步再预定义延长观察。

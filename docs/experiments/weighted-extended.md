# EXP-005-13：加权12并发的两分钟观察

## 背景与选择依据（运行前固定）

EXP-005-12中，相同两个单名额Worker（10ms / 20ms）下，静态2:1加权在8/10/12并发各三批20秒均达标。12并发由普通轮询30/36完成变为加权36/36完成，但20秒不能说明处理落后是否会随时间累积。本轮固定12场，验证延长到120秒后是否仍完整完成并满足实时性判据。

备选方案：继续提高并发用于寻找边界；延长已通过档位用于检查持续表现；再跑双方长时对照能比较120秒条件下的策略差异，但成本更高。本轮先选第二种：12是上一轮最高的已测加权达标档位，先为已有改善补充较长观察，不同时改变负载与时长。两批属于有限重复筛查，不是统计显著性或临床长时稳定性证明。

本轮只运行加权，不新增普通轮询长时组，不能把短时轮询与长时加权直接计算为新的策略收益。当前Mock耗时是模拟等待，不代表真实ASR推理资源。

## 固定条件与选点规则

- 来源为已完成的六组短时策略对照 `strategy-comparison-2026-10-03-retest-1`，必须在副本重新分析全部来源，核对根分析与原始哈希。8/10/12各三批加权须全部达标，完整分母及结果一致；按规则选择最高已测档位12，不按本轮结果修改。
- 两个独立Worker，各一个处理名额，Worker1每块10ms，Worker2每块20ms，结果延迟均5ms；Gateway使用 `weighted_round_robin`，有序权重2,1。
- 一次启动同一组后端，先两场各两秒预热，随后两批12并发、每场120秒，24次正式尝试。每场3840000字节、3200字节一块，每100ms发送，共1200块。
- 批次之间不重启后端、不重置选择器；每批三个采样来源先观测空闲再放行。预热推进选择位置；每批12次选择是3的整数倍，但没有逐会话Worker绑定观测，不将名义比例当作实测分配。
- Gateway待处理音频上限32000字节、最大会话64；开始/空闲/Worker发送/尾部/结果写回期限10/30/2/15/2秒，消息上限1048576字节不变。
- 会话期限从35秒扩大为140秒，正式采样窗口从40秒扩大为150秒；预热采样仍10秒。Gateway查询间隔100ms，两个Worker各20ms串行查询，单次预算1秒，覆盖间隔预算500ms。
- 新运行的Go源码哈希、Worker配置、Gateway业务预算、策略、权重、Go/OS/硬件和Go环境设置须与短时来源一致，漂移在构建/监听前拒绝并保存错误。提交工具前未修改Go业务代码。
- 重新构建并记录五个二进制SHA；工具提交及构建版本记录变化，不要求与上一轮二进制逐字节相同。跨实验一致性依据业务源码SHA及运行条件，不声称跨实验二进制相同。

预计约五分钟。使用本次进程范围内的caffeinate防止休眠，不修改永久系统设置。

## 判据、问题与证据

每批业务达标：全部会话完整完成、成功尾部nearest-rank p95 ≤250ms、逐会话最大发送排期落后 ≤100ms。尾部为end后等待最终结果，不是逐块转录延迟。失败保留在24次总分母；合并成功原始样本重算分位数，不平均两批p95。

3. 是否出现积压保护失败？批次结束与停服后是否正常回到空闲？

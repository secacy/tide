# EXP-005-14：加权16并发过载候选及新会话可用性

## 背景、方案选择与目标（运行前固定）

2:1静态加权已在异速Mock（10ms / 20ms、各一个处理名额）下通过12并发20秒三批及120秒两批。但尚无加权策略的高负载失败证据：输入超过处理能力时，是否触发明确保护，失败会话能否释放资源，后端能否继续接受新会话？本轮补这组证据。

备选方案：细测13/14/15并发可寻找更精细的短时边界，但增加档位与重复次数；直接测试较高固定档位更适合验证失败与清理；运行中注入变慢会同时改变实例能力和故障时刻。本轮选择固定16并发三批，每场20秒。每场每秒输入10块，总160块/秒；忽略调度及其他开销，两台Mock按10ms/20ms逐块等待估算最多100+50=150块/秒，因此16是过载候选。这个推算是选点依据，不是实测生产容量或准确失败时刻。

每批之后追加两场各两秒的新会话，证明“观测空闲”之外是否还能完成下一次请求。两场短探测比再跑整批12场成本低，但只能证明低负载新会话可用性，不能证明立即重新承受12场或原失败音频得到恢复。重连、重放与结果去重属于第六阶段。

## 条件与来源

- 来源为完整 `weighted-extended-2026-10-03`：12并发两批120秒须24/24完成、2/2达标；读取前核对根分析引用，在副本重新分析全部原始证据，并记录其短时来源链。选点固定16，不接受失败或中断的来源。
- 两个独立Mock Worker，各处理名额1，Worker1逐块10ms、Worker2逐块20ms，结果延迟5ms；Gateway加权策略、有序权重2,1。整轮复用同一组后端，不在失败后重启或重置选择器。
- 先两场各两秒预热，随后按“16场过载候选 → 两场短探测”重复三轮。正式候选48次尝试，探测6次，分别统计；预热另两次不计入任何正式分母。
- 正式每场640000字节、3200字节一块、每100ms发送，共200块/20秒，会话期限35秒，采样40秒。
- 每次探测两场，每场64000字节、20块/2秒，客户端期限5秒、采样10秒。探测也记录失败，不删除或混入16场正式完成率。
- Gateway最大会话64、待处理音频上限32000字节、消息上限1048576字节；开始/空闲/Worker发送/尾部/结果写回期限10/30/2/15/2秒不变。探测的客户端5秒期限不修改Gateway业务期限。
- Gateway串行查询间隔100ms，两个Worker各20ms，单次查询预算1秒。每个批次及探测开始前，三个来源均先观测空闲，再放行输入。
- Go源码哈希、Worker及Gateway配置、策略/权重、业务判据和Go/OS/硬件及Go环境须与来源一致，漂移在构建/监听前停止并保存错误；五个新构建二进制SHA单独记录，不要求与旧版本元数据的二进制逐字节相同。

预计约三分钟，使用仅限本次进程的caffeinate保持唤醒。未修改Go业务代码，所有新工作为实验工具、测试与文档。

## 判据与预期观察

沿用逐批判据：全部会话完整完成、成功尾部nearest-rank p95 ≤250ms、逐会话最大发送落后≤100ms。正式48次均保留，成功尾部单独统计且不得替代失败计数。探测按同样完成/尾部/发送判据判断，但固定较短输入与客户端期限，6次另列。

数据质量与业务是否达标分开：三个来源负载窗口内零失败查询、覆盖有效观测间隔≤500ms、每批前后空闲；所有采样器自然结束，后端正常退出0。若采集不合格，保留全部尝试，不产生有效性能结论；业务失败不停止预定批次、不替换重测。即使16场三批都达标，也记录“本档未观察到过载”，不会临时提高负载制造失败。

重点保存完成/失败数、错误原因及发生时刻、实际输入量、成功尾部、发送节奏、活动会话与逐实例处理/等待快照。按五秒分段观察失败后负载如何下降，避免把失败后低延迟当作承受原始16场的证据。已有“批次退出后首个空闲快照完成的间隔”是离散观测值，不能作为精确资源清理或故障恢复时间。

需要区分三个结论：积压保护确实触发；结束后活动会话及处理/等待名额归零；后续短会话完整完成。三者都需要各自证据。waiting不是排队时长或积压字节；busy不是CPU/时间利用率，异步峰值不能相加。当前没有逐会话Worker绑定观测，不能把某次失败归因给具体实例，也不宣称测量了内存上界。

## 收获与下一步

本轮分别验证了三个事实：16并发三批都未达标且七次触发明确积压保护；全部批次结束后服务端活动会话与处理/等待均归零；同一后端的后续六次低负载新会话完整完成。保护触发不代表原业务成功，也没有自动恢复被丢失的音频。

结合此前12并发短时与两分钟达标证据，现在有“已验证12场”与“已测16场过载”两个参考点，13–15未测，不能给出精确加权边界或把12直接称为最大容量。固定Mock/有限批次也不是临床问诊、持续到达、动态抖动或真实ASR容量。

下一步汇总第五阶段运行点、资源与策略两类对照、延长观察和过载证据，整理STAR+T及验收范围，再设计第六阶段重连、有限音频重放与结果去重。是否补精细边界由明确目标决定，本轮不继续临时增加实验档位。

# 第六阶段：会话身份、注册表职责与身份部件

日期：2026-10-05。状态：设计与实现指导，等待开发者实现身份部件；注册表尚未实现。当前依据 `2be0e77`、[恢复契约](2026-10-04-session-resume-contract.md)及 [ADR-003](../adr/003-session-admission.md)。

## 为什么现在需要身份与注册表

resumeState 可以判断某个会话是否允许接回，但新 WebSocket 尚不知道该向哪个会话提出请求。现有 tracker 只保存数量；现有 session 是一条 WebSocket 与一条 Worker 流的桥接对象。跨连接恢复需要稳定的逻辑会话身份，以及从身份找到仍存活会话的入口。

三种值职责不同：sessionID 定位问诊；resumeToken 是接回凭据；generation 隔离同一问诊的新旧连接事件。重新附着后 ID 与凭据保持不变，generation 递增。ID 不包含患者姓名、病历号或诊疗内容，知道 ID 不表示有权恢复。

## 身份方案与选择

| 方案 | 好处 | 代价与选择 |
| --- | --- | --- |
| 只有普通 ID | 查找简单 | ID 无法同时承担可记录标识和秘密凭据的职责 |
| 一个不可预测的秘密同时作 ID 与凭据 | 字段少、可直接索引 | 每次按 ID 记录日志都会携带凭据，需要始终把该 ID 当秘密 |
| 随机 ID 与独立随机凭据 | 可以记录 ID 排查问题，凭据单独校验 | 增加一个字段和校验步骤；本轮建议采用 |
| 自包含签名凭据 | 可在多个实例统一验证签名 | 仍需找到进程内 Worker 流，且增加密钥、失效及声明语义；当前没有对应需求 |

拟使用 16 随机字节编码为 32 字符小写十六进制 ID；另用 32 随机字节编码为无填充 URL-safe Base64 凭据，共 43 字符。长度为本轮明确的工程选择，不是容量或性能结论。生产调用传入 crypto/rand.Reader，不能使用时间戳、计数器、math/rand 或从 ID 推导凭据。

随机 ID 仍不能当作数学上的唯一性保证。注册表插入时必须检测冲突、禁止覆盖；后续创建入口可采用有限次重生成或返回明确创建错误。身份部件本身不循环查询或访问全局注册表。

凭据在当前进程内保存原值以供比较；不记录凭据或整个身份对象到日志，也不放在 URL 中。若以后引入持久化或跨进程存储，再决定保存摘要、轮换和失效方案。它仅证明持有本次会话凭据，不替代将来的医生账号认证和授权。

## 注册表方案与所有权

| 方案 | 收益 | 代价与当前选择 |
| --- | --- | --- |
| map + mutex | 插入、查找、条件删除的规则集中，便于验证 | 全局临界区必须短；本轮建议从单把 Mutex 开始 |
| sync.Map | 提供并发键值操作 | 仍需设计身份冲突、引用有效性及复合操作；现阶段没有测量依据支持更换 |
| 分片 map | 可减少独立键操作争用 | 增加分片和全局管理复杂度；测到注册表锁竞争后再评估 |
| Redis/数据库 | 可共享或持久化元数据 | 无法把仍在原进程里的 gRPC 流一起搬过去；需要额外路由和恢复语义 |

拟定职责如下，当前只用于后续设计，不在本步写空注册表或占位逻辑会话类型：

- **注册表**由 Gateway 持有，保存 ID → 逻辑会话引用，负责并发安全的插入、查找与移除。全局锁只保护映射，锁内不进行网络 I/O、不等待协调者、也不执行资源清理。平均查找成本随 map 操作，而不是遍历全部会话；尚未测量高并发锁开销。
- **逻辑会话协调者**独占可变的 resumeState、Worker 流及未来音频/结果进度。身份创建后不变。查找到引用不表示恢复已成功，调用方仍须向协调者提交请求，由其再次判断状态、期限和停止条件。
- **连接 handler**完成协议握手与凭据检查，并请求附着。它不能拿到会话引用后直接调用 resumeState.resume，否则两个连接会竞争这个非并发安全部件。
- **生命周期与准入**区分新建和恢复：新建逻辑会话占名额，保留期间不释放，成功接回不再占第二个逻辑名额。连接握手另有限制，防止请求尚未识别身份前无约束堆积。现有 ServeHTTP 的 tryEnter/defer leave 绑定 handler 生命周期，接入时必须重新安排所有权，不能原样复用为逻辑会话计数。

并发例子：连接 A 查到会话引用后，协调者因超时关闭会话；随后 A 发来的恢复请求必须被协调者拒绝。Go 引用仍有效不代表业务资格有效。删除只阻止未来查找，不能撤回其他调用方已取得的引用。未来移除接口应核对当前记录仍是预期对象，避免迟到的清理误删后来记录。

终止时先在协调者中结束恢复资格，再结束/撤销注册入口并清理 Worker 及附属资源，清理完成后释放逻辑名额。已完成结果的有限重取记录需要单独定义保留与容量，不把结果保留等同于 Worker 仍在工作。服务停止时，注册表、创建准入与协调者取消必须共同遵守停止规则；本步不声称已有此集成。

## 本次实现：sessionIdentity

新文件：`internal/gateway/session_identity.go`。只写身份值、构造和凭据比较，保留函数及字段注释。不要在本步修改现有 session、tracker 或 WebSocket v1 消息。

```go
// sessionIdentity 保存一场逻辑会话的稳定标识和恢复凭据。
// 由 newSessionIdentity 创建，发布后保持不变，可供并发读取。
// 不得将整个对象或 resumeToken 写入普通日志。
type sessionIdentity struct {
    id          string // 16 随机字节的小写十六进制编码，用于定位会话。
    resumeToken string // 32 随机字节的无填充 URL-safe Base64 编码，用于验证恢复请求。
}

// newSessionIdentity 从 random 读取随机材料并创建身份。
// 生产调用必须传入 crypto/rand.Reader；测试可传可控 Reader。
// nil 接口或读取失败时返回零值身份和错误，不返回部分生成的身份。
// 不访问注册表、不检查全局唯一性，也不启动后台任务。
func newSessionIdentity(random io.Reader) (sessionIdentity, error)

// matchesResumeToken 检查 candidate 是否与当前恢复凭据完全相同。
// 零值身份、空值、长度错误或内容不匹配均返回 false。
// 不修改身份、不更新恢复期限，也不代表会话仍可恢复。
func (i sessionIdentity) matchesResumeToken(candidate string) bool
```

构造实现步骤：

1. 拒绝 nil Reader 接口。调用方负责传入可用 Reader；本步不引入反射以识别含 nil 指针的任意 Reader 实现。
2. 用固定大小的 48 字节数组保存随机材料，使用 io.ReadFull 完整读取。Reader 一次返回不足 48 字节且无错误时，ReadFull 会继续读取；不能把第一次短读直接当失败。
3. 读取失败返回 `sessionIdentity{}` 和包含 `%w` 的上下文错误，使测试和调用方能用 errors.Is 检查原因。读取不完整时不编码或发布部分身份。
4. 前 16 字节使用 hex.EncodeToString；后 32 字节使用 base64.RawURLEncoding.EncodeToString。不得从同一段字节分别编码 ID 和 token，否则公开 ID 会暴露凭据材料。

比较实现步骤：先要求存储值和 candidate 都是 43 字节，再用 subtle.ConstantTimeCompare 比较字符串字节，结果为 1 才成功。存储值来自构造器，精确匹配即可，不必再解码输入。不得 TrimSpace 或忽略大小写；空 token 与空 candidate 必须返回 false。该比较不授权调用方直接修改会话状态，真实恢复仍由协调者判定。

使用标准库已在本地 Go 1.26.5 文档核对：io.ReadFull 负责完整读取；crypto/rand.Reader 是可并发使用的安全随机源；ConstantTimeCompare 对相同长度输入的比较时间不依赖内容。这里只选择并核对 API，没有运行身份实现测试。

## 助手后续验收

实现后由助手补测试：固定字节序列的精确编码、ID/凭据来源分离、Reader 多次短读、零字节 EOF、部分 EOF、自定义错误可追溯、失败时零值返回、正确/错误/空/不同长度/首尾空格凭据、零值身份拒绝，以及独立身份互不匹配。测试不以随机生成多次未碰撞证明唯一性，也不比较纳秒级时间来证明安全性。

身份部件无可变共享状态，不需要给它加锁。注册表 map 的并发安全和每个逻辑会话的串行状态管理是下一步的独立问题。身份验收后再明确逻辑会话引用/命令入口与注册表接口，然后实现注册表及竞争测试；暂不引入外部存储或修改 Worker 选择规则。

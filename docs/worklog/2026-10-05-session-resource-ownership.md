# 第六阶段：连接交接与资源清理所有权

日期：2026-10-05。状态：设计约定，尚未接入运行链路。依据 `f68e888`、[恢复契约](2026-10-04-session-resume-contract.md)和[自动到期验收](2026-10-05-session-expiry-timer.md)。核心实现继续由开发者完成，助手负责测试与记录。

## 当前问题与目标

当前 session.run 将一个 WebSocket 与一个 Worker 流绑定；finish 在客户端断开后取消 RPC，ServeHTTP 返回时通过 defer tracker.leave 归还名额。该结构符合 v1 断开即结束的行为。可恢复会话需要跨越多条连接，因此必须调整 Worker、会话名额及最终清理的拥有者。

已有 requestResume 只完成连接保留状态变化，尚未安装真实 WebSocket、完成数据追平或交付恢复响应。不能在外部调用成功后直接并发修改旧 session.ws，就把它视为完整的连接交接。

目标是让临时连接的退出与整场问诊的终止分开：断线时保留原 Worker 和连续数据状态；期限到达或不可恢复失败时统一终止、等待资源退出，最后归还名额。

## 方案比较

| 方案 | 优点 | 代价及决定 |
| --- | --- | --- |
| 原 handler 一直保留，新 handler 把连接交给它 | 可保留原调用栈和部分清理逻辑 | 原 HTTP handler 实际兼任逻辑会话运行器，后续连接责任和停服等待仍要重划；可行，但不采用其隐含所有权 |
| 独立逻辑会话运行器持有 Worker 和名额，各连接只负责本代 I/O | 生命周期与问诊一致，断开、恢复、终止职责明确 | 要拆分目前 upload/download 与 WebSocket 的直接绑定；采用 |
| 每次恢复重建 Worker，再重放音频 | 每条连接容易独立清理，能探索原流丢失场景 | 有限缓存不一定重建模型上下文，无法直接沿用原接纳位置；留待实例异常方案 |

独立运行器不要求再叠一层永久调度协程。最终把现有控制命令、Timer、Worker 事件整合到逻辑会话的唯一协调者；已有 runControl 是这条控制路径的基础。I/O 在独立任务中运行，结果以事件汇报，协调者不直接执行阻塞读写或等待任务退出。

## 所有权划分

| 资源或状态 | 拥有者 | 单次连接断开时 | 整场终止时 |
| --- | --- | --- | --- |
| WebSocket、该代读取/写入任务及 context | 一次连接附着对象，受协调者管理 | 取消/关闭本代连接并回收任务 | 对仍持有的连接执行相同清理 |
| 原 Worker stream、RPC context、唯一上传与接收任务 | 逻辑会话 | 保持运行；没有新音频不等于输入结束 | 取消 RPC 并等待任务退出 |
| 音频接纳位置、输入结束位置、结果序号与有限缓存 | 逻辑会话 | 保留，继续执行容量限制 | 释放；必要终态记录交给独立的有界保留机制 |
| 逻辑会话准入名额 | 逻辑会话运行器 | 继续占用，恢复不再申请一次 | 资源退出确认后恰好归还一次 |
| 会话 ID 到对象的映射 | 注册表存储，逻辑会话运行器负责撤销 | 保留以供恢复查找 | 结束恢复资格后条件删除 |
| 尚未完成握手的临时连接名额 | 握手入口 | 握手失败时归还 | 与逻辑会话名额分别管理 |

RPC context 继承服务/逻辑会话生命周期，不能继承某次 HTTP 请求或 WebSocket 的取消。连接 context 可继承逻辑会话生命周期，使整场终止能停止连接；取消连接不会反向取消逻辑会话。

注册表负责查找，tracker 负责尚未清理完成的计数。映射先删除、名额稍后归还的清理期间，两者数量允许不同。

## 断开与重新附着的顺序

1. 当前代连接发生可恢复的传输故障，向协调者报告代次及原因。协议错误、Worker 错误、积压超限及停服等仍按终止处理，不能统一伪装成可恢复断线。具体传输错误分类和断连检测期限在接入时验证。
2. 协调者使该代失去提交新输入的资格，转入 detached，关闭旧连接并安排其任务退出，启动已有恢复窗口。断开不调用 Worker CloseSend；只有接纳合法 end 才半关闭输入。
3. 后续音频、end、结果确认和断开事件都携带代次；协调者按当前附着状态与代次校验。只过滤旧断开事件不足以隔离旧连接。旧连接已经成功交给会话的音频仍归会话所有，由同一个 Worker 上传任务继续处理。
4. 新连接先完成有期限、受准入限制的握手及凭据校验，再提交带候选连接的附着命令。仍 attached 时拒绝抢占；需要客户端在重试期限内再试。
5. 最终附着命令需在同一串行处理段完成恢复资格判断、代次分配及候选连接安装，再回复明确结果。网络握手确认写入另行执行。当前无连接参数的 requestResume 仅是状态部件，真实接入前必须扩展，不能把“修改状态”和“安装连接”分散给不同协程。
6. 附着被接受之前，候选连接由握手方清理；接受之后，清理责任转交逻辑会话。若接受后握手响应写入失败或请求取消，必须报告新代次连接失效，由会话重新进入保留或终止，不能遗漏已成功的状态变化。

旧连接任务可能还在退出，新连接已开始握手。它们不得直接共享调用 Worker Send，也不得通过可变 session.ws 指针读取“当前连接”。连接只操作自身句柄，Worker 上传保持唯一发送者；临时/退出中连接也需要受连接侧预算约束，不能因逻辑会话名额没增加就认为资源有界。

## 断线期间的数据去向

Worker 接收任务继续读取响应，将处理进度计入逻辑会话，将识别结果写入有序、有界的结果保留区；连接写任务从该区投递。恢复后依据客户端已应用位置重发。不能丢弃结果，也不能使用无限 channel。

Worker 上传任务消费会话已接纳的连续音频。客户端有限缓存负责断线期间采集及尚未获得接纳确认的音频，恢复后按位置重放；Gateway 已接纳范围避免重复送入 Worker。缓存耗尽或位置出现无法补齐的缺口，明确失败。具体结构、字节/条目预算和线格式在后续协议小步确定。

已接纳 end 的尾部期限继续推进，重连不重置它。结果写入期限只约束实际连接上的一次 Write；无连接时改由恢复窗口、缓存上限和既有会话保护约束。正常完成通知需要有限保留，否则客户端可能把丢失的完成通知误认为问诊丢失；终态查询/确认和期限属于端到端接入的必备项。

## 最终清理顺序

```text
结束恢复资格，停止接纳该会话的新操作
    → 停止恢复 Timer，撤销活动注册表映射
    → 取消 Worker 和连接 I/O，主动关闭可解除阻塞的连接
    → 等待全部已拥有的任务退出
    → 释放运行缓存，归还逻辑会话名额
    → 发出整场清理完成通知
```

由唯一生命周期拥有者执行这个顺序。清理等待放在控制循环退出后的收尾路径；I/O 任务汇报事件也必须能够因会话停止退出，不能循环停止后仍永久卡在向它发送事件。资源获取时即明确对应释放者；启动失败按已经获取的资源回退，登记失败不得删除同 ID 的其他对象。

controlDone 保留原义：控制循环及恢复资格已结束。后续增加的整场清理完成信号须在 Worker、连接任务退出和名额归还之后发出，命名与 controlDone 区分；等待方超时不代表这些工作已完成。现有 requestClose 仍只等待 controlDone，不能悄悄改变已验收的语义。

活动注册表撤销后如需返回“已经正常完成”，由有限终态记录承担，不能保留仍持有 Worker/名额的整个对象。终态记录仍须凭据校验、明确 TTL 和容量；本步只是确定职责，没有实现该缓存。

停服需要同时禁止新建与恢复交接，再取消并等待逻辑会话。逻辑会话满额时，已有会话恢复不重新申请逻辑名额，但仍须通过连接握手预算；因此不能直接照搬当前 ServeHTTP 最前面的单一 tryEnter。该入口改动与真实恢复一起验收。

## 实现顺序与本步边界

本步完成设计，不新增空的资源管理接口、cleanup 回调框架或第二套永久协调循环。已有纯状态、身份、注册表和命令部件开始按这里的所有权组合，真实网络切换前先补齐数据连续性规则。

接下来分为四个可验收小步：

1. **v2 音频位置与接纳规则。** 定义连续范围、新数据/完整重发/缺口/部分重叠及溢出处理，以及带音频终点的 end。明确确认发生在有界所有者接管之后；先验证规则，再决定线格式与实际缓冲。
2. **有限重放与结果投递。** 客户端音频缓存，Gateway 结果序号、确认和有限保留；明确终态通知以及缓存耗尽的失败行为。
3. **连接交接与会话运行器接入。** 将已存在的控制循环和数据通路整合，接入原 Worker 保留、候选连接安装、双层准入及统一清理，逐项替换 v1 生命周期责任。
4. **真实断连验收。** 注入窗口内/超窗断线、恢复与到期竞争、缓存耗尽、Worker 失败和停服；记录音频重复/缺口、结果重复应用、恢复率和耗时及资源归零。

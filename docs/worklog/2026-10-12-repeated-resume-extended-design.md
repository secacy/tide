# 多轮恢复延长观察：设计与下一实现单元

日期：2026-10-12。对应 [EXP-006-05 预登记](../experiments/repeated-resume-extended.md)。本步只完成实验和工具设计，未执行十分钟实验或修改恢复策略。

## 当前问题与方案选择

短场景已证明“接回后正常传输，再次断线”的组合规则。接下来需要把时间拉长，观察跨轮等待和资源趋势。现有 `resumeRecorder` 保留 SourceReads、Frames、Applications、Samples、Worker.Audio 等全量切片；十分钟期间这些数据会增长，整进程堆曲线会混入记录器保留量。

| 备选 | 优点 | 代价与本次选择 |
| --- | --- | --- |
| 原六秒夹具直接延长 | 最少改动，原始数据丰富 | 保存全量音频/事件影响堆趋势；不采用作本轮资源证据 |
| 独立部署 Client/Gateway/Worker，再引入外部故障工具 | 便于隔离进程资源，更接近部署链路 | 需要跨进程计时、故障同步与观测接口；留作后续，当前问题可先用已有公开链路解决 |
| 新增专用多轮夹具、流式证据与独立分析 | 可复用真实网络和协议路径，按轮核对；记录空间有明确边界 | 增加测试工具，需要先验证写盘和计时；本轮采用 |
| 直接改成每轮重置次数 | 可以避免长会话逐轮消耗全场预算 | 会改变产品语义，掩盖当前边界；先测五次/八次的实际跨轮行为，再讨论策略 |

采用单场十分钟、六轮 500ms 故障，预算八次与五次，加一个同配置无故障参照。六轮分别位于 30/120/210/300/390/480s；两轮反向顺序，总计六场。八次保留少量意外重试余量，不代表生产推荐；第五阶段容量与 jitter 优化不同时叠加到本轮。

## 工具职责及资源所有权

1. **按位置生成源与在线校验 Worker。** 每块用文档固定算法生成，仅持有当前块和增量摘要；Worker 逐字核对下一块、发送处理进度及位置结果。独立分析器按块号另行生成摘要，发现工具两端共同偏移。来源和 Worker 处理分别记录，失败不伪装完整。
2. **多轮故障代理。** 原音频 offset 对应唯一故障编号；当前轮切断和到期开放均有事件，重放不能再次触发同一轮。代理中的连接任务和故障计时任务分开拥有退出通知；即使客户端次数耗尽不再连接，开放任务也必须退出。
3. **有界事件写入器。** 单独 goroutine 顺序写 JSONL；生产者提交不可变值，包含单调经过时间和组件内序号。建议队列 1024 条、每条编码上限 8KiB，bufio 64KiB，完整配置入清单。队列满或写入失败记独立原子首错并取消本次测量，绝不阻塞业务等磁盘，也不丢事件后宣布成功。失败通知不能依赖已经满的队列。
4. **独立采样任务。** 从线程安全计数和现有 Gateway 快照观察资源，每 100ms 串行采样；保留采样开始/结束、失败和队列压力。全链路共享一个单调原点，避免 JSON 时间丢失单调读数后混算间隔。
5. **采集器与独立分析器。** 一个冻结构建、每场独立测试进程、固定顺序，保存所有场。分析时读取完整事件与配置自行推导指标，保留失败分母；以日志分段和独立产物替代超大单条测试报告。

记录器清理由协调者负责：业务与自然清理观测结束后等待所有生产者退出，再关闭队列、等待写入器 flush/close，最后输出小型终态清单。若日志写入卡住，整体测试进程保护到期，由外部采集器保存已有文件并记不完整；不声称 context 能强制解除任意文件系统 I/O。成功报告必须同时具备生产者退出、记录器关闭及独立分析通过。

采集实时节奏仍由生产客户端的 `Realtime=true` 驱动。不同于短测试的 io.Pipe 屏障，本轮不能在故障或观察结果时暂停源；结果未追赶时保留事实，而不是等追赶后才启动下一故障。

## 下一实现单元与后续两步

下一步由助手实现**专用夹具和有界记录器，并让三组十二秒 probe 形成闭环**。配置、事件和逐轮状态均写清字段含义、所有权和完成信号；先验收源生成/位置校验、记录失败传播、故障不重复触发、次数边界以及自然清理。具体类型和方法在实现时围绕这些职责确定，无须改生产客户端 API。

随后接独立 Python 采集/分析与证据反例测试，核对逐场/逐轮/资源窗口输出和搬移复算；工具通过后冻结版本，执行预登记六场正式观察并归档。若发现观测契约无法实现，先修订预登记并解释，不能在看到结果后悄悄放宽判据。

本轮确切缓存占用无现成公共快照，暂以采集/接纳/处理位置和进程趋势观察。若这些不足以解释结果，再设计归属协调者发布的只读统计；不能通过跨 goroutine 读取私有缓冲字段制造竞态，也不能把位置差标成缓存实际使用量。

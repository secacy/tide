# 第六阶段：当前能力、量化依据与剩余验收

日期：2026-10-12。本步核对已有实现与记录，未运行新实验、修改业务逻辑或调整默认参数；这是阶段检查点，尚未将第六阶段标记为全部完成。

## 当前能力

同一存活 Gateway 和原 Worker 流仍保留状态时，客户端可以在有限时间与缓存内重连，补发未确认音频、接续结果并完成原会话；实例状态丢失时原场明确失败，服务重启后可显式创建独立新场。

这里的价值是把“连接断开”与“一次问诊结束”分开：短暂断网可以换连接继续，原音频位置、识别上下文及结果位置仍属于同一个逻辑会话。恢复超过预算或原状态已不存在时，保留失败事实，不能用新建会话掩盖原场缺口。

## 能力与证据对应

| 能力 | 已有依据 | 仍需区分的边界 |
| --- | --- | --- |
| 换连接继续原会话 | 独立逻辑会话、身份与注册表、连接代次、唯一 Worker 流；真实恢复测试核对原场选择与 RPC 数 | 注册表在内存中，不提供跨实例迁移 |
| 音频重放与结果去重 | 连续音频位置、累计接纳确认、客户端有界重放、结果序号和应用确认；覆盖音频/结果 ACK 丢失 | 接纳确认不等于模型已处理，更不是持久检查点；回调外部副作用不能据此承诺 exactly-once |
| 尾部正常完成 | end 绑定最终音频位置，结果保留以及 completed/completed_ack；覆盖 end、completed、恢复 ready 丢失 | 客户端写出确认不证明对端处理；已核实完成后的确认错误与未完成分别记录 |
| 有限恢复及清理 | 每轮固定恢复窗口、整场累计尝试次数、字节/条目预算、自然到期；有相关行为与真实网络测试 | 本地停止尝试不等于远端立刻释放，客户端与服务器预算独立 |
| 实例异常边界 | Worker/Gateway 受控退出、独立子进程 SIGKILL、原地址新 PID 重启后的独立新场 | 原场明确失败，尚无崩溃后原场无损恢复；退出原因和精确缺失音频范围的产品诊断仍有缺口 |
| 群体恢复及策略比较 | 共享入口八场同时断线，固定握手名额，次数预算和 jitter 同版本对照 | 六秒输入、一次可控故障、轻负载 Mock；未获得长时、多次断线或真实模型结论 |

## 关键设计与取舍

以下是对当前实现的回顾；不把本次补充的比较描述成当时已经做过的实验。

1. **将逻辑会话与连接分开。** 每次重连从头新建 Worker 流更容易实现，但旧识别上下文和音频处理位置会丢失。当前保留原流，只更换连接；代价是断网期间仍占用会话名额和 Worker 资源，因此必须有保留期限。
2. **用位置、确认和有界缓存支持补发。** 仅依赖网络写入成功无法知道对端到底接纳了多少；无限保留整场音频又会随问诊时长增长。当前按连续位置补发并排除已接纳范围，结果按序确认和释放；代价是需要处理确认丢失、连接交接和缓存耗尽，超出覆盖范围时明确失败。
3. **由单个会话协调者管理状态变化。** 相比多个读写任务分别更改连接、位置和结束状态，事件汇总到协调者更便于维持一致规则；代价是协调循环需要保持可响应，将网络阻塞交给有明确所有者与退出通知的任务。
4. **同时限制恢复时间和整场尝试次数。** 只有时间窗口时，快速拒绝可能产生很多请求；只有次数时，单次连接等待仍可能拖延。两种预算共同约束恢复。当前整场计数成功后不清零，规则简单、请求上限明确，但对长时反复断网可能过于保守。按故障轮次重置或采用滑动窗口都是后续备选，需要多次断线证据再决定。
5. **随机退避作为可选配置。** 固定退避便于解释，但群体可能同时重试；jitter 分散时点，也可能把一次本可成功的请求推迟。实验已同时观察到收益与等待退化，因此保留默认关闭，不能仅凭最大值改善选择生产默认。

## 可以用于阶段成果的数字

不同实验分别保留版本、条件及分母，不拼接成一个“整体恢复成功率”。以下数据来自已有正式报告，本步没有新增测量。

| 问题与条件 | 结果 | 可以支持的结论 |
| --- | --- | --- |
| EXP-006-01，单场六秒输入，500ms 可控断网，开/关恢复各三场 | 完整完成 0/3 → 3/3；500ms 和 2s 两组共六个恢复场均处理完整 192000 字节，结果 seq 1–61 各应用一次 | 当前同实例恢复在这些故障样本中保住完整输入与结果；不是网络成功率估计 |
| EXP-006-03，八场同时断线、握手入口占位 2s，固定退避/5s 窗口，五次与八次各三批 | 完整完成 0/24 → 24/24；请求 120 → 154（+28.3%）；成功均使用第六至八次机会 | 增加次数确实使这些场等到入口开放，成本是更多请求；不代表仅提高上限就普遍有效 |
| EXP-006-04，固定八次，500ms 占位，none/jitter 各四批 | 各 32/32 完成；请求 144 → 129（−10.4%），开放后拒绝 16 → 0；最大 partial 间隔 2626.574 → 1404.862ms（−46.5%） | 本轮随机退避减少争抢和观察到的最坏转录停顿 |
| EXP-006-04，相同策略比较，2s 占位 | 各 32/32 完成；请求 203 → 195（−3.9%），开放后拒绝 11 → 0；最大间隔下降 24.7%，但各场最大间隔的中位数增加 146.505ms（5.6%） | 减少拒绝与缩短典型等待不是同一件事；第四轮最大间隔也变差 |

证据入口：[单场正式对照](2026-10-09-client-resume-baseline-results.md)、[次数对照](2026-10-11-group-resume-budget-results.md)、[jitter 对照](2026-10-12-group-resume-jitter-results.md)。其中“最大间隔”是每场相邻 partial 结果的最大间隔再取组内最大值，不是 P99 或单条识别延迟。

另一个可核实的完整性结果：jitter 正式合格复测 16 批 128 场全部完整完成，24,576,000 字节输入、7,808 条结果逐场核对，无替代 RPC 或串场；16 批都在兜底清理前自然空闲。首次时间证据不合格的运行完整保留，未与复测拼接。它证明该次固定实验的完整性，不证明生产可靠性或无限期无泄漏。

## 尚未闭合的验收

最优先的是**同一会话多次断线，以及时间拉长后恢复状态与资源是否仍符合约束**。其他边界继续记录，不将其全部变成当前必须新增的功能。

- 当前正式恢复对照只有六秒、一次故障。已有 `TestV2ResumeWindowAndAttemptLimits/total_attempts_survive_success` 用模拟时间和替身验证“成功不清零”，已有恢复 ready 丢失的真实网络测试也涉及再次尝试；这些不能替代正常传输一段时间后反复断线的端到端观察。
- 受控关闭连接和握手占位没有覆盖网络黑洞、持续丢包、网络切换或任意弱网分布。
- 当前字节/条目预算及采样峰值不能证明整进程严格内存上界；长期趋势还要排除测试夹具持续保存日志和完整音频造成的增长。
- 实例失效后原场不可恢复是当前设计边界；真实 ASR 适配、识别质量与模型追赶能力属于第七阶段。
- Gateway 退出原因分类与面向用户的精确音频缺口诊断仍待完善，实验工具能核对缺口不等于客户端产品已具备同样的诊断能力。

## 下一步路线及选择

| 备选路线 | 价值与代价 | 本次判断 |
| --- | --- | --- |
| 继续扩大 jitter 参数与种子搜索 | 可增加策略证据，但不能回答长会话重复断线的正确性和累计预算问题 | 暂缓，当前已有足够证据说明收益及代价 |
| 直接启动数十分钟、多客户端、多次随机故障压测 | 更接近目标时长，但首次失败难以区分预算、协议、故障注入和资源问题 | 作为后续延长验证，不作第一个动作 |
| 先固定单场多次断线语义，再延长观察 | 先区分按契约耗尽和实现错误，短场景排错成本低，再验证持续运行 | 采用；先用真实 Gateway/Worker 链路补足组合证据 |

后续分三步推进，测试、工具与记录由助手完成；若发现需要改核心契约，先解释证据和方案，再由开发者实现，除非另有委托。

1. **短场景验证多次断线。** 同一个 Run 使用同一个源与原 Worker RPC；每次接回后先观察新音频结果，再触发下一次故障，避免把一次恢复握手重试误算成多轮断网。覆盖预算内连续接回、最后一次预算成功后正常结束，以及下一次断线耗尽且不再 Dial。预算可设为二次以缩短行为测试，但不当成生产建议。核对输入/结果位置跨连接单调推进、采集不因重连重启、源关闭一次、资源自然退出。明确失败场保留已采集、已处理和未采集范围。
2. **制定延长实验并验收工具。** 固定音频模型、观察时长、故障时间表、预算、重复轮次及失效判据；加入无故障对照，逐轮记录故障到 ready/新音频结果、最大 partial 间隔、累计尝试与剩余预算、缓存占用和资源清理。历史音频与事件尽量流式落盘，业务状态与夹具保留量分开，防止观测工具制造“内存泄漏”。本步只选定方向，具体时长与档位尚未预登记。
3. **执行延长观察并决定是否调整预算。** 完成与明确失败都保留；分别判断正确性、转录等待及资源趋势。若证据表明整场累计预算妨碍目标场景，再比较每轮预算、滑动窗口或分层限额；不要预先把“加大次数”当作修复。

进入延长实验前应能回答：每轮恢复是否沿用原场、是否补齐需要的音频/结果、为何停止尝试、何时真正释放资源。一次短测试通过不应被写成“已支持长时临床问诊”。

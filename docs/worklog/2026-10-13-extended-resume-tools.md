# EXP-006-05：独立采集与分析工具验收

日期：2026-10-13。关联[预登记](../experiments/repeated-resume-extended.md)、[Go 工具验收](2026-10-12-extended-resume-harness.md)。本步完成独立工具接入及六场十二秒 probe；**十分钟正式六场尚未运行。**

## 为什么这样实现

实验夹具负责制造事件，记录器负责保存事实；外部采集器固定版本、顺序和分母，离线分析器从原始事件复算结论。复用现有 `source_hashes`、UTC 时间与摘要工具，保留一个专用入口，没有新增通用监控平台。

相较把六场全部放进一个 Go 测试进程，每场独立进程能隔离前一场的连接、GC 和记录量。相较直接相信 summary，独立分析核对音频块摘要、位置、结果、原 RPC 和资源清理，支持同一数据反复复算。独立实现仍可能出错，因此同时维护证据反例和真实 probe。

## 实现内容

1. [单场 Go 入口](../../internal/gateway/extended_resume_collection_test.go)默认跳过；要求明确 mode/case/output，formal 另外要求显式开启，不能缩短正式条件。入口独占创建事件目录，每次只执行一个原场。默认测试的十二秒组合 probe 沿用。
2. [采集器](../experiments/scripts/run_extended_resume.py)独占创建目录、冻结选择的源码和计划、一次非 race 构建；按 A→B→C、C→B→A 逐场启动同一测试二进制，保存 stdout/stderr、事件、终态、进程退出码及前后源码摘要。超时只终止并等待本函数创建的直接子进程；失败槽位保留，后续不会重测替换。省去 test2json 大报告，原始 JSONL 直接写盘。
3. [固定条件](../experiments/scripts/extended_resume_contract.py)独立于 Go summary，固定输入算法、配置、场次和资源窗口。[分析器](../experiments/scripts/summarize_extended_resume.py)分别检查档案和逐场事件：完整行、固定组件/字段、连续序号、数值类型、音频摘要/连续位置、Worker 处理/输出顺序、客户端应用、代理写入配对、故障不重复、握手开放顺序、预算及真实空闲。证据错误时保留固定分母和未知数，拒绝对应指标。
4. 逐轮计算实际故障/开放、ready 转发、新采集音频结果、追赶确认、覆盖故障的 partial 间隔；最后故障未恢复时保留 null 和右删失标记。输出外部采集/接纳/处理位置序列、输入缺口、自然清理，以及固定窗口的堆/goroutine/GC/活动任务等摘要。
5. 采样密度、最大间隔、源计划落后和实际故障时长独立分类。业务完整性可以有效、时间/资源质量却不合格；降低指标解释资格，不把完整场改成业务失败。资源窗口标明未到达/部分/仍恢复/在线及质量，增长线索仅表示需定位，不认定泄漏。formal 额外记录自有唤醒进程及过滤后的睡眠转换审计，缺审计或观察到转换时限制时间/资源解释。

## 先补齐观测，再复算

读取旧 Go probe 时发现：`gateway.cfg.V2` 已由构造器内部移走，因此旧 summary 的 V2 为 null；`natural_idle` 没有附上清理计数。该旧记录足以支持当时的 Go 断言，但独立分析无法据此核对生效 v2 参数或空闲事件的资源状态。

本步记录独立的实际 `gateway.v2` 配置副本，空闲事件带会话/握手/注册/RPC/handler/计时任务零值，并记录停止/取消状态；同时给代理退出事件增加连接编号、入口拒绝增加明确 code，记录 UTC 原点用于环境对齐。业务状态和协议语义未改，旧归档没有补写这些新事实。

## 工具执行与结果

首次独立三场 probe 全部校验合格。随后加强字段类型、写入配对、必需源码与质量分级，最终版本按两轮六场重新采集，不拼接首轮。两次原始目录及各自冻结分析器均保留。

最终命令：

```sh
PYTHONDONTWRITEBYTECODE=1 GOCACHE=/private/tmp/tide-review-gocache \
  GOPROXY=off GOSUMDB=off \
  python3 docs/experiments/scripts/run_extended_resume.py \
  --mode probe --count 2 --output /private/tmp/tide-extended-tools-2026-10-13-run-2
```

326 份选择的源码/计划测量前后摘要一致；一次构建，六个独立进程依次完成，无场次重叠、未知或替代场。全部证据和本轮采集节奏/采样质量判据合格。

| 条件 | 计划 / 已核实 | 完整完成 / 明确失败 | 原 RPC | 恢复接纳 |
| --- | --- | --- | --- | --- |
| A 正常 | 2 / 2 | 2 / 0 | 每场 1 | 每场 0 |
| B 八次预算 | 2 / 2 | 2 / 0 | 每场 1 | 每场 6 |
| C 五次预算 | 2 / 2 | 0 / 2 | 每场 1 | 每场 5，第六轮不拨号 |

A/B 每场 384000 字节与 121 条结果完整；C 每场采集 275200、处理 272000，已采集未处理 3200、尚未采集 108800 分开记录，85 条结果，末轮恢复等待 null/右删失。B 代理重复音频负载每场 19200，C 每场 16000，不是 Worker 重复处理或 TCP 总流量。每场源关闭一次、服务资源自然归零，完成确认与失败结局分别保留。

最终最大采样间隔 110.660ms、最大源计划落后 7.197ms；这些是 probe 的观测质量说明，不作正式性能结果。固定窗口 A/B 全部在线，C 末窗未到达；不把失败后服务器保留期间的资源样本当作该场继续在线。

新目录复算四个输出逐字节一致。[证据归档](../experiments/results/extended-resume-tools-2026-10-13/README.md)分别保留最终 359 文件与初次 347 文件的完整采集目录；全部文件解压读回摘要一致。两份归档各自使用冻结分析器重算，四个输出均与各自原始分析逐字节一致。

测量时 HEAD 为 bf85832，包含本步尚未提交的 Go/Python 变更；实际代码以 326 份冻结快照为准，不声称最终提交已经受测。六份本步 Go/Python 源码与快照一致；测量后计划文档仅更新进度，归档内计划保留测量时版本。

## 检查与边界

新增 Python 18 个测试方法含配置/位置/摘要/缺事件/数值类型/额外字段/截断/档案损坏/搬移/构建失败等反例；全部实验 Python 测试 177 方法通过。归档完成后，另以仓库默认归档夹具运行新增 18 方法，全数通过。采样减半反例保留完整业务结局但撤销资源/时间质量。相关 Go 两包 race：Gateway 1103、wsclient 327 通过，共 1430，零失败、无竞态报告，18 个默认跳过含新增显式采集入口。Gateway `go vet` 通过。

本步没有首次真实采集或分析失败；单元测试中的刻意损坏、构建失败是反例，不当作正式运行失败。此前记录器短写超时仍留在上一工具归档。

十二秒 probe、多轮可控代理、每块 10ms Mock、单会话同进程 loopback；不证明十分钟稳定性、真实模型追赶、群体弱网、生产参数或严格进程内存上界。客户端内部缓存没有新增公共快照，位置差只能作为外部积压线索。工具自身有测试，不代表分析结论天然正确。

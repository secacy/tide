# EXP-006-05：十分钟、多轮断线正式结果

日期：2026-10-13。关联[预登记](../experiments/repeated-resume-extended.md)、[独立工具验收](2026-10-13-extended-resume-tools.md)、[完整证据](../experiments/results/repeated-resume-extended-2026-10-13-run-1/README.md)。本步执行预登记六场并分析，没有修改业务代码、预算规则或默认参数。

## 本轮回答了什么

在固定单会话、100ms 音频输入、10ms/块 Mock 和六轮 500ms 断线下，八次预算的两场十分钟会话都接回六次、完整结束；五次预算的两场都在第六轮明确耗尽，原场自然清理。所有六场完整性证据有效、行为符合预期，时间/资源质量五场合格，一场因输入计划落后超限而降级。

这补足了此前六秒一次断线实验不能回答的原场跨轮完整性和累计预算问题。它也暴露两个限制：成功恢复不清零的整场预算会被相隔很久的故障逐渐耗尽；自然释放与 goroutine 回落不代表已经排除堆增长。保留这些观察，不以业务验收通过代替性能或内存结论。

第二轮 B 所有输入和结果完整、六轮各一次请求/接纳，也都追赶；其第 1592 块源 Read 开始在 elapsed 159.342663417s，计划 159.201916875s，落后 **140.746542ms**，超过预登记 100ms。只读一个块用时 0.008458ms，开始落后与读函数执行耗时分开；该场还有三次大于 200ms 的采样间隔，最大 289.272ms，未超过 1s 判据。未观察到睡眠，但当前记录无法确定停顿原因，不能直接归因于网络、GC 或系统调度。

按预登记和既有分析器，第二轮 B 整场时间/资源解释资格降级；所有原值留在 CSV/JSON，七个资源窗口 `quality_ok=false`，增长标记为 null。不会删除慢块、只挑故障附近样本或补一场替换它。五个合格场最大输入计划落后 33.846ms，最大采样间隔 117.280ms。

## 资源：稳定任务数与需定位的堆线索

42 个计划窗口中，38 个在线、4 个 C 未到达；31 个窗口时间/资源质量合格，第二轮 B 的七个在线窗口降级。合格在线窗口覆盖率 98.333%–99%，每窗 295–297 个样本，尾窗 394–396 个；所有这些窗口 goroutine 最小/中位/最大均为 30，会话/注册/RPC 各一、代理 handler 一、握手与故障计时任务零。恢复后没有观察到活动转发任务累积，六场最终资源共同归零。

整场记录器队列峰值依次 6/8/5/12/11/4，远低于配置 1024；合格窗口队列中位数零、最大二，不出现随记录量增长的排队。JSONL 累计文件增大是落盘记录量，不能据此推断常驻堆在保存整场事件。

## 复算、边界与下一步

完整采集归档包含 359 文件，解压逐文件 SHA256 一致；冻结分析器在搬移后的目录复算四输出，另用当前同版本分析器新目录复算，均与原输出逐字节一致。代码未变，本步没有重复既有 177 Python / 1430 Go race 检查来包装新成果；新增验证是正式六场、档案读回与冻结复算。首次辅助打印在 C 未到达窗的 null 上报 TypeError，修正打印方式后继续读取，原始证据和正式分析器未改。

价值是从一次连接恢复扩展到十分钟六轮的完整性、明确预算边界和自然释放证据，并把等待与资源结论限制到合格样本。它不证明数十分钟临床问诊、群体多轮弱网、黑洞/丢包、实例失效后无损恢复或真实 ASR 性能。

下一步先针对堆增长线索设计诊断，并结合“第六次低频断线仍耗尽”的事实讨论整场累计预算是否适合长问诊。每轮重置、滑动窗口和分层限额各有成本，需要先确定契约与判据；本轮不直接提高默认次数或更改预算算法。第六阶段仍保留这些解释及边界，第七阶段真实模型尚未开始。

# 第七阶段：首个本地中文流式模型探针

日期：2026-10-25。承接[接入评审](2026-10-25-real-asr-entry-review.md)。状态：独立模块、测试与四类本地原生运行完成；真实 Worker/Gateway 适配仍未实现，尚无模型质量优胜或生产容量结论。

## 本步目标及取舍

先在单模型、单 stream、无网络链路的条件下验证分块出字、输入尾部、静音与取消，再确定 Worker 的状态和协议映射。直接接网关会同时引入模型调用、RPC、结果修订及生命周期问题，排错成本较高；本步选择独立探针，代价是尚未覆盖完整链路。没有因为存在 Go SDK 而认定模型适合最终医疗业务；FunASR 等候选仍待对照。

代码位于 [experiments/asrprobe](../../experiments/asrprobe/README.md)，为独立 Go 模块，主项目依赖和业务逻辑未变。固定 `sherpa-onnx-go-macos v1.13.8`，Go 1.26.5/darwin arm64/cgo，CPU 两线程、greedy search、无 endpoint reset；模型为中英流式 Zipformer int8，Hugging Face revision `98590b7ed6443e77b714204da2757d75e1a642f4`。七份模型/示例/说明资源摘要已核对，模型卡声明 Apache-2.0。模型运行在本地，无 GPU 租用或识别期间的云端请求。

## 实现与可观察事实

- 固定 16kHz、单声道 PCM S16LE；WAV 容器与元数据不送入模型，每 100ms/1600 样本，短末块保留。计划按原始音频位置推进，模型计算不移动后续计划。
- 参考官方示例使用 300ms 前置与 600ms 尾部零 padding，然后 InputFinished/drain；padding 单列，不计入原始输入字节。该配置尚未优化，不声称所有模型都需要相同 padding。
- Accept、Decode、GetResult 与 InputFinished 串行调用，逐调用记录单调时间及原始输入位置；文本保留为整场快照。取消在调用前后检查，等待已启动同步调用返回后才删除 stream 和 recognizer。
- 绑定没有 context 参数或已证明的逐字节处理位置 getter。记录 `processed_audio_bytes=null`，不以提交量、末词时间或 IsReady=false 代替。版本源码中 IsReady 比较已处理帧、chunk size 与可用帧；Decode 内部按 chunk shift 推进。该机制还不能直接证明原始字节前缀映射，相关源码随归档保留。

## 本机探索结果

最终版四进程串行运行窗口为 **2026-10-25 22:58:43–22:59:04（Asia/Taipei）**，复用同一非 race 可执行文件；模型每进程重新加载，系统文件缓存未清除，不称四次冷启动。每种场景仅一场，无预登记性能达标阈值，属于接入探针验收，不是正式策略比较。

| 场景 | 原始输入 / 实际提交（B） | Decode / 文本快照变化 | 首次非空快照 | 最后输入返回→刷新完成 | 结局 |
| --- | ---: | ---: | ---: | ---: | --- |
| 上游示例 0，10.053125s | 321700 / 321700 | 33 / 16 | 1026.014ms，输入结束前 | 37.741ms | 本地输入与刷新完成，释放调用返回 |
| 上游示例 1，5.1s | 163200 / 163200 | 18 / 11 | 1331.939ms，输入结束前 | 37.782ms | 本地输入与刷新完成，释放调用返回 |
| 纯静音，2.035s | 65120 / 65120 | 8 / 0 | null | 41.865ms | 文本为空，输入与刷新完成 |
| 示例 0，加载后约 350ms 主动取消 | 321700 / 12800 | 1 / 0 | null | null | context deadline exceeded，退出 1，无 InputFinished/尾部 padding，释放调用返回 |

示例 0 最后一块只有 850 样本，静音末块 560 样本，事件核对输入位置连续且完整；两场正常语音确实在后续原始块尚未输入时出现文字。共三个完整探针与一个预期取消，不合并称恢复成功率，也没有验证 gRPC completed 协议。

完整三场的 `call_rtf` 分别为 **0.086585、0.079623、0.085363**。这里分子只累计包围 Accept/Decode/GetResult/InputFinished 的时间，含 padding 分配和少量调用内记账，排除人为排期、模型加载、Ready 检查、日志和释放；分母为原始音频时长。它不是端到端 RTF、单条文本延迟或并发容量。模型加载耗时 533.739–634.262ms，三场完整输入最大排期落后 1.084–1.479ms。

取消场从加载后 stream 计时到释放调用返回共 378.663ms。记录不足以断言该轮截止恰好落在 C 推理中；不能将约 29ms 差额全部归因于停止计算，更不据此承诺原生硬取消或最坏退出时限。可控测试另外验证了取消发生在同步 Decode 内时不会并发删除对象。

## 文本与质量边界

原始快照和最后文本完整保留，示例 0 包含 `TODAY IS LIBR`，示例 1 包含 `叫叫`。没有独立核对的人工作文，因此不推断这些词的正确与否，**两场 CER 均为 null**，也不拿官方解码输出或本模型输出反过来当作参考。当前只证明真实模型能在输入期间产生文本，医疗术语、数字、否定词和说话人质量均未评估。

探针提供可选人工参考 CER：Unicode 小写、去空白和标点，保留数字/否定词等字符，不做繁简替换。质量数据必须在独立参考确认后再产生。模型输出是可修订的整场快照，Worker 后续需明确定义片段身份、替换/追加与定稿规则，不能每次把完整快照追加为新句子。

## 测试、修正与证据保存

独立模块最终 `go test -race -count=1 ./...` 与 `go vet ./...` 通过。测试覆盖短末块/padding、原始排期、输出失败退出、调用前及 Decode 内取消后的关闭顺序、WAV 格式和字符计分。没有重跑未改动的主项目测试来增加成果数量。

首次原生四场也为三个完整探针、一个预期取消，但审阅报告发现：取消场的 RTF 使用整段计划时长，不能比较；leading padding 计数也应跟随实际调用而非提前初始化。最终改为取消 RTF=null、实际调用后计数，并将 final_text 改名 last_text_snapshot 避免误读为片段定稿，然后重跑四场。首次全部原值保留，两轮不合并分母；修正属于探针口径，没有改模型参数来替换不利结果。

最终四场摘要与逐调用事件核对一致；复核脚本拒绝伪造提交量、处理进度、文本快照、RTF 和 CER 五种报告。下载器经本地 file URL、拒绝已有目录及错误 SHA 反例检查；网络实际下载另使用固定 revision URL，七份资源摘要一致。

[归档](../experiments/results/real-asr-probe-2026-10-25/README.md)含首次/最终原始事件、摘要、进程输出、参数、源文件摘要与源快照、绑定/模型元数据及相关源码。55 文件全部读回 SHA 一致，搬移后冻结校验器核对最终四场通过。首次源快照在修正后还原，并逐字节匹配首次运行前的六个文件摘要，明确区别于当时立即备份；最终八个文件快照与运行清单一致。模型与可执行文件体积较大且依赖本机动态库路径，不放入归档，保留下载 revision、文件/二进制/原生库摘要及构建说明；本步不承诺重新构建二进制逐字节相同。

## 对下一步的影响

已经具备首个真实模型的本地行为依据。**进入生产 Worker 编码前，先处理进度和文本映射方案：** 比较补充保守处理前缀观测、显式暂不启用未确认字节预算的接通模式，或调整适配契约；必须说明保护范围和启用条件。现有累计接纳确认仍不等于模型处理或持久保存，不能为了复用预算伪造进度。

随后指导开发者实现一个最小真实 Worker，再做现有 Gateway 的单场闭环。说话人字段、医疗效果对照、FunASR 备选、完整录音与延后转录、GPU 与并发容量仍未完成；没有从本轮单场 RTF 得出这些能力已具备。

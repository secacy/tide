# 第七阶段：真实 Worker 的文本与进度映射

日期：2026-10-25。承接[本地模型探针](2026-10-25-real-asr-probe.md)。状态：首版方案与文本映射器实现已完成，评审及部件验证见文末；真实 Worker 和网络闭环待实现。本步没有新增模型运行数据。

## 能力目标

将真实模型产生的可修订文本正确传到客户端，并明确没有可信处理进度时的运行范围。探针已经证明短音频可以边输入边出字；尚未证明文本经过 Gateway 后能正确替换、定稿和结束。

后续按三步形成闭环：本步指导纯 Go 文本映射器；随后组合模型调用与 gRPC 生命周期；最后由助手完成真实 Worker → Gateway → 客户端的短音频验收。原生依赖继续隔离在独立构建入口，主模块中的映射逻辑不导入 sherpa，也不要求常规测试下载模型。

## 文本方案与权衡

例如模型先输出“患者发烧”，随后改为“患者没有发烧”。后一条必须替换前一条，追加会产生重复甚至相互矛盾的内容。这里的例句仅说明协议，不是模型测试结果。

| 方案 | 好处 | 代价及本次决定 |
| --- | --- | --- |
| 同一片段发送完整快照，客户端替换 | 可以处理插入、删除和改字；现有字段即可表达 | 重复传输前文；选择用于首个短音频闭环 |
| 只发送新增后缀 | 单次消息小 | 前文可能改写，不能只靠追加；若采用编辑补丁，需新增位置、版本和重放规则，本次不做 |
| 端点切段，每段定稿后建立新片段 | 限制单段大小，适合长对话演进 | 需要验证切段、上下文和尾音行为；探针未启用 reset，后续独立验证 |
| 仅结束时发送文本 | 实现最少 | 无法验收实时出字，本次不选 |

现有 [resultBuffer](../../internal/gateway/result_buffer.go)允许同一 segmentID 多次更新；[v2 客户端状态](../../internal/wsclient/client_state_v2.go)按 Seq 校验顺序和去重，不负责合并文字。应用侧 OnResult 应以“逻辑会话 + segmentID”为键替换文本，成功应用后才确认。不同 RPC 可以各自使用 segmentID="1"，不能在多会话共用的表中仅按 "1" 存储。

首版规则：

1. 一个短音频 RPC 对应一个片段，ID 固定为 "1"，无端点 reset。每条 Text 是该片段的完整快照。
2. 初始空 partial 不发送；相同 partial 不重复发送。非空变为空是有效修订，必须发送空快照让客户端清除旧文字。
3. 正常输入 EOF 后执行尾部 padding、InputFinished 和 drain，再读取最后快照，生成一次 IsFinal=true；即使与上一次文本相同或全程静音，也生成 final。
4. final 仅表示本片段不再修订。Worker 成功发送 final 后正常返回，Gateway 仍依照合法输入结束、上传半关闭和响应 EOF 判定整场完成。取消、刷新失败、发送失败均不能伪装为成功。
5. Gateway 分配的 Seq 表示第几次更新，与 segmentID 不同。不能在结果已经分配 Seq 后随意合并快照，否则会改变现有确认和重放契约。

完整快照可能随输入变长，逐次发送的累计量也会增长。本方案只用于首个短音频接通，不作为数十分钟问诊的最终分段设计。文本上限超出时明确失败，不截断后报告完整结果。

## 处理进度方案与权衡

[AudioProgress](../../proto/tide/asr/v1/asr.proto)要求连续完成处理的原始音频字节位置。当前探针没有证明这样的映射；Accept 返回、IsReady=false、文字出现或末词时间都不直接等价于这个位置。

| 方案 | 好处 | 代价及本次决定 |
| --- | --- | --- |
| 补充可信处理位置观测 | 可继续使用未确认处理字节预算 | 需验证特征窗口、右侧上下文、padding 和完成时机；作为后续方案 |
| 不发 progress，显式关闭该预算 | 不篡改协议，能够先验证真实文本闭环 | 缺少这一项推理积压保护；选择用于隔离的短音频接通 |
| 更换后端或调整保护契约 | 可按模型真实能力重新设计保护 | 需要新的模型证据或协议评审，不能靠改名直接复用旧承诺 |

首版 Worker 不发送 AudioProgress，包含 EOF 时也不补造“全部处理”的字节确认。专用实验 Gateway 显式配置 MaxPendingAudioBytes=0；不能自动豁免，也不能将该模式与启用预算的 Mock 结果混称同等保护。若错误地启用正预算，没有 progress 的流仍会累计未确认量并超限。

已有会话准入、音频/结果缓冲、发送和尾部等待等保护仍然存在，但它们不能证明模型内部积压或原生内存有相同上界。后续首个 Worker 拟限制一场活动 RPC、16kHz/单声道/PCM S16LE、每场最多 30 秒原始音频（960000B），超限明确拒绝；这些限制尚未实现。验证使用已固定的短输入，不据此推断长时容量。

同步原生调用不接受 context。取消后应停止后续调用，等待正在使用对象的调用返回再释放；Gateway/RPC 超时不等于原生计算已结束。若要硬停止卡住的推理，需要进程隔离与终止等额外方案，本次不作该承诺。

## 开发者本步实现：文本映射器

新增 `internal/realasr/snapshot.go`，包名 `realasr`。这是 Worker 的纯 Go 协议逻辑，位于主模块；不移动探针，不增加原生依赖，不修改 protobuf 线格式。

建议骨架如下，函数签名需要补充实现后才能编译：

```go
// snapshotMapper 将单个模型流的完整文本快照映射为 Worker 响应。
// 每个 RPC 独占一个实例，由同一个执行流程串行调用，无需加锁。
type snapshotMapper struct {
    segmentID    string // 本 RPC 内稳定的片段 ID；首版传入 "1"。
    maxTextBytes int    // 单条 Text 的 UTF-8 字节上限，不是字符数。
    lastText     string // 最近一次生成的快照；初始空值用于抑制空 partial。
    finalized    bool   // 已生成 final；不表示发送成功或客户端已应用。
}

// newSnapshotMapper 校验非空、合法 UTF-8 的 segmentID 和正数文本上限。
// 首版调用者使用 segmentID="1"、maxTextBytes=4096；该值是开发保护参数。
func newSnapshotMapper(segmentID string, maxTextBytes int) (*snapshotMapper, error)

// mapSnapshot 接收完整快照，绝不能把 text 当作新增后缀。
// final 只能由调用者在正常尾部刷新完成后置 true。
// 返回 nil,nil 表示 partial 无变化；成功返回的响应由调用者负责发送。
// final 后再次调用、非法 UTF-8 或文本超限返回错误，且不修改原状态。
// 此方法不执行 I/O，不分配 Seq，始终令 Progress=nil。
func (m *snapshotMapper) mapSnapshot(text string, final bool) (*asrv1.StreamingRecognizeResponse, error)
```

实现顺序：先检查 finalized、UTF-8 与 len(text) 上限；再判断非 final 且 text==lastText 时抑制；其余情况新建响应，然后更新 lastText/finalized。每次创建独立响应，后续调用不得修改已经返回的对象。错误信息不包含识别原文。

4096B 是首轮短输入的显式开发上限，不是实测容量；它只约束 Text，不等于 JSON 帧大小或全部保留结果大小。原有传输、结果条目和总字节预算仍各自生效。

映射器在生成响应时更新状态，未尝试提供发送事务。后续 Worker 若 Send 失败应结束本 RPC，不在同一 mapper 上重试。v2 的结果重放由 Gateway 已有保留机制处理。

## 验收与下一步

开发者实现后，助手评审并补测试：首个空 partial、相同文本去重、前文改写、非空撤回为空、相同文本 final、纯静音 final、final 后拒绝、UTF-8/字节上限及失败不改状态、历史响应不被修改、所有响应无 progress。随后用现有 Gateway/客户端验证同 ID 修订和 final，不将纯函数测试当作真实模型端到端验收。

本步只落定方案与实现指导，没有修改核心代码、运行模型或产生新的延迟/准确率数据。真实 Worker、客户端展示应用、网络闭环、处理位置观测、长对话分段及医疗质量仍待完成。

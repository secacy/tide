# 真实 Worker 连续会话基线：五轮退出与资源观测

日期：2026-10-26。状态：测试/采集/独立复核工具、首轮验证与完整复测完成；原始证据已归档。本步只修改测试与实验工具，没有调整 Gateway、客户端或原生 Engine 的业务行为。方案与权衡见[设计](2026-10-26-real-asr-backend-baseline-design.md)，复测前判据见[实验计划](../experiments/real-asr-backend-baseline.md)。

## 结论

同一 Worker 进程、同一 Gateway 实例，预热后完成五轮“取消 → 正常完成”：**正常完成 5/5、预期取消 5/5、取消后新场 5/5**；预热另列。十一场均有一个原生创建/释放对，源恰好关闭一次；每场自然清理后 Gateway 活跃数归零，没有靠停服或重启取得成功。

真实模型的首字、尾部和资源成本现有逐场依据。此次尚无优化前后对照，不能把基线数字表述为延迟或内存优化收益。资源释放有两层证据：模型 Close 返回、Gateway 会话归零都能观察到，**RSS 则未回到预热后的值**；这既不证明长期无泄漏，也不足以断定泄漏。

## 条件与实施

- Apple M2 Pro、32GiB 内存、12 逻辑 CPU，macOS 26.6.2 arm64；原模型及 SDK v1.13.8，greedy、原生配置两线程。Worker 二进制 SHA256 `8e2c93fdfe75b257614db246b63c171db1d80de5e1decffde924d84e880a8c3c`；与首轮相同，非 race。
- 固定公开示例 0，16kHz 单声道 PCM S16LE，321700B、10.053125 秒；每 100ms 提交最多 3200B，不重采样。模型每场加载，Gateway 一个名额，处理前缀未知、未启用积压字节预算。默认十秒恢复窗口保留，无客户端自动恢复。
- 正式预登记十一槽位：预热一场及正式十场；每场自然清理后固定空闲，连续采样，不强制 GC。工具在证据落盘且 RPC 清理后释放完整 trace，内存只保留本轮固定规模摘要。
- 首字从 V2Client.Run 起点计算，包含握手与加载；尾部从源 EOF 到 Run 返回。客户端取消、原生关闭观察、Gateway 归零观察分别记录，所有观察时刻使用驱动单调时钟。
- 复测采样窗口 **14:56:34.381～14:58:59.891（Asia/Taipei）**，持有 `caffeinate -i`。292 次采样，最大单调/墙钟间隔 **509.399ms / 509.414ms**，单次采样最长 13.847ms；无超过三秒的采样缺口，无 RSS 查询失败。这不代替完整系统睡眠审计。

五场正常首字为 **1024.327～1033.950ms**，尾部 **35.861～62.598ms**；全部在输入读完前收到文字，且输入摘要、末块、快照顺序、final、completed 与 ACK 一致。不将首字解释为逐词声学延迟，也不拿探针加载后口径相减来估算 Gateway 开销。

取消触发至客户端返回 **0.100～0.203ms**，至 Gateway 归零观察 **10011.456～10011.913ms**，至模型 Close 观察 **10020.822～10021.900ms**。约十秒主要包含既有恢复政策；观察粒度也有开销。三者不能合成“模型在 0.2ms 内释放”，Gateway 归零也不证明远程原生对象已释放。每场均等到两项释放依据齐备后才启动后续会话。

十一场后的全部空闲窗口均观察到 Gateway=0、模型创建/关闭累计数相等、驱动 goroutine=11。Worker 运行期 RSS 最大采样值 **631.56MiB**；上表每个 Worker 空闲窗口内采样值相同，完整取消场窗口也保留于归档。

Worker RSS 从预热后约 307MiB 上升到约 600～632MiB；正式正常场之间存在回落，并非单调增加。当前证据无法区分原生分配器缓存、模型运行时保留、映射或真实残留，不能把“有 Close 日志”当作 RSS 必须归还的保证，也不从五轮拟合长期趋势。先保留这个资源成本与待解释项，不为得到平坦曲线而重启、强制回收或继续无限扩轮。

驱动 Go 堆包含 Gateway、客户端、HTTP/gRPC 与工具；Worker RSS 是独立进程的驻留内存。两者不能直接相加称为单会话内存；RSS 采样最大值不等于精确峰值。单 Worker 的一个名额来自限制，不是实测稳定容量；长时音频仍限 30 秒，真实并发与进度保护仍未验收。

## 首轮、修订与验证

首次完整运行同样正常 5/5、取消 5/5，十一份模型释放；其资源采样原值全部保留。准备阶段原本用 `os.ReadFile` 计算摘要，整份模型暂存于驱动 Go 堆，预热空闲约 209MiB，后续自然 GC 后降到约 2MiB。这是工具分配造成的初始观测干扰；改成流式摘要读取后完整复测。不把两轮分母合并，不以堆变小宣称 Gateway 优化，也不将两轮 Worker RSS 差异归因于此改动。

另一次冻结在查询硬件信息时被沙箱 sysctl 权限限制中断，未启动 Worker、没有运行槽位；保留该准备目录及说明。工具现将硬件查询失败单列为元数据缺失。最终新目录成功冻结并取得硬件信息，没有覆盖旧目录。

sherpa 模块 race 回归与 vet 通过；独立复核器十项单元测试覆盖缺失释放、伪造完成 ACK、文本损坏、RSS 伪零/不可用、采样缺口、源码损坏及恢复窗口被缩短等。首次普通回归因沙箱不允许绑定本地 TCP 失败，允许本地端口后通过；这不是服务功能失败。正式测量使用非 race 驱动与 Worker。

首轮和最终运行分别用各自冻结的 Python 复核器核对原始文件；归档真正解包后再次核对全部文件摘要，复核结果与原件一致。[归档与命令](../experiments/results/real-asr-backend-baseline-2026-10-26/README.md)。

## 当前进度与后续

第七阶段已有真实模型的短音频闭环、重复退出及单场成本依据。后续仍需围绕长问诊的分段/状态边界、未知处理进度下的保护及真实模型容量开展设计；本步没有实现这些能力。

RSS 是后续容量估算必须保留的实测成本，当前尚无证据把它定性为网关生命周期缺陷。若需要定位，先限定一个能区分缓存与存活对象的诊断问题；不继续扩展模型准确率实验，也不自动把后端主线变成原生运行时研究。

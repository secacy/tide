# 解码策略对照结果：当前 beam/4 未改善质量

日期：2026-10-26。状态：十二场测量与复核完成；助手文字对照不代替人工事实审核。起始代码 `337bb89`，执行前冻结[计划](../experiments/real-asr-decoding-comparison.md)、输入及十九份源码/配置快照。

## 结论与决定

两组各 6/6 完整完成。相同 200 个参考字符下，greedy 为 **35%（70/200）**，beam/4 为 **42.5%（85/200）**，后者增加 **7.5 个百分点**。beam 少了两个替换错误，但插入从 63 增至 80；六段中 q02 少错一字，其他五段错误更多。体温“37.8→67.8”仍未纠正。

本轮不采用 beam/4 作为质量改进方案，生产 Worker 继续既有 greedy 配置。这里只否定当前固定模型、六段素材、四路径预算下的选择，不声称所有 beam 设置或其他模型的 beam 都更差。六段首轮质量基线和此前直接定位证据保留，没有被新结果覆盖。

后续优先进入候选中文流式模型的同素材对照，再根据效果和接入代价选择后端；本轮没有选定新模型或部署设备。继续扩大搜索预算目前缺乏本轮收益依据，不能靠改显示文本来掩盖原始数值错误。新后端若在这六段上用于选择，仍需未参与选择的新素材验证。

助手只在独立探针增加两个参数、有效配置映射和 v2 报告字段；默认仍 greedy。greedy 拒绝非零路径预算，beam 要求显式 1～16 的实验预算。Go 测试核对设置真正映射到 SDK，其他模型/特征参数保持相同；非法参数在资产访问及输出创建之前拒绝。生产 Engine、Worker、Gateway、V2Client 和协议未改动。

正式运行前探针 race 回归、vet 及 Python 十三个测试通过，覆盖策略映射、错误预算、历史兼容、负向分数差、失败/缺场及损坏消息。本轮程序与输入首轮通过，没有准备或推理失败；结果较差的五段和唯一改善的 q02 均保留。

# 质量问题定位：同 PCM 的直接模型探针对照

日期：2026-10-26。起始代码 `6b367d2`。状态：两段直接探针对照完成，最终全文和文本变化序列均与原链路相同。前半部分保留执行前设计，结果见文末。

## 问题与方案取舍

[六段首轮质量基线](2026-10-26-real-asr-quality-results.md)出现重复字和体温数值错误。原始 Worker 快照与客户端一致，仍需判断 Worker/Engine 适配是否额外引入错误。选择重复明显的 q04 和数值异常的 q05，复用已有独立 `experiments/asrprobe`，直接调用 SDK，绕过生产 Engine、Worker、gRPC、Gateway 和 V2Client。

不重新录制、不重采样、不更换模型，也不先通过规则去重：这些变化会使错误来源更难比较。相比重跑整个系统，直接探针缩小了参与的代码范围；代价是它仍共享 Go SDK、原生库、模型和已转换 PCM，不能单独区分这些共同部分。两条路径均自行解析 PCM16 并转换 float32，不共享生产 `pcm16Samples` 实现。

## 执行前固定条件

- 输入使用首轮冻结的 `testdata/asr-quality/self-recorded-2026-10-26/pcm/q04.wav` 和 `q05.wav`；WAV、PCM、原始参考摘要必须与首轮一致。样本是看过首轮输出后选出的定位样本，不作为新的随机质量集合。
- q04→q05，各一次，各自独立探针进程；原首轮结果保持不变。固定当前探针源码，执行前保存源码、程序与模型摘要，记录每次退出状态及原始 stdout/stderr/逐调用事件。
- 使用同一 SDK `sherpa-onnx-go-macos v1.13.8`、同四份 int8 模型文件、CPU 两线程、greedy、无 endpoint/reset；100ms 原始块，300ms/600ms 零 padding 和输入结束后排空。
- 两路同为按音频位置排期的分块，但探针在加载后开始计时，原闭环包含握手/加载，首批送达节奏也可能不同。本轮比较输入身份、原始快照序列和最后文本，不将延迟或调用 RTF 差异作为优化结论。
- 探针不传 `-reference`，保留其 `character_score=null`，避免沿用早期探针不同的标点归一化。统一复用本轮质量工具的 CER 规则重算两路文本。
- 进程保护每场 60 秒，保存失败；未知/失败不当作空转录、不能跳过后改分母。执行期间持有唤醒保护，不追加并发或故障场景。

## 比较与解释

先用已有探针事件复核函数核对完整输入、调用、padding、结束和释放，再核对 WAV/模型/程序摘要。原闭环逐段重新核对消息、音频 SHA 与完成事实，而不是只读之前打印的最终文本。

直接探针的 `text_snapshot` 为全文变化；原 Worker 在正常结束时会再发一次可能相同的 final。比较变化序列时只去掉相邻完全相同的快照，不去重文本内的任何字符；最终全文另外原样比较。

- 如果两段逐条变化和最后全文相同，说明这些错误在绕过生产适配与网络时仍能复现；本轮未观察到上述业务层额外改变文本。
- 如果只有最后全文相同但变化过程不同，只说明最终错误复现，继续检查中间快照/排期；不声称每一步完全相同。
- 若全文不同，则保留差异，继续核对调用顺序、输入/解码配置和实际原生依赖，不能直接宣称模型本身有问题。
- 即使相同，也不能据此断定唯一根因是模型权重，或排除共用 SDK、原生运行时、转换素材、声音条件和解码设置。后续按证据确定下一项单变量对照。

本次仍是定位，不是修复；不替换六段基线，不把两个已知难例 CER 合并到原六段统计，也不提前修改长对话设计。

## 实现与证据复核

新增的[对照复核脚本](../../experiments/asrquality/compare_probe.py)复用既有探针调用事件复核、Gateway 正常结果复核和质量评分，不增加推理服务或重复实现模型接口。旧探针内置评分的标点策略与本轮不同，因此两场均未传参考，`character_score=null`；上表统一采用当前质量基线规则。

执行前从六段基线归档核对八份被复用的输入/结果文件，WAV 与解码 PCM 摘要分别核对；固定四份模型摘要和探针程序摘要。执行结束、写回本页结果前，14 份源码/配置快照、两份 WAV、程序和模型摘要均保持一致。SDK 为相同固定版本，但本轮没有另做原生动态库文件的独立版本对照。

探针模块 race 回归与 vet 通过。复核脚本在实际结果上拒绝五类反例：改写最终文本、换 WAV 摘要、伪造未释放状态、错误 padding、改写旧基线；这些反例不混入实际两场分母。38 份归档文件全部读回 SHA 一致，搬移后冻结复核与五个反例复跑一致。归档不含音频、模型或可执行程序，搬移验证没有重新推理。本轮无准备或实际识别失败。

## 后续选择

下一步优先检查输入/特征设置，并在探针内比较当前 greedy 与 `modified_beam_search`。固定 SDK 的 `OnlineRecognizerConfig` 明确列出这两种方法及 beam 的 `MaxActivePaths`；改变解码策略有机会判断搜索方式对重复/数值错误的影响，无需先迁移 Worker 或租 GPU。实际支持和收益仍须运行验证，不能预设会改善。

相比立即换模型，该对照保留模型、音频与服务结构，变量更少；相比直接做输出去重，它保留了模型原始判断，可避免把合理重复或自我纠正误删。代价是可能增加计算，并且不能解决所有声学/模型问题。若差异很小或关键错误仍在，再安排同素材候选后端对照。

这两个已知难例只用于定位，不宣称泛化提升；若据此选择配置，应在原六段上完整报告，并增加未参与选择的新录音验证。六段首轮 CER=35% 和人工事实待审状态保持原记录。

## 当前能力与证据

现在能把一段短音频经过真实链路转成可修订文本，并在正常结束时收到完成通知。还不能据此认定系统适合长时临床问诊：传输完整不代表转录准确，单场完成也不代表长时或并发稳定。

| 能力 | 已有依据 | 仍缺什么 |
| --- | --- | --- |
| 真实模型完整链路 | 四场完整输入合计 615140B，Gateway 成功转发 PCM 的 SHA 与源一致，快照逐条一致，客户端核实 completed | 麦克风采集、产品展示与命令级完整部署未覆盖 |
| 输入期间产生文本 | 两段示例语音首条非空回调为 1033.597ms、1330.460ms，均发生在输入结束前 | 只有两段示例，不能解释为逐词延迟或临床实时性达标 |
| 正常收尾与退出 | 静音可完成；五次模型创建/释放对应；取消场保留默认十秒恢复窗口后自然清理 | 原生调用硬取消、真实模型断线恢复与长时资源趋势未验证 |
| 文本质量 | 当前仅保存模型原始快照 | 无独立人工参考，CER 未知；医疗词汇、否定、数字和纠正表达未知 |
| 长对话 | 首版单场上限 960000B，即 30 秒；单片段完整快照上限 4096B | 未实现 endpoint/reset、跨片段结果组织，不能只放大上限就宣称支持长问诊 |
| 处理进度与容量 | 原生模型不发 AudioProgress；接通实验显式关闭未确认音频量预算，Worker 仅允许一场 | 连续处理前缀未知，Mock 的积压及调度收益尚未在真实模型复验 |
| 说话人及完整记录 | 无相应真实模型验收 | 说话人区分、可靠完整录音与延后转录仍待设计 |

## 下一步为什么先做质量基线

现在即使把连接维持到半小时，也仍不知道模型有没有把“没有胸痛”听成“有胸痛”。先用少量带人工参考的短录音定位明显错误，成本较低，而且可为后续分段、换模型提供同素材对照。

| 可选行动 | 能回答什么 | 代价与本次取舍 |
| --- | --- | --- |
| 先做短音频质量基线 | 当前模型在哪里错；之后的改动是否改善或破坏文本 | 需要人工核对，小样本代表性有限；本次采用 |
| 先实现长对话分段 | 能否持续产生多个定稿片段并控制状态大小 | 引入切段/上下文边界，暂时难区分原有识别错误与切段造成的错误；紧接基线后评审 |
| 先租 GPU 或更换模型 | 可以进一步比较设备或后端 | 没有固定音频与参考文本时，缺少可比较的质量依据；保留候选，不在本步购买资源或迁移 |
| 先补模型进度或并发压测 | 保护和容量是否适配真实后端 | 可信进度仍需研究模型内部语义；当前单场短音频范围下不急于扩并发 |
| 先做完整录音与延后转录 | 实时链路失败后能否保留并最终处理内容 | 涉及新的保存、确认和任务生命周期，按 [TODO-001](../TODO.md#todo-001完整问诊记录与实时转录降级)另行评审；本次不默认为已选架构 |

质量基线是诊断用的第一把尺子，不是上线门槛。不会临时设一个 CER 阈值，靠六段熟悉的朗读证明临床可用，也不会为了得出好成绩删除差样本。若后续发现关键事实经常识别错误，应先定位与比较模型；若短句表现可用，则带着这些样本进入长对话分段设计。

## 本轮输入与执行边界

开发者已选择自录模拟问诊，具体录制说明见[质量基线计划](../experiments/real-asr-quality-baseline.md)。先固定六段提示内容，实际录音、参考文本及摘要就绪后再冻结本轮输入。

继续使用当前固定模型和短音频 Worker，不开 endpoint/reset、不改保护参数、不加热词或文本纠错。正式结果取 Gateway/v2 客户端应用的最后定稿快照；不把所有 partial 拼起来评分。助手复用已有网络夹具，补充数据输入及评分工具和必要测试，不另外搭建通用评测平台。

本轮不同时更换模型、加入长对话或制造网络故障。先让质量差异能对应到明确的输入和后端；此前两段公开示例已看过输出，仍可作工程回归，但不混入新的盲核参考样本。

# 两个真实 Worker：错峰新场完成 0/3 → 3/3

日期：2026-10-27。状态：实验驱动、采集、独立复核及完整实测完成。代码起点 `a0e76dd`；运行前冻结相关源码/依赖、模型、两份输入、Worker 二进制和原生库摘要。条件依据[预登记计划](../experiments/real-asr-admission-comparison.md)，前置能力见[Gateway Lease 验收](2026-10-27-gateway-worker-lease-validation.md)。

## 结论

两个真实单名额 Worker、相同短输入和预设错峰条件下，新场 N 的完整完成数从普通轮询 **0/3** 变为本地占用轮询 **3/3**，该场景完成率增加 **100 个百分点**。两种策略原有 L/S 会话分别 **6/6** 完成。三次旧策略失败均选中仍忙的 A，返回 `worker is busy`，没有创建新模型；新策略三次都使用已空闲的 B，音频与结果完整性判据通过。

三个超额批次中，第三场均在 Gateway 入口返回 `session_limit`，**3/3** 正确拒绝，没有额外 Worker RPC 或模型创建；每批原来的两场合计 **6/6** 完成。

结果证明本地占用选择修正了这组错峰分配问题，并在已测有限并发下保持清理与总准入语义。它不代表稳定容量提升到某个并发数，也不代表所有到达模式的平均完成率；场景是为检验已知机制而预设的，不能将 100 个百分点推广到一般问诊负载。

## 条件与分母

- Apple M2 Pro、32GiB、12 逻辑 CPU，macOS 26.6.2 arm64；两个独立 Worker 进程，SDK v1.13.8、原 bilingual/int8 模型、greedy、每 Worker 配置两线程，每场重新创建模型。非 race Worker 与驱动；暖机后不重启进程，不强制 GC。
- Worker 二进制 SHA256 `994b0f70277187dea23c955138669c1dfb2ebee0821affbc0dc2f1eeda020bd1`，执行前后模型、程序和六份原生库身份一致。模型及 SDK 未更换。
- L 使用公开示例 0：321700B、10.053125 秒 PCM；S/N 使用示例 1：163200B、5.1 秒。均为原始 16kHz 单声道 S16LE，3200B/100ms 实时提交，不重采样。两份 SHA 在清单与逐场结果中核对。
- 一个活动 Gateway，`MaxSessions=2`、消息上限 3208B；保留既有存储和期限预算，恢复窗口十秒，客户端不自动恢复；未知模型处理前缀预算仍为 0。本地上限每 Worker 为 1，是配置值。
- 两场暖机单列；错峰按“旧→新、新→旧、旧→新”执行三个配对批次，每臂 L/S/N 三场，每种策略九次尝试；真正对比的新场 N 各三次。另有三个超额批次、六场正常输入及三次拒绝。
- 共 **29 次客户端尝试、26 条 Worker RPC、23 次模型创建**。三次忙拒绝有 RPC 而无模型，三次入口拒绝无 RPC；23 次模型包含暖机两次，不能把 29 次都写成识别成功。

每臂重建 Gateway 和策略实例，两个原生进程及 gRPC 连接持续复用；每臂自然清理后固定空闲两秒。没有补场、重跑识别、未知槽位或触发窗口未满足的记录。

## 配对结果与时间

L 先选 A，再启动 S 选 B；S 正常完成且 B 模型释放、Gateway 活跃数为 1 时触发 N。逐场身份、触发快照、原始回调、RPC 终态及模型事件交叉核对，未根据启动 goroutine 的顺序猜测后端归属。

| 配对批次 | 执行顺序 | 旧策略 N | 本地占用策略 N | 两臂原 L/S |
| --- | --- | --- | --- | --- |
| 1 | 旧 → 新 | A 忙，未完成 | B 完整完成 | 各 2/2 完成 |
| 2 | 新 → 旧 | A 忙，未完成 | B 完整完成 | 各 2/2 完成 |
| 3 | 旧 → 新 | A 忙，未完成 | B 完整完成 | 各 2/2 完成 |

旧策略 N 的失败返回约 **1.098～1.413ms**；这只是失败耗时，不能与成功场的整段识别耗时相比称为速度收益。

| 本地占用策略新场 | 加载 ms | Run 至首条非空回调 ms | 源 EOF 至 Run 返回 ms |
| --- | ---: | ---: | ---: |
| 第 1 批 | 522.795 | 1317.889 | 45.489 |
| 第 2 批 | 528.558 | 1325.323 | 48.657 |
| 第 3 批 | 494.699 | 1325.335 | 46.774 |

三次正常 N 都在输入读完前产生文字，源关闭一次，PCM 字节/SHA、短末块、快照替换与序号、一次 final、completed 和 ACK 全部通过。首字包含握手与模型加载，不是逐词声学延迟；不与上一轮单场基线相减来估算纯调度开销。

超额第三场从 Run 起点至拒绝返回分别为 **0.928ms、0.691ms、0.710ms**。触发时两场仍在运行、两进程各已创建本场模型；三次均为 Gateway `session_limit`，不是后到的 Worker 忙错误。本轮观察到的本机拒绝时间不是生产 SLA。

## 资源与清理

- 每个实验臂结束时 Gateway 活跃数归零，两进程创建/关闭计数对应；启用容量的七个实验臂均在批末验证两个本地名额可同时再次取得。旧策略没有容量限制，该字段明确保留 null。
- Worker A 创建/关闭 **10/10**，B **13/13**。B 多三次正是新策略让新场 N 使用空闲 B 的结果；忙拒绝未增加模型创建。
- 十个臂间窗口中，驱动空闲 goroutine 均为 **17**。驱动包含 Gateway、客户端、连接与工具，不能称为 Gateway 独占数量，也不能和上轮不同装配的 11 直接对比为资源退化。
- 连续采样 **263 条**，窗口 **09:55:09.459～09:57:20.473（Asia/Taipei）**；持有 `caffeinate -i`。最大单调/墙钟间隔 **509.644ms / 509.659ms**，单次采样最长 29.312ms；无超过三秒缺口，无 RSS 查询失败，不等于完整系统休眠审计。
- Worker RSS 最大采样值 A **630.50MiB**、B **627.20MiB**。这包含原生分配器缓存与映射；采样最大值不是精确峰值，两进程各自最大值也不能相加声称同一时刻峰值。没有长期无泄漏结论。

运行中没有用 TryAcquire 探测容量，避免观测修改调度游标。本地名额回收在批末检查，不能据此声称获得逐时刻的精确占用曲线。Worker 的实际模型名额始终独立执行；本地释放与远端释放间隙仍由前置可控测试说明。

## 工具验证与保留的失败

新增驱动只用于显式实验，不改变 Gateway、容量池或原生 Worker 业务逻辑。复用日志读取器时，将本实验每 Worker 的事件上限固定为 64；旧十一场基线仍为 22。

sherpa 模块普通 race/vet 通过，更新后的观察器/基线工具定向 race 测试通过。Python 独立复核器最终 **13 项**测试通过；基于真实结果复制件的 **6 类损坏检查**均被拒绝：伪造完成 ACK、错误 Worker、把输入超限错误冒充忙、缺失释放、错误触发占用及 RSS 伪零。

首次冻结复核器遇到忙拒绝的 `results=null` 报 TypeError：Go 的 nil 切片会写成 JSON null，而合成夹具最初只使用空数组。修订只把 null 解释为空列表，其他非法类型仍拒绝，并补充两个测试。**没有修改运行条件、Go 驱动、模型或原始数据，也没有因此重跑识别。** 冻结的原脚本、首次失败日志、修订差异与额外工具摘要全部保留；修订脚本独立复核完整原始证据后通过。

归档真正解包后逐份校验文件摘要，再执行修订复核和六类真实数据反例，与原结果一致。证据与重现命令见[归档说明](../experiments/results/real-asr-admission-2026-10-27/README.md)。

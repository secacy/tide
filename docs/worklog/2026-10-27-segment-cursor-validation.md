# 原始音频分段计数组件验收

日期：2026-10-27。设计依据 [长对话分段与状态边界](2026-10-27-long-dialogue-segmentation-design.md)，前置版本 `b78c12d`。状态：开发者实现完成，助手评审与组件测试通过；尚未接入 Worker 或原生模型流。

## 实现评审

[segmentCursor](../../internal/realasr/segment_cursor.go) 符合当前契约：构造拒绝非法预算，plan 不修改状态并先检查整个请求余量，commit 完成全部校验后更新两个计数，advance 只在满段且整场仍有额度时推进。预算比较使用剩余量，避免累计加法溢出；commit 不自动换段，因此保留了模型收尾与音频数量的区分。

未发现需要修改的核心逻辑。开发者同步完善了注释；助手新增测试，没有改写计数逻辑。组件按 RPC 串行拥有，不需要锁或后台任务。

## 覆盖与验证

[新增测试](../../internal/realasr/segment_cursor_test.go) 覆盖构造校验、反复 plan 不提交、跨段余量、满段等待、整场超限时不接纳前缀、失败保持状态、非法换段，以及接近当前架构 int 上限的合法计数与超限拒绝。

输入守恒检查采用 20B 和 24B 的唯一字节序列，每段上限 10B，遍历所有按 2B 样本边界划分请求的方式，分别为 512 和 2048 种，共 **2560 种**。每种划分的结果与源音频固定位置切片逐段比较，并检查重组字节、计数和段数；包含整段结束与最后短段。该数字是组件检查规模，不是实际音频时长、完成率或容量成果。

验证命令：

```sh
go test -race ./internal/realasr -count=1 -timeout=90s
go vet ./internal/realasr
```

上述命令使用本地依赖缓存。首次 race 命令在沙箱内运行，既有 Worker TCP 测试因 `bind: operation not permitted` 失败；取得执行许可后，相同命令在沙箱外完整通过。vet 通过。没有更改测试期限或因本次检查启动真实模型实验。

## 能力边界与下一步

现在已有可独立验证的分段计数规则，尚无实际分段输出。当前 Worker 仍使用一个片段，默认整场上限仍为 30 秒。测试中的 advance 只代表计数推进，没有执行 Finish、final 发送或原生流创建/释放。

下一块按[集成指导](2026-10-27-segmented-worker-integration.md)成组接入 Worker 与原生生命周期：明确分段 Engine 契约和显式模式入口、逐段流释放/创建、新片段 ID、边界 EOF 与错误收尾，保留整场 RPC 和名额。随后补可控模型及 Gateway/v2 验收，再开展预登记的真实 120 秒验证。

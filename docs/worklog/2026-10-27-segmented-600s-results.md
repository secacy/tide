# 固定分段真实链路：十分钟延长观察结果

日期：2026-10-27。前置版本 `61c756d`。按照[预登记计划](../experiments/real-asr-segmented-600s.md)，复用两分钟基线的同一 Worker 二进制，扩展正式输入为十分钟。单次正式运行与冻结复核均首次通过，没有补场、重启或运行后改判据。

## 结论与范围

**本机固定模型、单会话条件下，600 秒输入完整完成：20 段样本摘要一致、20 个唯一 final、连续结果及整场完成确认核实；同场一个模型、20 次流创建与释放配对，清理后新场仍能完成。** 五个窗口的边界等待没有持续增长；RSS 在第一窗口后仍小幅上升，模型关闭后未回预热值。

这将已验证输入范围从两分钟扩展到一次十分钟观察。它增加长会话证据，不是十分钟生产可靠性承诺、稳定并发容量或任意时长资源有界的证明。

## 五个两分钟窗口

边界等待沿用上轮定义：每段最后一块源 Read 完成至客户端收取 final，不是逐词延迟或物理音频末端延迟。100ms 完整块在采集块起点交付。表中每窗口四个 final 点、240 个 RSS 样本；时间和内存值均经过四舍五入。

| --- | --- | --- | --- |
| 0～120s | 33.20 / 33.97 / 39.69 | 584.56～612.53 | 585.67 |
| 120～240s | 42.89 / 43.87 / 46.98 | 585.67～586.36 | 586.36 |

| 480～600s | 33.06 / 34.89 / 38.33 | 586.97～587.02 | 587.02 |

20 个边界等待整体 **24.128～46.978ms**，中位数 **37.031ms**；末窗口没有持续变差。首个窗口末到末窗口末 RSS 增加 **1.344MiB**，最后两个窗口的末值增加约 **0.047MiB**。这些点描述本轮缓慢变化，不拟合泄漏速度，也不能证明最终必然平台化。

正式场后续 19 次流创建 **0.192～0.299ms**，20 次流释放 **0.013～0.064ms**。模型本场加载 **523.434ms**，仅一次；首流包含在工厂内，不与后续流操作作同类性能对照。

最大采集落后 **30.867ms**，最大 Gateway gRPC Send 返回落后 **42.799ms**，相对源起点及原始 offset 的固定节奏。后者包含多个环节，不表示客户端实际 Write 的单独等待。源 EOF 至 Run 返回 **7.307ms**；最后段已在满额处提前定稿，该数仅是剩余整场收尾。

这些时间与两分钟历史值存在差异，但运行时系统负载不同、没有成对重复控制，不把差异称为算法或调度优化收益。

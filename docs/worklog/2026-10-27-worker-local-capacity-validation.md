# 本地 Worker 占用池：实现评审与组件验收

日期：2026-10-27。状态：开发者实现已评审，助手补充组件测试并通过 race/vet；Gateway 集成和真实并发对照尚未完成。前置设计见[准入评审](2026-10-26-real-asr-admission-design.md)。

## 实现与评审结论

[CapacityRoundRobin](../../internal/workerpool/capacity_round_robin.go)符合本步约束，无需修改核心实现。构造器拒绝空列表、空白/重复 ID、nil Client 和非正上限；复制配置，保留原 ID 与共享客户端身份。

TryAcquire 在同一把池锁内检查空额、增加占用并推进游标；只扫描一轮，全满时不等待、不发 RPC、不修改游标。返回凭证的归还闭包捕获固定条目下标，不依赖后续变化的 next。Release 通过每凭证的 sync.Once 防止重复扣减，再以池锁保护计数，二者分别处理“同凭证重复释放”和“不同凭证同时更新池”的竞争。

Worker 值返回与配置复制避免外部修改内部条目；Client 引用仍由外部拥有。Lease 及池必须经构造、以指针使用，不支持复制正在使用的锁/Once 对象。名额不自动随 context 取消归还，后续集成由会话清理路径负责。

## 助手补充的验证

[组件测试](../../internal/workerpool/capacity_round_robin_test.go)覆盖：

- 非法配置；原始 ID 保留；配置与返回 Worker 的修改隔离。客户端替身调用 RPC 即 panic，检查分配/释放不会调用后端。
- A/B 各一个名额，全部占满后拒绝；只归还 B，下一次可取得 B。旧 B 凭证再次释放不能归还新 B 凭证的名额。
- 异构上限 2/1/3 时跳过已满条目，按可用条目轮询；释放和失败申请不改变游标。
- 每轮 96 个并发申请用同一起跑信号启动，申请全部返回前不释放：恰好成功 6 个，A/B/C 分别 2/1/3，其余返回本地容量错误。并发归还后，同一池继续八轮验证复用；不是吞吐或公平性基准。
- 同一旧凭证被并发重复释放，并在一次释放返回后取得新凭证；旧释放不能增加新凭证持有期间的可用名额。

执行并通过：

```sh
go test -race -count=1 ./internal/workerpool
go vet ./internal/workerpool
```

测试使用本地替身和并发屏障，没有真实模型、网络容量测量或新的性能成果。现有普通轮询及加权轮询测试一并通过；未更改两者语义。

## 当前边界与下一步

现在已经具备“在本地原子选择并占位、全满立即失败、幂等归还”的独立组件。尚未把 Gateway 的 Pick 改成名额分配，现有服务行为不变；不能把组件测试写成真实会话完成率改善。

下一步成组接入 Gateway 的显式 WorkerAllocator 入口与旧选择器适配，覆盖 v1/v2。新建时取得 Lease，入口失败回收未交接资源，逻辑会话接管后持续持有；普通断开/原场恢复不重复申请，退出时等待本地任务完成再归还。助手随后补入口失败、恢复、停服及错峰分配测试，再运行已设计的真实两 Worker 对照。

本地名额归还不证明远端模型已释放。当前 Worker 的最终单名额保护继续有效；忙拒绝、处理前缀未知和原生合作取消等边界仍按原设计保留。
